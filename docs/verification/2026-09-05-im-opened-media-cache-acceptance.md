# IM 主动打开媒体缓存验收（2026-09-05）

## 范围

- 分支：`codex/im-opened-media-cache`
- 基线：`6cbdce0a3ff916fcd4ee0b1ccf70e75149225ce6`
- 仅处理 IM 图片/视频的主动打开、加密本地缓存、终止清理与媒体 HTTP 缓存策略。
- 未新增接口、数据表或 migration；未写共享 MySQL，未推送或部署。

## 根因与修正

- 原始异常不是媒体自然过期，而是相对存储目录在不同工作树运行时指向错误位置；基线修复已恢复原始媒体文件。
- 旧 `/media/im/*` 响应使用一年期 `public, immutable`，因此“图片标签仍可显示”不代表服务端文件仍存在，也不能作为正式本地保存机制。本切片将 IM 媒体改为 `private, no-store`，并为展示 URL 增加 `needo_media_policy=2` 以绕开既有旧缓存。
- 全屏首次打开以同源 `cache: no-store` 读取字节，使用临时 Blob URL 展示，同时以账号/会话/消息为 AAD 写入 AES-256-GCM IndexedDB 密文。再次打开优先解密本地副本。
- 撤回、本人删除、隐私过期与历史墓碑通过同一个 `state + media` IndexedDB 读写事务建立消息级终止标记并删除密文；写入侧也在同一事务内执行“无墓碑才写入”，所以同标签页及跨标签页的旧并发下载均无法在删除后重新写回。终止事务会自动重试三次；持续失败会进入后台重试队列直至成功，并保留可恢复错误状态、提示从“账户与安全”清除本机缓存。实时隐私删除不会在本机终止成功前刷新移除消息；历史撤回墓碑会先应用权威状态并释放分页，再独立清理本地密文。
- 仅 HTTP 410 或权威 `mediaState=expired` 显示“已过期”；404、鉴权、网络及其他交付错误不伪装为过期。气泡失败/过期状态仍可进入“查看本地副本”。
