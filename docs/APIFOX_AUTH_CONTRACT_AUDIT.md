# Apifox Auth Contract Audit

Source: `https://s.apifox.cn/308cd366-5ff1-49b7-9017-6ade6633605e`

Checked on: 2026-05-25

## Published APIs

The shared Apifox project currently exposes only two auth APIs:

- `GET reg`
- `GET login`

No `/auth/me`, `/auth/refresh`, `/auth/logout`, user profile, roles, or permissions APIs are present in the shared documentation.

## Login

- URI: `login`
- Method: `GET`
- Documented parameter mode: `application/x-www-form-urlencoded`
- Browser-compatible request used by NeeDo frontend: `POST` with `application/x-www-form-urlencoded`.
  - The Apifox example uses `GET` with a form body, but browser `fetch` cannot send a body with `GET`.
  - The deployed backend reads form body fields and returns field-level errors for `POST`.
- Password login fields used by NeeDo frontend:
  - `username`
  - `password`
  - `type=username`
- Other documented optional/login-mode fields:
  - `username`
  - `mobile`
  - `numcode`
  - `smscode`
  - `emailcode`
  - `type`
- Header area documents token-related fields:
  - `Authorization`: public pre-login bearer token for unauthenticated auth APIs
  - `token`: optional device fingerprint generated by FingerprintJS

Live probing without the pre-login bearer token returns:

```json
{"code":100011,"msg":"token不能为空"}
```

This means the API requires a public pre-login bearer token value outside the shared Apifox examples.

Live probing with the pre-login bearer token and password-login form fields currently reaches validation and returns:

```json
{"code":100103,"msg":"图形验证码不能为空"}
```

So the current login API also requires a graph-captcha value (`numcode`) for username/password login, but the shared Apifox project does not publish the captcha image/creation API.

## Register

- URI: `reg`
- Method: `GET`
- Documented parameter mode: `application/x-www-form-urlencoded`
- Browser-compatible request should use query string or a server-side proxy.
- Fields:
  - `username`
  - `mobile`
  - `email`
  - `password`
  - `numcode`
  - `smscode`
  - `emailcode`
  - `type`

## Required API Changes Or Missing Docs

To complete real NeeDo login without a mock session, the API documentation or backend must provide:

- The required public token/header value for `login` and `reg`, or remove token authentication from public auth endpoints.
- The graph-captcha API or a test-account bypass rule for username/password login.
- The exact success response shape for `login`.
- A current-user API equivalent to `/auth/me` that returns user, roles, permissions, and identities.
- Refresh/logout APIs, or an explicit statement that sessions are not refreshable/revocable from the frontend.
