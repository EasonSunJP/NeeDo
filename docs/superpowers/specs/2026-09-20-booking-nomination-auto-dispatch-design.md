# 预约指名费与店铺派单设计

## 业务口径

- 用户从店铺服务进入预约且未指定技师时，订单价格只包含服务价格，`technicianProfileId` 保持为空，订单进入店铺待分配池。
- 用户通过明确的技师入口预约店铺服务，或预约技师服务时，提交被指名的技师 ID。服务端必须校验该技师与所选时段一致，并按当前店铺财务规则计算指名费。
- 指名订单的最终价格、下单价格校验和订单快照统一为“服务成交价 + 指名费”。未配置指名费时按 0 日元处理。客户端不能提交或覆盖指名费金额。
- 订单快照保存 `wasTechnicianNominated` 和 `nominationChargeAmountJpy`，后续财务结算直接读取这份不可变快照。

## 店铺自动派单

自动派单入口显示当前 ON/OFF 状态，但整个控件是进入设置页的导航，不在首页直接切换。设置页使用正式店铺规则 API，保存：启用状态、日期与时段、到店/上门类型、服务区域、最低评分、最低接单率、最高取消率、单人每日上限、策略、移动时间、严格班次窗口，以及优先员工列表。

“指定员工池”统一改为“优先员工列表”，标题右侧提供编辑按钮；编辑态从当前店铺正式有效员工中增删。底部左侧按钮为“手动派单”，进入待分配预约列表。

新建未指名预约后，服务端在同一业务链路读取当前有效规则并尝试派单。候选人必须属于当前店铺、处于有效从属关系、符合筛选阈值、没有时间冲突且未超过每日上限。优先员工策略只提高列表内员工顺序，不绕过硬性条件。没有合格人选时订单继续保持待分配，不伪造分配结果。

## 手动派单与页面规则

新增商户订单派单命令，服务端校验店铺所有权、订单仍为待分配、技师当前有效从属关系和时间冲突，并在事务内写入技师、审计及通知。

- 已指名或已派单订单：预约卡片按原样显示，不出现派单按钮。
- `technicianProfileId === null` 的待分配订单：预约卡片容器底部显示整行大按钮“派单”。
- 预约详情底部操作栏继续使用现有 `MobileBottomActionBar` 悬浮在页面底部；待分配时包含“派单给员工”，已分配时不显示派单动作。
- “变更”保留人工修改入口，但保存必须调用正式订单更新 API；不得继续把人员分配或订单变更写入浏览器共享演示状态。

## 验证

覆盖无指名、指名费为 0、正数指名费、客户端价格篡改、跨店技师、时段技师不一致、手动并发派单、自动派单无候选、优先员工、每日上限和时间冲突。前端覆盖入口只导航、优先员工编辑、已分配/待分配卡片按钮差异及悬浮底栏。
