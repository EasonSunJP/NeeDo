# IM 快捷判断、表情回复双槽位与统一目录设计

## 1. 目标

将消息快捷回复改为两个彼此独立的槽位：

- 判断回复槽位：`OK`、`NO`、`Pending`、`+1`、`Done`、`Cool`、`Good`、`Thanks` 八选一。
- 表情回复槽位：现有快捷表情和展开后的默认表情中任选一个。

同一个用户对同一条消息最多同时保留一个判断回复和一个表情回复。两类可以同时存在，其他用户的选择不会影响当前用户的可选状态。

## 2. 交互规则

### 2.1 判断回复

- 判断项固定提供 `OK`、`NO`、`Pending`、`+1`、`Done`、`Cool`、`Good`、`Thanks`。
- 当前用户尚未发送判断回复时，八个选项均可用。
- 当前用户发送其中一个后，已选项保持正常高亮，不变黑、不置灰，并可再次点击取消。
- 同组另外七个选项立即置灰并禁用；禁用项不能触发前端状态变化，也不能发送 API 请求。
- 已选项取消成功后，八个选项恢复可用。

### 2.2 表情回复

- 八个判断值从一般表情目录中移出，避免同一个值同时属于两类。
- 当前用户尚未发送表情回复时，所有表情均可用。
- 当前用户发送一个表情后，已选表情保持正常高亮并可再次点击取消。
- 其他表情立即置灰并禁用，不能触发前端状态变化或 API 请求。
- 已选表情取消成功后，全部表情恢复可用。

### 2.3 消息下方的回复摘要

- 判断回复和表情回复继续使用现有 reaction 摘要样式及人员名单。
- 当前用户同时选择一个判断和一个表情时，消息下方同时显示两个摘要。
- 摘要顺序固定为判断回复在前、表情回复在后；同类内部保持服务端稳定顺序。
- 当前用户已选摘要可点击取消。取消请求进行中时禁止重复点击；失败时保留原摘要并显示明确错误提示。

### 2.4 折叠快捷行与展开目录

- 消息操作菜单折叠时，判断图标和普通表情仍在同一行显示，不拆成两行。
- 折叠行的数据来自最近使用记录，最近使用的判断或表情排在最前；“更多”按钮固定保留在行尾。
- 折叠行根据可用宽度显示最近记录的前若干项，不横向滚动，也不为了显示全部记录而压缩到不可辨识。
- 展开后固定按“常用表情”→“判断表情”→“一般表情”的顺序显示；“常用表情”的数据含义就是最近使用记录。
- 输入框右侧表情按钮打开的面板采用同一组目录、同一分区顺序和同一最近使用记录。
- 消息操作菜单点击目录项时发送或取消 reaction；输入框面板点击普通表情时插入 Emoji，点击判断图标时插入其文字值。
- 最近使用记录最多保留 8 项，判断与普通表情共享排序；成功发送 reaction 或成功插入输入框后才更新记录。
- 升级后沿用现有最近 Emoji 记录；没有历史记录时继续使用当前默认常用 Emoji 作为初始内容。

## 3. 状态与数据分类

不新增 reaction 类型字段，继续使用现有 `MessageReaction.emoji` 字段：

- `OK`、`NO`、`Pending`、`+1`、`Done`、`Cool`、`Good`、`Thanks` 归类为 `judgement`。
- 其他值归类为 `emoji`。

前后端共享同一组判断值和分类规则，避免 UI 与持久化规则分叉。用户可见的区域标题和错误提示进入现有 i18n；八个判断值保持产品指定的英文写法及大小写。

## 4. 前端设计

- 新增一个共享 reaction/emoji 目录模型，为消息操作菜单和输入框表情面板提供常用表情、判断表情、一般表情三个分区；两个入口不再各自维护一套目录常量。
- 折叠消息操作菜单只渲染最近使用快捷行，展开后再渲染完整三个分区。
- 根据当前用户在该消息上的 reaction 摘要分别计算 `selectedJudgement` 与 `selectedEmoji`。
- 某槽位已有选中值时：选中按钮保持 active；同槽位其他按钮使用灰色 disabled 样式并设置原生 `disabled`。
- 最近使用区同样遵循槽位禁用规则：已有判断时，最近使用中的其他判断禁用；表情槽位不受影响，反之亦然。
- disabled 按钮的点击处理在组件边界直接终止，不能进入 store，也不能产生网络请求。
- reaction 变更以服务端权威响应为准。请求期间仅锁定对应槽位，不先插入会闪退的临时摘要；成功后写入 store，失败时保留原状态并显示错误。
- 判断槽位和表情槽位分别使用 pending key，因此两类请求可以独立进行；同一槽位不能并发提交。
- REST 与 SSE 继续通过 `reactionVersion` 合并，旧版本不得覆盖新版本。

### 4.1 判断 SVG 图标

- 八个判断值分别使用独立、透明背景的本地 SVG 资源，不复用用户提供的低分辨率截图作为运行时图片。
- 视觉参考为彩色、粗体、略倾斜、带轻微描边或立体阴影的文字徽标；不使用黑色矩形底板。
- 主色固定为：`OK` 绿色、`NO` 红色、`Pending` 琥珀色、`+1` 蓝色、`Done` 绿色、`Cool` 青蓝色、`Good` 紫色、`Thanks` 橙色；描边与阴影只使用对应主色的深浅变化。
- 图标视觉高度控制在约 22–26px，宽度按文字自适应并受按钮格宽限制；`Pending`、`Thanks` 等长词不能撑高快捷行。
- 每个按钮保留可访问名称；选中态由浅色主色描边/底色表达，不把图标变黑。禁用态使用降低饱和度和透明度的灰色效果。
- 同一 SVG 组件同时用于消息 reaction 目录、输入框表情目录和消息下方的判断摘要，避免三个位置出现不一致的文字造型。

## 5. 后端约束

- reaction 写事务继续先锁定权威消息行并校验会话成员资格。
- 在写入前按 `messageId + userId + category` 查询当前有效 reaction。
- 同槽位没有有效值时允许写入。
- 同槽位已有相同值时，PUT 作为幂等成功处理。
- 同槽位已有不同值时拒绝写入，返回可识别的 409 业务错误；客户端必须先取消原值，不能直接替换。
- DELETE 只能取消请求中指定的已选值；成功后递增 `reactionVersion` 并返回完整权威聚合。
- 消息行锁保证多标签页或并发请求下同一槽位只能有一个最终有效值，先成功的请求占用槽位。
- 判断槽位与表情槽位相互独立，因此一个判断和一个表情可以并存。

## 6. 历史数据整理

新增可回滚的数据 migration，以八个判断值重新分类，对每个 `messageId + userId + category` 的现有有效 reaction：

- 只保留 `updatedAt` 最新的一条；时间相同时保留 `id` 最大的一条。
- 其余记录设置 `deletedAt`，不做硬删除。
- 已经符合双槽位规则的数据不变。
- 旧数据中的 `+1`、`Done`、`Cool`、`Good`、`Thanks` 从原先的一般表情语义切换为判断语义；若与其他判断并存，同样按最新 `updatedAt`、再按最大 `id` 保留。
- migration 后增加检查脚本或测试，证明不存在同一用户、同一消息、同一槽位的多条有效记录。

## 7. 错误处理

- 409 槽位占用：前端重新采用响应或刷新后的权威消息，并提示“请先取消已发送的同类回复”。
- 429 限流：不静默回滚，提示“操作过于频繁，请稍后重试”。
- 网络或 5xx：保持原有已发送状态，提示操作失败，不制造短暂出现后消失的摘要。
- SSE 或 REST 乱序：按 `reactionVersion` 忽略旧消息快照。

## 8. 测试与验收

### 8.1 后端

- 一个用户可以同时保存一个判断回复和一个表情回复。
- 同槽位第二个不同值返回 409，数据库仍只有原值。
- 再次 PUT 相同值幂等成功。
- 取消已选值后可选择同槽位的新值。
- 两个并发请求竞争同一槽位时只有一个成功占用。
- 历史数据 migration 只软删除同槽位重复项，并按 `updatedAt`、`id` 规则保留最新项。

### 8.2 前端

- 八个判断项都使用独立 SVG，并保持紧凑高度。
- 折叠快捷行只显示最近使用项和“更多”，判断与普通表情可以混排。
- 展开后按常用表情、判断表情、一般表情排序；输入框表情面板结构一致。
- 选择 `OK` 后，其他七个判断在完整判断区和最近使用区均为原生 disabled，点击不调用 store/API。
- 选择一个表情后，其他表情为原生 disabled，点击不调用 store/API。
- 判断和表情可以各选一个并同时显示。
- 已选项再次点击会取消；取消成功后同槽位其他项恢复可用。
- 输入框点击判断 SVG 插入对应文字，点击普通表情插入 Emoji；两者都会更新共享最近使用顺序。
- 旧的最近 Emoji 记录会迁移到共享最近使用记录，且最多保存 8 项。
- 409、429 和网络错误均显示明确提示，且不会出现错误的临时摘要。
- 较旧的 `reactionVersion` 不能覆盖较新的双槽位状态。

### 8.3 浏览器验收

在 5180 正式本地链路使用两个真实测试账号验证：

1. 使用消息操作菜单发送 `OK`，确认其余七个判断变灰且无法点击。
2. 同时发送一个表情，确认其他表情变灰且判断回复仍保留。
3. 检查折叠行显示刚使用的 `OK` 与该表情，展开顺序为常用表情、判断表情、一般表情。
4. 刷新页面，确认一个判断和一个表情都持久化。
5. 点击已选判断取消，确认八个判断恢复可选，表情不受影响。
6. 点击已选表情取消，确认所有表情恢复可选。
7. 从输入框右侧打开表情面板，确认分区结构一致；点击 `Thanks` 插入文字，点击普通表情插入 Emoji，并确认最近使用顺序同步更新。
8. 在第二个账号观察 SSE 状态与第一个账号一致。
9. 检查八个 SVG 清晰、尺寸紧凑、无黑底；控制台无产品错误，移动端菜单无横向溢出。

## 9. 非目标

- 不增加第三个 reaction 槽位。
- 不允许在禁用状态下直接替换同类回复。
- 不扩张新的 mock、demo 或前端本地专用 reaction 数据源。
- 不在本步骤推送、部署或修改生产环境数据。
