# NeeDo 媒体存储稳定性与失败状态设计

**Date:** 2026-09-05  
**Status:** Approved direction; implementation pending design review  
**Scope:** Step 13 IM/Social 媒体交付的一个可回滚微步骤。只处理跨 worktree 的稳定磁盘路径、现有文件恢复和前端失败状态；不在本步骤合并完整 IM 生命周期分支。

## 1. 目标

修复正式本地运行时中图片、视频和语音记录存在于数据库、对应文件仍在磁盘，但浏览器得到 404 并显示原始文件名或 `0:00 / 0:00` 的问题。

完成后必须满足：

- 同一正式数据库对应同一持久化媒体目录，不因从不同 Git worktree 启动而切换到空目录；
- 现有未过期媒体重新可读，不重传、不改写消息、不伪造数据；
- 只有服务端明确声明过期时才显示“图片已过期”或“视频已过期”；
- 网络错误、文件缺失和服务异常显示“媒体加载失败”，不得误报为过期，也不得泄露原始文件名作为错误界面；
- 语音读取失败时显示失败状态，并保留服务端提供的可信时长，不将加载失败误显示为零时长；
- 不删除、不移动现有媒体文件，不修改数据库，不新增 mock。

## 2. 已确认的根因

正式数据库中的 IM 图片、IM 语音和 Social 图片记录均未标记过期或清理。记录引用的哈希媒体文件存在于主检出目录的 `backend/runtime` 下。

当前运行中的正式后端来自另一个 worktree。`IM_MEDIA_STORAGE_DIR=runtime/im-media` 与 `CONTENT_MEDIA_STORAGE_DIR=runtime/content-media` 是相对路径，Express 会相对于该后端进程的工作目录读取，因此实际查找的是运行 worktree 自己的空目录。数据库与磁盘根目录由此失配，媒体 URL 返回 404。

当前 IM 和 Social 前端都直接渲染原生媒体元素，没有业务错误状态。图片加载失败后，浏览器回退显示 `alt`；IM 的 `alt` 恰好是上传文件名，所以页面显示了 `_699137a1-...jpeg`。语音元素无法读取文件元数据，因此显示 `0:00 / 0:00`。

这不是媒体过期。HTTP 404 不能单独证明过期，因为它也可能表示目录配置错误、文件意外缺失、代理错误或服务不可用。

## 3. 设计边界

### 本步骤包含

1. 正式开发启动器解析一个跨 worktree 稳定的绝对媒体目录。
2. IM 与 Social 的图片、视频、语音加载失败状态。
3. 对服务端显式 `mediaState=expired` 的过期占位映射，为后续生命周期分支保持兼容。
4. 配置、组件和真实运行时验收。

### 本步骤不包含

- 不合并 `codex/im-message-lifecycle` 的 58 个提交；该分支与当前 `main` 差异过大，必须另行重放和验收。
- 不在浏览器收到消息或列表渲染时自动永久下载媒体。
- 不实现或扩展加密 IndexedDB 本地缓存。用户主动打开媒体后缓存、过期后本机回退、撤回和隐私删除强制清缓存，继续遵循已批准的 `2026-08-26-im-message-lifecycle-retention-recall-design.md`，作为下一微步骤移植。
- 不更改媒体保留期限、数据库生命周期字段、清理任务或对象存储架构。
- 不处理头像、身份申请材料等不在本次故障证据中的存储域。

## 4. 稳定存储路径

### 4.1 正式开发启动器

`scripts/dev-formal.mjs` 在启动三个正式 API 服务前解析媒体目录：

1. 若调用环境显式提供绝对 `IM_MEDIA_STORAGE_DIR` 或 `CONTENT_MEDIA_STORAGE_DIR`，分别使用显式值；
2. 否则通过 Git common directory 找到所有 linked worktree 共享的主检出根目录；
3. 默认解析为 `<主检出根>/backend/runtime/im-media` 和 `<主检出根>/backend/runtime/content-media`；
4. 若当前目录不是 Git worktree，则回退为启动项目自身的绝对 `backend/runtime`，同时输出可观察的目录日志；生产部署仍必须显式注入持久卷的绝对路径。

启动器把解析后的绝对目录传给 client-api、ops-api 和 merchant-api。三个服务共享同一正式数据库时必须共享同一媒体根目录，不能各自在 worktree 内创建权威副本。

路径解析抽成无副作用函数，Git common directory 和当前目录作为参数输入，以便单元测试覆盖普通检出、linked worktree、显式覆盖和非 Git 回退。

### 4.2 配置约束

- 显式媒体目录必须是绝对路径；相对覆盖值启动即失败，避免再次悄悄绑定到进程 `cwd`。
- 生产环境的 IM 和 Content 媒体目录必须是显式绝对持久卷路径。
- 日志只记录解析后的目录和来源，不记录用户文件名、消息内容或访问令牌。
- 本地现有文件已经位于选定的共享目录，所以本次无需复制或迁移；不得删除各 worktree 中的任何文件。

## 5. 前端媒体状态

所有媒体组件使用显式状态机，而不是依赖原生元素的破损 UI：

```text
loading -> ready
loading -> failed -> retrying -> ready|failed
server mediaState=expired -> expired
```

状态优先级：

1. 服务端显式 `expired`：显示按类型区分的过期占位；
2. 当前 URL 成功加载：显示媒体；
3. `error` 事件：显示加载失败和重试入口；
4. 组件不得根据消息年龄、HTTP 404 或文件名自行推断过期。

IM 文案：

- 图片：`图片已过期` / `图片加载失败，点击重试`
- 视频：`视频已过期` / `视频加载失败，点击重试`
- 语音：`语音加载失败，点击重试`

Social 在当前正式契约中没有媒体过期语义，因此只显示图片/视频加载失败。所有新增用户可见文案进入现有 i18n，不硬编码单一语言。

重试只重新请求当前正式 URL，可附加内部重试键以触发元素重建；不得把失败 URL 替换为假图，也不得把原始文件名展示为用户错误文案。

## 6. 本地缓存关系

“用户主动打开过的媒体保存到本机”是已批准产品规则，但当前 `main` 尚未包含对应实现。稳定共享存储先恢复服务端媒体交付，避免把后端路径错误掩盖成本地缓存问题。

下一微步骤将从生命周期分支移植最小缓存闭环：

- 仅在用户主动打开且鉴权下载成功后写入加密 IndexedDB；
- 正常列表渲染不自动永久缓存；
- 服务端媒体过期时优先读取本机已打开副本；无副本才显示过期；
- 标准撤回、无痕撤回和隐私到期必须删除 IndexedDB、浏览器缓存和活动 object URL；
- 缓存按用户、身份和设备作用域隔离，并提供容量查看与清除入口。

该缓存步骤必须在当前 `main` 上重新评估数据契约和迁移，不直接合并高度分叉的旧分支。

## 7. 测试与验收

### 自动化

- 先写失败测试，证明 linked worktree 在旧逻辑下解析到不同目录；
- 验证普通检出和 linked worktree 得到相同 IM/Content 绝对目录；
- 验证显式绝对覆盖生效、相对覆盖被拒绝、非 Git 回退可观察；
- 后端静态媒体测试验证存在文件返回 200、未知哈希返回标准 404；
- IM 组件测试覆盖 ready、failed、retry、explicit expired 和语音可信时长；
- Social 组件测试覆盖失败占位、重试以及不显示原始文件名；
- 运行相关 lint、定向测试和生产构建。

### 真实运行时

1. 证明监听进程的 PID、cwd、分支、端口和前端代理目标；
2. 从正式数据库读取本次三个媒体记录的 URL 与生命周期字段；
3. 验证 IM 图片、IM 语音和两张 Social 图片的 URL 均返回 200，并校验 MIME 类型；
4. 在浏览器重新打开原会话和原 Social 动态，确认图片可见、语音显示服务端时长且可播放；
5. 用明确的过期契约 fixture 验证“图片已过期”，用不存在的哈希验证“图片加载失败”，确保两者没有混淆；
6. 检查浏览器控制台没有新的资源错误、React 警告或横向溢出。

## 8. 回滚

- 代码回滚只需撤销启动器路径解析和媒体错误状态组件；
- 本步骤没有数据库 migration、文件移动或文件删除；
- 原媒体目录内容保持不变，因此回滚不会造成数据丢失；
- 若共享目录配置异常，启动器必须在服务启动前失败，不得静默创建另一套权威目录。
