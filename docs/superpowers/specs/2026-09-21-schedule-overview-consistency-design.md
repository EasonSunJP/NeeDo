# 排班概览一致性修复设计

## 目标

修复商户排班页面的步骤条外框、下一周期标题与步骤样式、正式排班缓存加载体验，以及现状确认日/周/月统计无效的问题；同时让商户端与后台使用同一种“空闲/已预约时长柱形 + 出勤人数折线”图表。

## 设计

- 把现有自动化向导步骤条提取为共享组件。首段保留平直左边，末段改为平直右边，外层继续负责圆角裁剪，中间分隔仍使用箭头。
- 下一周期卡片只显示 `开始日期 - 结束日期`，不再重复“下一周期”；直接复用共享步骤条，移除卡片内第二套圆点步骤实现。
- 正式排班缓存使用与预加载器一致的 `store-<内部店铺ID>` 资源键。缓存命中时立即渲染并后台刷新；冷启动仅显示非阻塞旋转指示器，页面导航和日/周/月切换保持可操作。
- 基于正式排班时段按当前视图生成统计桶：日视图按小时、周视图按天、月视图按日期。每桶统计空闲时长、已预约时长和不同技师数量。阻塞时段不计入空闲或已预约。
- 新增共享组合图表：两个柱形序列分别表示已预约时长、空闲时长，折线使用独立纵轴显示出勤人数。商户端现状确认和后台仪表盘都复用该组件。
- 后台 dashboard bucket 增加 `scheduleAttendanceCount`，由正式 `schedule_slots` 在每个统计桶内按 `technician_profile_id` 去重计算。该字段只扩充只读 API，不改变数据库结构。

## 验收标准

- 三步或四步步骤条整体左右均为圆角矩形；内部步骤边界仍为箭头。
- 下一周期标题只出现一次日期范围，样式与新建排班步骤条一致。
- 缓存命中后首屏直接显示旧数据并后台刷新；loading 指示器持续旋转且不拦截点击。
- 日/周/月切换会改变统计桶、摘要值和图表内容。
- 商户端与后台都显示双色柱形和出勤人数折线。
- 聚焦测试、前后端类型/构建、非 5180 浏览器验收通过；合并本地 main 后重新在 5180 验证。

## 边界

- 不修改 Booking、Schedule 的事务、权限或状态机。
- 不新增数据库 migration，不写远程或 staging 数据。
- 不操作开发阶段的 5180。
