# NeeDo 后台登录页门户文案、语言切换与浏览器保存密码设计

日期：2026-08-27

## 目标

在现有 PC 后台共享登录页中明确区分运营后台与商户/店铺后台，同时补齐五语切换入口和安全的“保存密码”开关。保持现有 React、TSX、Vite、正式 Auth 与 RBAC 接线，不重做登录页，不新增 mock、后端接口、数据表或 migration。

## 已确认文案

主标题继续使用各语言现有的“欢迎回来”自然翻译。副标题按登录门户显示，不增加“账号登录”字样。

| 语言 | 运营后台 | 商户/店铺后台 |
| --- | --- | --- |
| 简体中文 | 请使用运营后台 | 请使用商户/店铺后台 |
| 繁体中文 | 請使用營運後台 | 請使用商戶／店鋪後台 |
| 日本語 | 運営管理画面をご利用ください | 店舗管理画面をご利用ください |
| English | Please use Operations Admin | Please use Merchant / Store Admin |
| 한국어 | 운영 관리자 화면을 이용해 주세요 | 가맹점/매장 관리자 화면을 이용해 주세요 |

联盟营销后台不属于本次文案区分范围，继续使用当前对应语言的通用后台登录副标题，避免扩大修改范围。

## 页面结构

### 标题区

- 将标题行改为左右布局。
- 左侧显示“欢迎回来”的当前语言版本。
- 右侧复用现有 `LanguageSwitcher` 的 `iconOnly` 模式。
- 语言菜单继续提供简体中文、繁体中文、日本語、English、한국어，并沿用 `I18nProvider` 现有的语言持久化与系统语言规则。
- 图标按钮按当前后台主题的明暗模式显示，不能只适配截图中的蓝黑主题。
- 副标题放在标题行下方，根据 `AdminLoginPortal` 读取相应文案。

### 保存密码区

- 在“密码”标签同一行的右侧显示当前语言的“保存密码”文字和开关。
- 五语标签为：`保存密码`、`儲存密碼`、`パスワードを保存`、`Save password`、`비밀번호 저장`。
- 开关默认关闭，并按 `admin`、`merchant-admin`、`afirieito-admin` 分门户保存布尔偏好。
- 本地只允许保存开关偏好，不保存账号密码、可逆密文、令牌或其他凭据。

## 保存密码安全边界

采用浏览器密码管理器方案：

1. 开关开启时，账号与密码输入框使用浏览器密码管理所需的 `username` 和 `current-password` autocomplete 语义。
2. 正式密码登录成功后，如浏览器支持 Credential Management API，则向浏览器提交 `PasswordCredential` 保存或更新请求。
3. 浏览器不支持该 API 时，保留标准表单 autocomplete 作为原生密码管理器的回退入口。
4. 开关关闭时不主动调用凭据保存 API，并关闭本页主动提供的密码 autocomplete 语义；浏览器或扩展自身的全局策略仍拥有最终决定权。
5. 凭据保存失败不得阻塞已经成功的 NeeDo 登录或门户跳转，也不得把账号密码写入错误日志。
6. 继续清除历史 `needo.auth.remember-credentials.*` 明文记录，不恢复已经退役的 `readRememberedCredentials` 或 `writeRememberedCredentials`。

## 代码边界

预计只修改或新增以下前端范围：

- `src/pages/auth/AdminLoginPage.tsx`
- `src/pages/auth/AdminLoginPage.test.tsx`
- 一个仅处理浏览器密码管理器与安全布尔偏好的小型 auth helper 及其测试
- 必要的 `src/styles.css` 登录页局部样式

不修改正式 Auth API、Token 存储、RBAC、Prisma schema、后端服务或登录成功后的门户范围校验。

## 状态与数据流

1. 路由继续把 `portal="admin"` 或 `portal="merchant-admin"` 传给共享登录页。
2. 当前语言与门户共同决定标题、副标题和“保存密码”标签。
3. 页面初始化时读取当前门户的保存密码布尔偏好，默认 `false`。
4. 用户切换开关时只写入该布尔偏好。
5. 用户提交账号密码后继续调用现有 `loginWithFormalPassword`。
6. 登录失败时不触发任何凭据保存动作。
7. 登录成功且开关开启时请求浏览器保存凭据；无论浏览器接受、拒绝或不支持，随后都按现有门户校验结果跳转。

## 错误处理与无障碍

- 语言按钮保留 `aria-label`、菜单角色、点击外部关闭与 Escape 关闭能力。
- 保存密码开关使用 `role="switch"`、`aria-checked` 和当前语言的可访问名称。
- 浏览器凭据 API 的拒绝、取消和不支持均静默降级，不显示误导性的“密码已保存”成功提示。
- 门户不匹配、登录失败、验证码和扫码登录继续使用现有错误路径；保存密码只作用于账号密码登录。

## 测试与验收

实施时严格执行红—绿—重构：

1. 先增加会失败的测试，覆盖五种语言下运营/商户副标题的准确区分。
2. 覆盖“欢迎回来”右侧存在语言按钮，并能调用现有五语切换能力。
3. 覆盖保存密码开关默认关闭、可切换、按门户持久化且存储中不含密码。
4. 覆盖仅在正式密码登录成功且开关开启时请求浏览器保存凭据。
5. 覆盖浏览器拒绝或不支持凭据保存时，成功登录仍正常跳转。
6. 保留并更新历史明文凭据清理测试，确认没有恢复本地密码读写函数。
7. 运行相关 Vitest、完整前端测试、TypeScript lint、正式模式 build 和 `git diff --check`。

## 完成标准

- 运营后台和商户/店铺后台在五种语言中显示各自副标题。
- 标题右侧语言按钮在后台明暗主题与窄屏下可用。
- 密码标签右侧显示五语“保存密码”开关。
- 开关开启后只使用浏览器密码管理器，不在应用存储中保存密码。
- 账号、验证码、扫码登录、门户校验、Token 与 RBAC 行为没有回归。
