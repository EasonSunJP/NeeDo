# Social Background Image Publish Design

## Goal

新动态选图后立即开始正式媒体上传，但上传状态不阻塞“发表”按钮，也不向用户展示上传中的遮罩。用户可随时发表并立即返回动态列表；已启动的上传在后台完成后，再携带正式媒体资产引用创建动态。

## Behavior

- 新动态只要包含正文或已选图片，就允许点击“发表”；图片是否已上传完成不参与按钮可用性判断。
- 选图后仍立即调用现有正式 `POST /api/v1/social/media` 上传接口，不新增 mock、临时媒体 API 或缺图动态。
- 点击“发表”时冻结本次正文、可见范围、提醒对象和图片顺序，立即返回当前身份的动态列表，并在后台等待该批图片上传。
- 全部图片上传成功后，调用现有正式动态创建 API；成功后清除草稿。
- 任一图片上传或动态创建失败时，不调用或不产生缺图动态，保留未清除的草稿，并通过全局错误反馈提示用户重新进入发布页处理。
- 新动态创建态不显示“上传中”遮罩；上传失败后的重试入口保留。
- 已发布动态的编辑保存维持现有同步保护：新增图片必须上传完成后才可保存，避免后台失败造成编辑内容无法恢复。

## Implementation Boundaries

- 在 Social composer 媒体辅助模块中区分“存在可发布内容”和“媒体已取得正式资产引用”。
- 组件为每个本地图片维护一个可复用的上传 Promise，后台发布复用已经开始的上传，不重复上传。
- 发布任务只捕获本次提交快照，不依赖组件卸载后的 React state。
- 不修改后端 schema、API、权限、审计或动态数据模型。

## Error Handling and Tests

- 单元测试覆盖：本地待上传图片也可发表、空内容仍不可发表、正式媒体完成判断、后台解析保持图片顺序、失败时拒绝创建缺图动态。
- 页面接线测试覆盖：创建态立即导航、复用上传任务、后台完成后创建动态、错误走全局反馈、编辑态仍等待上传。
- 完成后运行 Social composer 专项测试、前端 lint/typecheck、完整前端测试与 production build。
