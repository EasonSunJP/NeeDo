# NeeDo 实时运营大屏响应式与地区地图交互设计

日期：2026-09-07  
状态：用户已确认设计方向，待书面规格复核  
适用页面：`/pf-admin.html#/admin/live-screen`

## 1. 目标

在不改变实时数据口径、缓存、SSE、权限或地区归因规则的前提下，完成以下前端微步骤：

1. 桌面网页根据实际视口宽度和高度连续自适应，全部核心面板在一个视口内展示，不依赖固定设计尺寸、整页缩放或页面滚动。
2. 地图上方始终提供国家、都道府县、市区町村三级地区选择，以及覆盖日本全国行政区域的搜索。
3. 手机竖屏隐藏地图图形，但保留地区选择、搜索、当前范围和全部数据面板；手机页面允许纵向滚动。
4. 地图标签发生碰撞或区域过小时，将名称移到地图周围，以引导线连接行政区域锚点。
5. 地图提供放大、缩小、还原按钮；放大后可以拖动查看，切换地图层级时恢复到适合新层级的完整视图。
6. 订单与支付趋势图在任何桌面适配状态下都保留可读绘图区，日期轴不能被压扁到数据线或卡片边缘。

本步骤不新增后端接口、数据库表、migration、mock 数据或额外实时轮询。

## 2. 设计原则

### 2.1 真正的流式自适应

- 页面根容器使用 `height: 100dvh`，按“顶部状态栏 + 剩余数据区”分配空间。
- 桌面数据区使用可收缩的三列网格；列宽、字号、间距和内边距使用比例单位与 `clamp()` 连续变化。
- 删除基于固定最小宽度的整页 `transform: scale(...)` 和宽度补偿逻辑，避免文字变小、点击区域缩小和渲染模糊。
- 所有网格子项使用 `min-width: 0`、`min-height: 0`，地图、图表和列表只占父容器分配的空间。
- 页面本身在桌面横屏不产生横向或纵向滚动。实时列表和排行榜只在自己的面板中自动切换或滚动，不撑高页面。
- 对低高度桌面视口启用紧凑密度：缩小头部、卡片间距、标题间距、列表行高和图表高度，但不隐藏核心指标。
- 不以 1366、1440、1920 或 2560 等尺寸作为固定画布；这些尺寸只作为验收样本。

### 2.2 保持现有运营后台视觉语言

- 继续使用现有 `--admin-*` 主题变量、圆角、边框、阴影和字体体系。
- 不增加霓虹、扫描线、星空、机械边框或新的背景插画。
- 地图仍是中央主视觉；新的搜索、下拉、引导线和缩放按钮使用后台表单与工具按钮风格。
- 动画遵守 `prefers-reduced-motion`，标签排布和地图变换在减少动态模式下直接到达最终状态。

## 3. 响应式结构

### 3.1 桌面横屏

页面结构：

```text
┌──────────────────── 顶部状态与控制 ────────────────────┐
├──────── 左栏 ────────┬──────── 中央地图区 ────────┬──── 右栏 ────┤
│ 实时概览             │ 已确认服务支付             │ 实时订单     │
│ 订单经营             │ 地区搜索与三级选择         │ 订单动态     │
│ 区域归因完整度       │ 自适应地图                 │ 服务排行     │
│                      │ 订单与支付趋势             │ 技师排行     │
└──────────────────────┴────────────────────────────┴──────────────┘
```

- 三列使用流式比例，不设置阻止收缩的固定最小画布宽度。
- 中央列保持最大视觉权重；左右列在窄桌面下先压缩间距、字号和列表可见行数。
- 地图高度由中央列剩余空间决定，SVG 使用父容器实际尺寸，不再使用 500px/520px 固定最小高度。
- 趋势图设定可读绘图区下限和固定的内部坐标留白。低高度模式只压缩卡片外边距、标题间距和图例间距，不把日期轴、网格线或数据线压到同一条水平带。
- 趋势图使用保持比例的 SVG 视口或由容器尺寸计算的绘图区，禁止以 `preserveAspectRatio="none"` 进行不可控的纵向拉伸/压缩。
- 日期标签位于绘图区底线之外的独立轴带内；数据线最低点与日期轴之间保持明确间距。
- 头部控件允许在较窄桌面下换行或压缩，不整体隐藏国家、周期和当前范围。

### 3.2 手机竖屏

- 使用单列文档流并允许页面纵向滚动。
- 隐藏 SVG 地图、地图标签、引导线、缩放按钮和地图空白占位，不保留大块空卡片。
- 地区搜索、国家/都道府县/市区町村下拉、当前范围面包屑继续显示在数据面板之前。
- 数据面板按实时概览、订单经营、已确认服务支付、实时订单、订单动态、趋势、服务排行、技师排行、归因完整度排列。
- 触控目标不小于现有后台移动端控件规范，输入框不会造成页面横向溢出。

## 4. 地区选择和全国搜索

### 4.1 控件结构

新增独立的地区探索控件，地图正常或加载失败时都可使用：

1. 国家下拉：当前只有日本，数据结构保留未来国家扩展能力。
2. 都道府县下拉：47 个正式 N03 都道府县。
3. 市区町村下拉：在选中都道府县后展示其正式 N03 子区域；东京包含 23 个特别区及同层其他行政区域。
4. 全国搜索：从日本全国层级直接搜索都道府县、市区町村和特别区。

选择任一结果后，统一调用现有 `onSelectRegion`，更新 `country`、`admin1`、`admin2` 与保留的 `period` URL 参数。`useLiveDashboard` 继续只从 URL 消费唯一范围，避免地图、下拉和数据面板出现不同范围。

### 4.2 本地行政区索引

- 搜索索引从已经提交并校验的 N03 地图资源生成，包含行政代码、日文名称、所属都道府县和完整面包屑。
- 索引作为版本化静态资源随前端发布，加载不访问业务 API、数据库或 Redis。
- 输入在浏览器本地完成规范化和匹配；支持名称和行政代码，不上传搜索词。
- 结果数量受限并按“精确匹配、前缀匹配、包含匹配、行政层级、行政代码”稳定排序。
- 同名结果显示完整路径，例如 `日本 / 東京都 / 新宿区`，避免误选。
- 索引加载失败时，三级下拉仍可按当前层级工作，并显示清晰的搜索不可用状态。

### 4.3 可访问性

- 搜索采用输入框与受控结果列表，支持上下方向键、Enter 选择、Escape 关闭和清晰焦点样式。
- 下拉和搜索均有多语言标签；当前选择、结果数量和空结果通过可访问文本表达。
- 手机隐藏地图不会隐藏地区导航能力。

## 5. 地图标签避让与引导线

### 5.1 排布规则

每个标签以地图资源中的 `labelPoint` 作为地理锚点：

1. 标签可在区域内部完整显示且不与已放置标签碰撞时，保留内部标签。
2. 区域过小或发生碰撞时，将标签放入地图可视范围四周的候选槽位；最外圈满载时，允许沿边缘向内增加第二排及后续有界槽位。
3. 从行政区域锚点绘制折线或直线到外部标签，线端与文字保持间距。
4. 候选槽位按确定性顺序分配，输入和视口不变时结果不跳动。
5. 当前选中和键盘焦点区域优先，其次按是否有业务数据、区域面积和行政代码稳定排序。
6. 标签仍然只负责展示；地图路径继续承担点击和键盘选择，避免生成重复交互目标。

### 5.2 视觉和边界

- 引导线使用主题中等对比度，不能盖过区域边界。
- 标签使用现有地图文字描边，保证浅色、深色主题可读。
- 引导线和标签限制在地图可视容器内；极端密集时允许分列排列，不允许相互覆盖。
- 向内扩展的槽位仍须贴近同一侧边缘，不能退回原始锚点拥挤中心；这些标签继续按外部标注处理并保留引导线。
- 标签以实际地图绘图区的屏幕像素排布，不能因为 SVG 等比缩放而缩成不可读的小字。日本 47、东京 62 和冲绳 41 个区域在验收视口中须完整显示；北海道 195 等物理容量超限时采用确定性渐进披露，始终优先显示当前选中、键盘焦点和有业务数据的区域，并在放大后于当前可视范围揭示此前因容量隐藏的名称。缩放后可视地理范围变小时，总显示数无需单调增加。未显示名称的路径仍可聚焦、悬停、点击，并可通过搜索或下拉直接到达；界面以可访问文本说明当前显示数量。
- 东京岛屿、冲绳及其他离岛插图按各自可见范围参与排布，不能把名称堆在主岛中央。
- 地图缩放时根据变换后的锚点重新计算屏幕排布，而不是把外部文字一起无限放大。

## 6. 地图缩放、拖动与还原

- 地图工具区提供三个有文字替代的按钮：放大、缩小、还原。
- 缩放范围有限，采用稳定步进；达到上下限时相应按钮禁用。
- 放大以当前选中区域为优先中心，否则以地图可视中心为中心。
- 缩放大于 1 时支持鼠标和触控拖动；位移受地图边界限制，不能把地图完全拖出视口。
- 还原恢复当前行政层级的完整 `viewBox`、缩放值和位移。
- 切换全国/都道府县/市区町村层级或加载新的地图资源时自动还原。
- 手机竖屏隐藏地图时不渲染缩放和拖动交互。
- 地图变换完全在浏览器本地完成，不触发 snapshot、SSE 或其他网络请求。

## 7. 数据、性能与错误边界

- 本步骤不改变服务发生地点的正式归因规则，也不改变当前 snapshot/SSE 数据合同。
- 搜索、缩放、拖动、标签避让、时钟和列表动画均为本地行为，不触发数据刷新。
- 地区选择只触发现有范围切换流程；同一选择不重复导航或请求。
- 地图资源失败时继续显示地区选择和搜索；下拉仍能切换正式范围。
- 搜索索引延迟加载，不阻塞首个正式 snapshot 和大屏主体渲染。
- 标签计算只在地图资源、容器尺寸、缩放或活动地区变化时执行，并避免逐帧 React 状态更新。
- 趋势图按照数据域与独立绘图区映射坐标；即使全部数值为零，也显示完整网格、基线和日期轴，而不是把日期标签与数据线挤在一起。

## 8. 测试与验收

### 8.1 自动化测试

先写失败测试，再实现：

- 桌面根容器不再包含整页缩放变量或固定 1124px 最小画布。
- 多组桌面宽高下网格使用视口剩余高度，地图和图表可收缩，页面无横向/纵向溢出。
- 低高度紧凑模式保留所有核心面板。
- 趋势图保持可读纵向绘图区，零值序列、单点序列和七日序列均不会与日期轴重叠。
- 手机竖屏隐藏地图和缩放控件，但地区搜索、三级下拉和数据面板存在。
- 全国索引包含 47 个都道府县、1918 个市区町村和东京 23 个特别区；搜索结果路径与代码正确。
- 搜索和下拉保留 `period` 并生成正确的 JP/admin1/admin2 URL 范围。
- 键盘搜索、空结果、索引失败和地图失败回退可用。
- 密集标签不重叠，外部标签有对应引导线，屏幕字形可读且排布/渐进披露结果确定。
- 放大、缩小、上下限、还原、层级切换重置、拖动边界和减少动态模式通过。
- 地图本地交互不调用 snapshot 或 SSE API。
- 新增用户文案通过现有五语言审计。

### 8.2 真实浏览器验收

- 桌面样本至少覆盖 1366×768、1440×900、1920×1080、2560×1440，以及一个宽而低的视口；所有样本页面 `scrollWidth === clientWidth` 且 `scrollHeight === clientHeight`。
- 日间和 `blue-black` 主题均检查卡片密度、地图可读性和控件一致性。
- 每个桌面样本检查趋势图的网格、数据线和日期轴之间无重叠或压扁；零数据和有数据两种状态都需截图验收。
- 东京、离岛密集区域和至少一个市区町村密集区域检查标签、引导线和缩放后排布。
- 验证放大、缩小、拖动、还原和切换层级重置。
- 手机竖屏至少覆盖 320px、390px、440px 宽度：地图无占位、地区选择和搜索可用、页面无横向溢出并允许纵向滚动。
- DevTools Network 验证搜索、缩放、拖动和标签排布不产生业务请求；原有刷新节奏保持不变。
