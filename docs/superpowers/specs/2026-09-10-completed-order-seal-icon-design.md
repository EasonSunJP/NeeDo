# 简易信息卡完单数口径与认证章图标设计

## 目标

统一店铺、服务和技师简易信息卡左上指标栏的第二项，使其都显示各自范围内的正式完单数，并将旧四圆点/旧完成图标替换为参考图中的认证章：荧光绿色实心多齿章体，中央为清晰的白色对勾。

本改动同时保留已经完成的紧凑卡片高度修复。最终需合并到本地 `main`，并在正式本地运行端口 5180 验证；不包含远端推送或部署。

## 三种完单口径

三类数据不得互相替代，也不得用评价数推导：

1. 店铺简易信息卡第二项为店铺总完单数。按 `BookingOrder.shopId` 归属该店铺，且 `status = COMPLETED`、`deletedAt IS NULL` 的正式订单统计。
2. 服务简易信息卡第二项为该店铺内这个服务的完单数。店铺服务按 `BookingOrder.serviceId` 统计；技师服务按 `BookingOrder.technicianServiceId` 统计。两者都只包含 `status = COMPLETED`、`deletedAt IS NULL` 的正式订单，不能使用店铺总完单数或技师总完单数。
3. 技师简易信息卡第二项为该技师本人完单数。继续使用由正式订单生命周期维护的技师绩效汇总 `TechnicianPerformanceSummary.completedOrderCount`，不得读取所属店铺或服务的计数。

缺少正式完单统计的旧兼容数据源显示 `-`，不得回退到 `reviewCount`、静态值或前端估算值。

## 数据链与契约

### 店铺

- 在正式核心读取的店铺卡契约中新增必填 `completedOrderCount`。
- Prisma 店铺卡查询通过带过滤条件的关联 `_count.bookingOrders` 一次返回统计，避免逐卡查询和 N+1。
- 首页、搜索、详情、收藏卡与 IM 店铺分享卡都向共享店铺卡传递相同语义的 `completedOrderCount`。
- 旧 `Store` 兼容模型允许携带可选 `completedOrderCount`；只有正式 API 返回的真实值才显示。

### 服务

- 现有正式 `usageCount` 查询实际已经通过服务与订单关系统计已完成且未删除订单。本次在共享卡展示模型中明确命名为 `completedOrderCount`，所有适配器只把该服务自身的正式计数映射进去。
- 核心读取、收藏卡、IM 服务分享卡及技师服务卡必须保持各自服务 ID 的过滤范围。
- 为避免一次大范围破坏现有 API 消费者，后端现有 `usageCount` 字段暂时兼容保留；卡片层不再把它解释为泛化“使用次数”。

### 技师

- 继续传递现有 `completedOrderCount`，并增加测试证明第二项取技师字段，不取店铺或服务字段。

## 指标展示

- 店铺、服务、技师卡的第二项统一使用 `completed` 图标和本地化“完单数”标签。
- 三类卡仅共享展示组件和数字格式器，不共享统计值。
- 评分、距离、收藏、分享等其他指标顺序与业务语义保持不变。

## 紧凑数字格式

完单数使用共享紧凑格式器；后端和前端模型仍保留精确非负整数：

- `0` 至 `999` 显示完整整数。
- 从 `1000` 开始使用 `k`。
- 非整千值向下截断到一位小数，不四舍五入；末尾 `.0` 省略。
- 明确边界：`999 → 999`、`1000 → 1k`、`1001 → 1k`、`1999 → 1.9k`、`2000 → 2k`。
- 收藏数和分享数沿用现有共享格式规则；本次不修改其业务数据。

## 图形规格

- 继续使用 `0 0 24 24` SVG viewBox 和 `data-app-icon="completed"`。
- 章体采用约 16 个均匀外齿与内凹转折形成的闭合矢量轮廓，填充 `currentColor`，从卡片指标栏继承 NeeDo 荧光绿色。
- 白色对勾位于视觉中心，采用圆头、圆角折线；左下起笔、中心转折、右上收笔，确保 24px 移动端尺寸和 32px 放大尺寸都清晰。
- 不添加位图、渐变、文字或动画；保持深色卡片背景上的高对比度。

## 测试与验收

- 先增加失败测试，分别证明店铺、服务、技师第二项读取正确字段，且没有回退到评价数或其他实体计数。
- Repository 测试证明店铺和服务计数都包含 `COMPLETED + deletedAt: null` 过滤，并随现有列表查询一次加载。
- API 与 OpenAPI 测试覆盖店铺 `completedOrderCount` 契约及现有服务计数兼容契约。
- 格式器测试覆盖 `999`、`1000`、`1001`、`1999`、`2000`，其中 `1999` 必须显示 `1.9k`。
- 图标测试确认 `completed` 包含独立的认证章轮廓与白色对勾，并不再输出旧环形箭头结构。
- 卡片高度测试继续证明简易信息卡按内容自适应，不恢复 `min-h-[320px]` 或 `aspect-[16/9]`。
- 相关前后端定向测试、TypeScript 检查和正式构建通过。
- 将验证通过的提交合并到本地 `main` 后，核对 5180 的监听 PID、cwd、分支和源码版本，再在约 440px 宽度下浏览器验收三类卡片的高度、第二项图标、计数口径和 `k` 格式。
- 本微步骤不授权远端推送或部署。
