# NeeDo 用户中心信息卡内联编辑设计

## 目标

用户端 `/me` 保留当前完整个人中心页面，但调整个人信息卡和页面底部交互：

- 信息卡右上按钮是编辑模式入口，不再跳转账户设置。
- 点击后，信息卡在原位置切换为可编辑状态。
- 编辑状态下，右上按钮变成红色 X，用于取消编辑。
- `/me` 在普通状态和编辑状态都不显示原有底部导航。
- 编辑状态下显示固定悬浮的“保存并退出编辑模式”按钮；按钮相对视口固定，不随页面滚动。
- 正式账号保存后必须写入正式后端，刷新页面后仍保留修改。

本次只修改用户端个人中心及其正式资料写入链路，不改变首页、动态、聊天、通讯录等其他页面的导航。

## 采用方案

采用“原页内联编辑 + 固定悬浮保存动作”。

未采用以下方案：

- 在原底部导航上方再叠一层保存栏：会同时出现两套底部操作，视觉拥挤且容易误触。
- 跳转 `/me/settings/profile` 编辑：不符合“信息卡内容直接开启可编辑模式”的要求。
- 只更新浏览器本地状态：正式账号刷新后会丢失修改，不符合正式开发要求。

## 页面状态

### 普通状态

- 信息卡展示正式资料。
- 信息卡右上显示编辑按钮。
- 不显示用户端底部导航。
- 不显示保存按钮。
- NDP、利用次数、信用值、账号 ID、会员等级等系统计算字段始终只读。

### 编辑状态

- 当前信息卡在原位置切换为表单，不打开全屏浮层，也不跳转其他页面。
- 可编辑内容沿用现有资料编辑范围：头像、昵称、性别、年龄、身高、语言能力、自我介绍和隐私范围。
- 信息卡右上显示红色 X；点击后丢弃本次未保存草稿并恢复普通状态。
- 页面底部显示“保存并退出编辑模式”按钮。
- 保存按钮使用 `position: fixed` 语义并处理底部安全区，因此页面滚动时位置不变。
- 固定按钮不能遮挡最后一项表单；编辑状态下内容区增加与按钮高度匹配的底部留白。

### 保存中

- 保存按钮进入不可重复点击的提交状态。
- 红色 X 暂时不可操作，避免提交过程中同时取消造成状态竞争。
- 表单草稿保持可见。

### 保存成功

- 使用服务端返回的最新资料更新信息卡。
- 退出编辑状态。
- 隐藏悬浮保存按钮。
- 显示简短成功反馈。

### 保存失败

- 保持编辑状态和用户草稿。
- 恢复保存按钮和红色 X 的可操作状态。
- 在固定操作区附近显示明确错误信息，允许用户重试。
- 不用浏览器本地数据伪装成正式保存成功。

## 前端结构

`UserCenterPage.tsx` 继续作为唯一用户中心页面，不新增 formal/demo 两套页面。

- `CompleteUserCenterPage` 管理 `view`、`editing`、`saving` 三种状态。
- 正式资料加载成功后，以服务端数据初始化编辑草稿。
- 信息卡右上按钮在普通状态调用 `startProfileEdit`，在编辑状态调用 `cancelProfileEdit`。
- `/me` 的 `MobileShell` 不再传入 `userNavItems`；加载态、错误态和完整内容态保持一致。
- 固定悬浮保存动作只在编辑状态渲染，调用统一的 `saveProfileEdit`。
- 成功保存后用 API 响应替换当前资料；不依赖刷新页面或 browser storage 合并。
- 明确的 frontend-preview 会话仍可保留现有兼容数据，但不得影响正式账号的 API 写入路径。

## 正式数据写入

新增受保护的当前用户资料更新契约。客户端不能传入其他用户或资料 ID，后端只从已认证的 customer identity 解析当前 `CustomerProfile`。

写入范围与信息卡当前编辑字段一致：

- 昵称
- 头像媒体
- 性别
- 年龄
- 身高
- 语言能力
- 自我介绍
- 隐私范围

后端要求：

- 请求体使用 Zod 校验，并限制字符串长度、年龄和身高范围、语言数量及枚举值。
- Controller 只处理请求和响应；Service 处理身份、事务和审计；Repository 处理 Prisma 数据访问。
- 必要的资料字段通过 Prisma migration 正式落库。
- 头像通过正式媒体写入路径保存，不把 data URL 或临时浏览器地址直接写入资料表。
- 每次成功修改写入审计日志，记录资料 ID 和变更字段，不记录图片二进制或敏感认证信息。
- API 返回更新后的完整资料视图，供前端立即刷新信息卡。
- OpenAPI 和接口文档同步更新。

## 导航规则

- `/me` 普通状态：无底部导航。
- `/me` 编辑状态：无底部导航，只有固定悬浮保存按钮。
- `/me` 加载态和错误态：无底部导航。
- 其他用户端页面继续使用现有底部导航，入口数量、顺序和行为不变。

## 测试与验收

自动化测试必须先覆盖失败行为，再实现代码：

- 正式账号和 frontend-preview 账号的信息卡右上按钮都进入内联编辑模式。
- 进入编辑模式后右上按钮变为红色 X。
- 点击红色 X 会丢弃草稿并退出编辑模式。
- `/me` 的普通、加载、错误和编辑状态都不渲染 `userNavItems`。
- 悬浮保存按钮只在编辑状态出现，并使用固定定位和安全区偏移。
- 保存中禁止重复提交。
- 保存成功后退出编辑状态并显示服务端返回值。
- 保存失败后保留草稿和编辑状态。
- 受保护 API 只能修改当前 customer identity 对应的资料。
- 非 customer identity、越权访问、非法字段和非法取值会被拒绝。
- migration、Repository、Service、Controller、OpenAPI、前端 API adapter 均有相应测试。

最终验收需要在实际 `/me` 页面完成：

1. 普通状态确认底部导航不存在。
2. 点击卡片右上编辑按钮，确认卡片原地进入编辑模式。
3. 滚动页面，确认红色 X 和悬浮保存按钮的行为符合设计，保存按钮不随内容移动。
4. 点击红色 X，确认草稿被丢弃。
5. 再次编辑并保存，确认退出编辑状态。
6. 刷新页面，确认正式资料仍是保存后的值。
7. 检查首页、动态、聊天、通讯录等其他页面，确认其底部导航未受影响。

## 非本次范围

- 不重做个人中心整体视觉。
- 不修改其他页面的底部导航。
- 不新增第二套资料页或简化版页面。
- 不修改 NDP、订单统计、信用值和会员等级的计算逻辑。
- 不重构 Auth、RBAC、Booking、IM 或 Social。
