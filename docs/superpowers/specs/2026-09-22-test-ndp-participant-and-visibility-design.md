# Test NDP 测试主体、入账与管理员可见性设计

日期：2026-09-22

## 目标

在运营后台提供可审计的测试人员管理、Test NDP 人工入账和管理员个人可见性设置，同时保证 Test NDP 只能在测试账号与测试店铺之间流通，并在任何情况下都不进入正式结算。正式 NDP 继续使用双人审核入账。

## 已确认规则

- 测试资格以账号为单位。选择账号下任一身份加入测试人员后，该账号的全部身份都成为测试身份。
- 当前全部 `User.isTestAccount = true` 的账号自动出现在测试人员列表中，不维护第二套名单。
- 只有归属于测试账号的店铺才是测试店铺；普通管理、员工或临时操作关系不产生测试店铺资格。
- Test NDP 只允许在测试账号和测试店铺之间流通。任一交易参与方不符合测试资格时，支付、冻结、扣款、退款、奖励、转账和完成动作均拒绝。
- Test NDP 永远不进入提现、兑付、代理佣金、商家结算、正式对账或正式财务导出。
- Test NDP 使用独立账本科目，可人工入账但不得直接修改钱包余额。
- 正式 NDP 继续使用既有钱包调整申请与双人审核，申请人不得自审。
- 拥有 Test NDP 钱包的账号继续显示余额；没有 Test NDP 钱包的账号不显示空字段。

## 采用方案

继续使用 `User.isTestAccount` 作为唯一资格真值。测试人员设置页是该字段的管理投影；测试店铺资格从店铺的权威归属账号派生。管理员个人显示偏好单独持久化，并由服务端查询层执行过滤。

不建立独立白名单表，避免与账号分类形成两个真值；不只做前端过滤，避免接口和导出泄漏测试数据。

## 测试人员与店铺资格

- 运营后台设置增加“测试人员”区域，支持按 NeeDo ID、账号、邮箱、手机号或身份搜索。
- 选择任一身份后，服务端解析为唯一 `userId` 并更新账号级测试分类。
- 当前测试账号直接进入列表。
- 添加继续使用既有测试钱包校准链路；余额变化生成 Test NDP 账本流水。
- 移除前检查账号及归属店铺的冻结、未完成订单、退款等活动状态；存在活动状态时不做部分移除。
- 历史钱包、流水和审计保留。

店铺是否为测试店铺由权威归属关系判定。店铺管理员、员工或代运营账号是测试账号，不会自动把非其所有的店铺变成测试店铺。

## 权限

- 名单读取复用运营用户读取权限。
- 添加和删除复用 `user:test-account:update`，默认仅最高权限管理员持有，可由最高管理员通过现有角色权限管理授权。
- Test NDP 人工入账使用独立财务权限，名单管理权限不隐式包含入账权限。
- 资格变更、入账、拒绝和管理员偏好变更全部写入审计。

## 管理员个人显示偏好

运营后台设置增加“显示 Test NDP 数据”个人开关，绑定当前运营管理员账号：

- 未设置时，开发、测试和 staging 默认开启，production 默认关闭。
- 明确设置后只影响本人。
- 开启时可看到 Test NDP 余额、订单、流水、账本、指标、排行、汇总、导出和入账入口。
- 关闭时，该管理员的运营 API 和界面不返回任何使用 Test NDP 的余额、订单、流水、账本、统计、排行、汇总或导出数据，入账入口也隐藏。
- 测试人员资格列表仍可见。
- 过滤由服务端根据已认证管理员执行；前端只展示。
- 关闭不影响测试账号自身的钱包、订单和支付，也不删除记录。

个人偏好使用可空覆盖值；空值按当前运行环境计算默认值。

## Test NDP 流通门禁

所有 Test NDP mutation 在事务内、钱包变更前统一校验：

1. 用户钱包所有者必须是有效测试账号。
2. 店铺钱包所有者必须是归属于测试账号的有效测试店铺。
3. 付款方、收款方、奖励接收方、退款接收方和关联店铺全部符合资格。
4. 钱包及订单财务快照均为 `TEST_NDP`，不得与 `NDP` 混用。
5. 活动 Test NDP 交易阻塞资格移除。

Test NDP 可生成测试专用订单完成状态和独立账本，但不得进入正式 reconciliation、settlement、payout 或 withdrawal 队列。

## 入账流程

### Test NDP

- 从测试人员列表或用户详情进入“添加 Test NDP”。
- 目标必须仍为测试账号或测试店铺。
- 请求包含正整数金额、原因和幂等键。
- 同一事务内锁定主体与钱包、校验资格、增加余额、创建独立 `TEST_NDP_MANUAL_CREDIT` 账本交易与分录，并写审计。
- 同幂等键、同内容返回原结果；内容不同返回冲突。

### 正式 NDP

- 运营入口创建既有钱包调整申请。
- 另一名有权限的运营或财务审核后入账，申请人不能自审。
- 不复用 Test NDP 直接入账接口。

## 数据过滤

管理员关闭个人开关后：

- 钱包和账本排除 `TEST_NDP`。
- 使用 Test NDP 的订单及其派生经营数据按订单财务快照币种排除。
- 排行、趋势、汇总和导出从源查询排除测试记录。
- 不返回 Test NDP reconciliation、测试支付渠道或测试财务明细。
- 测试人员设置仍可管理资格，但普通用户列表不显示 Test NDP 余额。

## 大盘故障修复

工资补偿档案异常只能让受影响的专职、兼职佣金指标返回 `not_available`，不得使整个 overview 返回 500。前端主大盘与 overview 独立加载；overview 失败时仍展示已成功返回的主经营数据。

## 验证

测试先行覆盖资格、权限、活动状态阻塞、全参与方门禁、人工入账幂等与审计、正式 NDP 双人审核、个人偏好环境默认和账号隔离、运营查询过滤、大盘异常降级及前端入口。最终执行前后端 lint/build、非 5180 浏览器验收、合并 main 后 5180 最终验收。

## 非目标

- 不把 Test NDP 转换为正式 NDP。
- 不允许 Test NDP 与非测试主体交易或参与正式结算。
- 不删除历史数据。
- 不新增 mock、免鉴权入口或直接余额编辑。
- 不 push、不部署、不修改远程环境。
