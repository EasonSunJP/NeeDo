# IM 好友通过后联系人信息页切换设计

日期：2026-08-30

范围：用户端、技师端、商户端共用的正式 IM 好友资料页与单聊联系人设置页

## 背景与根因

好友申请资料页在接受申请后只执行正式接受接口、刷新 Store，并重新读取 DirectoryProfile。新的 DirectoryProfile 已经变为 `friend`，所以“拒绝”和“添加好友”动作消失，但当前路由和页面组件都没有变化，页面仍停留在申请前的只读资料结构。

正式接受事务已经创建双向 Contact、双向 Follow，并恢复或创建好友直接会话。现有 `ImConversationInfoPage` 也已经包含图 2 所需的完整联系人能力，因此问题是接受成功后的前端状态导航缺失，而不是后端好友关系、数据库或联系人设置组件缺失。

## 目标行为

- 好友申请资料页和单聊联系人设置页统一显示标题“联系人信息”。
- 接收方点击“添加好友”且正式接口成功后，当前页面自动切换到该联系人的完整单聊联系人信息页。
- 完整页继续显示正式身份资料卡、标签编辑、动态入口、消息免打扰、置顶聊天、黑名单/删除联系人能力，以及底部“开始聊天”。
- 已经是好友的申请记录或目录资料再次打开时，也进入同一完整联系人信息页，不回到只读申请资料结构。
- 群聊仍显示“信息设置”，不使用“联系人信息”。
- 简体中文新增“联系人信息”词条，并补齐繁体中文、日文、英文和韩文翻译。

## 方案

采用“关系状态驱动重用现有联系人设置页”的方案：

1. `ImDirectoryProfilePage` 继续负责非好友、待验证、被拒绝和已过期状态。
2. 正式 DirectoryProfile 的 `relationship` 变为 `friend` 后，通过现有 `ensureDirectConversation(userId)` 取得服务端权威的直接会话。
3. 使用 `replace` 导航到 `config.routes.conversationInfo(conversation.id)`，避免返回键回到已经失效的申请动作页。
4. 接受申请后的重新读取和已经是好友时的首次资料读取都走同一状态切换逻辑，避免只修点击瞬间而遗漏刷新或重进路径。
5. 会话解析期间显示明确加载状态；解析失败时保留可重试错误，不伪造已进入完整设置页。

不采用以下方案：

- 把 `ImConversationInfoPage` 的标签、开关、联系人操作和开始聊天区域复制进 `ImDirectoryProfilePage`：会产生两套联系人设置状态和后续维护分叉。
- 接受后返回“新的朋友”或通讯录：会增加一次点击，也不符合用户要求的图 2 即时切换。
- 仅在按钮回调中直接隐藏动作区：这正是当前缺陷，无法覆盖刷新、重进或其他关系更新来源。

## 数据流

```text
点击添加好友
  -> POST /api/v1/im/friend-requests/:id/accept
  -> Store 刷新正式 FriendRequest / Contact / Conversation
  -> GET /api/v1/im/directory/:userId
  -> relationship = friend
  -> ensureDirectConversation(userId)
  -> replace 到 /messages/:conversationId/info
  -> 渲染完整联系人信息页
```

标题规则：

```text
好友申请/目录资料页                  -> 联系人信息
单聊 ImConversationInfoPage          -> 联系人信息
联系人详情跳转中的加载/失败页          -> 联系人信息
群聊 ImConversationInfoPage          -> 信息设置
```

## 错误与并发边界

- 只有接受接口成功且正式关系重新读取为 `friend` 后才触发切换。
- 重复 effect、StrictMode 重放或 SSE/Store 同步不得创建平行会话；继续依赖 `ensureDirectConversation` 的既有幂等语义。
- 组件卸载后不得更新错误状态或执行第二次导航。
- 会话读取失败时显示重试入口；不退回只隐藏按钮的半完成状态。
- 不新增 mock、浏览器业务持久化、API、schema、migration 或轮询。
- 保留工作区中现有判断贴纸等无关未提交改动。

## 测试与验收

按 TDD 先增加失败回归测试，再改生产代码：

1. 目录资料页标题使用“联系人信息”，不再使用“账号信息”。
2. 正式关系变为 `friend` 后会解析直接会话并以 `replace` 进入完整会话信息路由。
3. 接受申请成功后走相同关系状态切换，而不是只让动作按钮消失。
4. 单聊联系人信息页标题为“联系人信息”，群聊仍为“信息设置”。
5. 联系人详情的中转加载与错误页标题为“联系人信息”。
6. “联系人信息”五语言翻译通过定向测试。
7. 运行相关 IM 回归测试、i18n 测试、lint 与正式 production build。
8. 在正式本地运行环境以移动端视口验收：接收好友申请后出现图 2 的完整区域；刷新和再次进入仍保持；浏览器控制台无新增错误，页面无横向溢出或底部按钮遮挡。

## 非目标

- 不修改好友申请 72 小时状态机、接受事务、双向 Contact/Follow 规则或删除好友规则。
- 不改变身份资料卡字段、信用值可见性、标签数据合同或 Social 动态内容。
- 不重做图 2 的既有视觉组件，也不改变群聊设置页结构。
