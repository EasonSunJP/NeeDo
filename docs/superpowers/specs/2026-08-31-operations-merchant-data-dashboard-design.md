# NeeDo 运营与商户数据大盘设计

日期：2026-08-31  
阶段：Step 12 — 运营后台与商户后台真实数据  
状态：已确认，待实施计划

## 1. 目标

把运营后台和商户后台现有总览、快照与经营驾驶舱收敛为各自唯一的“数据大盘”，参考用户提供的管理平台截图组织筛选栏、核心数字、趋势图和汇总数字，同时保持 NeeDo 现有后台主题与导航体系。

本次只使用正式 MySQL、Prisma、钱包账本、订单财务、排班、账号、身份、商家 SaaS 计费和审计数据。不得新增 mock、浏览器演示指标、静态曲线或本地会员数据。

## 2. 页面与路由边界

### 2.1 运营后台

- 唯一入口：`/admin`。
- 页面与菜单统一命名为“数据大盘”。
- 继续使用正式 `GET /api/v1/backoffice/dashboard`。

### 2.2 商户后台

- 唯一入口：`/merchant-admin`。
- 页面与菜单统一命名为“数据大盘”。
- 删除 `MerchantAdminAnalyticsPage`、页面测试、重复菜单项和 `/merchant-admin/analytics` 路由。
- 不保留第二套驾驶舱页面或平行 Dashboard DTO。
- 继续使用正式 `GET /api/v1/merchant-admin/dashboard`。

### 2.3 明确不做

- 不增加参考图底部的服务、技师或会员排行榜。
- 不在本微步骤实现会员卡模板、开卡、充值、核销、退款或会员账本。
- 不新增图表依赖；使用可访问的原生 SVG 与 CSS。
- 不修改订单、排班、钱包或 SaaS 计费的业务状态机。

## 3. 筛选与时间规则

两端提供统一时间选项：

- 今日
- 近 7 天，默认值
- 近 30 天
- 本周
- 本月
- 今年
- 自定义日期

运营后台额外提供城市筛选，默认“全部城市”。城市选项只来自正式店铺/资料数据，不写死城市列表。查询和重置都重新请求后端聚合。

所有时间按 `Asia/Tokyo` 解释。自定义范围包含起止日且最长 366 天。今天按小时分桶；近 7 天、近 30 天、本周和本月按天；今年以及超过 92 天的自定义范围按月。后端返回分桶标签，不由浏览器重新解释 UTC 时间。

每张大数字卡同时返回紧邻的等长上一周期值和变化比例。累计型指标比较两个周期结束时的期末存量；流量型指标比较两个完整期间。

## 4. 运营数据大盘

### 4.1 五张核心数字卡

1. 可排班时段：期间内 `AVAILABLE` 状态的正式 `ScheduleSlot` 数量，单位“个时段”。
2. 活跃技师：期间内至少存在一个排班时段，或参与至少一笔非取消订单的未删除技师去重数。
3. 注册技师：截至期间结束时所有未删除正式技师档案的累计数，不要求已发布或在期间内有活动。
4. 店铺数：截至期间结束时所有未删除正式店铺的累计数。
5. 新增用户：期间内新建且未删除的正式 CustomerProfile 去重数。

### 4.2 三张趋势图

1. 订单总量与服务 GMV：双曲线、双纵轴。订单总量按服务时间统计未删除订单；服务 GMV 只统计已完成、未退款的正式服务金额。
2. NDP 净收入与冻结 NDP：双曲线。净收入为实际平台费和请求费扣除用户返点后的正式 NDP；冻结量为每个分桶结束时仍有效的正式 hold 存量。
3. 店铺数与注册技师数：双曲线，均为每个分桶结束时的累计存量。

### 4.3 三张汇总数字卡

1. 用户奖励 NDP：期间内已实际入账的用户返点，不含待发放、禁用或过期奖励。
2. 存量 NDP：截至期间结束时所有钱包正数可用余额与冻结余额的合计。
3. 提现 NDP：期间内已审核通过、已关联正式账本交易并已扣除钱包余额的提现金额。

正式 NDP 是主值；Test NDP 是明确标注的次级值。Test NDP 永远不进入提现、可结算值或正式 NDP 主值。

城市筛选作用于订单、GMV、排班、店铺、技师、新增用户和可按订单店铺追溯的 NDP 指标。钱包存量与提现无法可靠拆分到单一城市，始终显示全平台值，并标记“不受城市筛选影响”。

## 5. 商户数据大盘

### 5.1 店铺信息卡

保留并强化顶部店铺信息卡，显示：

- 店铺名称、城市、地址和营业状态。
- SaaS 账号类型与状态：年费、月费、试用、免费或欠费。显示值来自当前 `SaasBillingProfile` 和正式计费策略。
- 当前店铺钱包的实时可用余额、冻结余额和币种。该余额是当前快照，不随历史日期筛选变化，并明确标注“当前余额”。
- 多店商户显示“切换店铺”按钮；普通单店账号不显示。

### 5.2 四张核心数字卡

1. 可排班时段：期间内当前店铺的 `AVAILABLE` 时段数。
2. 活跃技师：期间内当前店铺至少有一个排班时段，或参与至少一笔非取消订单的未删除技师去重数。
3. 注册技师：截至期间结束时当前店铺范围内所有未删除正式技师档案累计数。
4. 会员数：大字读取正式 API 的 `memberCount`；小字显示期间内至少完成一笔订单的去重利用者数，重复完成多单仍计一人。

会员卡数据源尚未建立时，API 必须返回：

```json
{
  "memberCount": null,
  "memberDataStatus": "not_available",
  "completedCustomerCount": 123
}
```

前端显示“会员数 —”“会员功能尚未开放”和真实利用者数。不得把 `null` 转成 0，也不得从旧浏览器会员 Store 读取数据。以后会员卡数据库接通时只替换 API 聚合，不重做卡片。

### 5.3 三张图表

1. 订单总量与服务 GMV：双曲线、双纵轴，严格限制在当前店铺。
2. 利润：单曲线，聚合正式 `shopEstimatedGrossProfitJpy`。公式为服务 GMV减技师毛收入减店铺承担 NDP，只统计已完成、未退款且收入已上报或确认的订单。
3. 排班状态：三色分组柱状图，按分桶展示总排班时长、空闲可预约时长和已预约时长，单位为小时。总时长等于有效 `AVAILABLE` 和 `BOOKED` 时段时长之和，不重复叠加三组数值。

技师毛收入沿用现有薪酬引擎：

```text
基础报酬 + 订单分成 + 保底补足 + 奖金 - 扣款
```

技师承担的 NDP 不属于技师毛收入，而在计算技师净收入时扣除。

### 5.4 两张汇总数字卡

1. NDP 成本：店铺实际承担的 NDP 总成本，并拆分为平台净收入与用户返点。例如总成本 500 NDP，显示“平台 400 NDP、用户返点 100 NDP”。
2. 冻结 NDP：期间结束时当前店铺仍有效的正式平台费 hold 存量。

## 6. API 合同

现有 Dashboard 路由增加查询参数：

```text
period=today|last7days|last30days|week|month|year|custom
from=YYYY-MM-DD
to=YYYY-MM-DD
city=<exact persisted city>
```

`from` 与 `to` 只在 `period=custom` 时允许。商户接口不接受 `city` 或客户端任意 `shopId`。

响应从当前松散 `metrics` 数组升级为有名字的结构，至少包含：

- `filter`：服务端规范化后的期间、时区、城市和分桶粒度。
- `summary`：当前周期、上一周期和变化比例。
- `series`：带稳定 bucket key 和 label 的图表序列。
- `finance`：正式 NDP 与 Test NDP 分离的汇总。
- `shop`：商户当前店铺资料、计费与实时钱包快照。
- `membership`：会员可用状态、会员数和期间去重利用者数。
- `switchableShops` 或独立受保护店铺列表资源。

可在迁移期间保留现有字段供同一提交内的调用方升级，但交付时前端只读取新的具名字段，不继续依赖标签文本解析数值。

## 7. 多店商户切换

新增受保护的可管理店铺列表和切换能力：

1. shop-scoped 身份只能看到当前店铺。
2. merchant-account-scoped 身份只能看到与当前 MerchantAccount 存在有效、未删除 `MerchantShopMembership` 的店铺。
3. 切换请求可以提交目标店铺 ID，但服务端必须重新校验当前身份、商户账号、会员关系、店铺状态和 RBAC。
4. 校验成功后轮换 Access Token 与 Refresh Token，将所选店铺作为签名后的商户后台上下文；不得依赖浏览器自行附加一个未经验证的 shopId 扩大权限。
5. Refresh 和身份切换必须保留或清除店铺上下文：刷新时重新验证仍有效的店铺关系；离开商户身份时清除；切换到单店身份时固定为该身份店铺。
6. 所有商户后台接口使用同一个服务端店铺范围解析器。切店不是只改变 Dashboard，也要改变订单、排班、财务、员工和设置的范围。
7. 切换成功写审计；权限已撤销或关系已结束时返回稳定错误，前端保留原店铺和现有数据。

切换过程中前端使旧请求失效；新店铺 Dashboard 成功后再更新页面。不得让前一家店的迟到响应覆盖新店铺。

## 8. 查询与性能

- Controller 只处理请求/响应，Zod 负责参数校验，Service 负责时间与权限口径，Repository 负责聚合查询。
- 所有软删除数据都必须过滤。
- 使用有界的批量聚合或参数化 SQL/Prisma 查询，不对每个分桶、店铺、技师或钱包发起一条查询。
- 复用现有订单、状态历史、OrderFinancial、Wallet、WalletLedger、WalletHold、WalletAdjustmentRequest、ScheduleSlot、TechnicianProfile、Shop、MerchantAccount、MerchantShopMembership 和 SaasBillingProfile；本微步骤不新增表或 migration。
- 期末存量必须按截止时间重建，不能拿当前余额冒充历史余额。
- 自定义范围上限、固定分桶粒度和有限序列点数防止 Dashboard 成为无边界报表接口。

## 9. 视觉与可访问性

- 沿用现有后台深浅主题、色彩 token、圆角、阴影和排版，不复制参考站点品牌。
- 顶部筛选栏、核心数字卡、三图表和汇总卡采用参考图的信息密度。
- 大卡用克制的彩色边缘、图标底和趋势色区分类别；图表保持白底/主题底、细网格和高对比图例。
- 双曲线使用不同颜色、点形和左右纵轴，不只依赖颜色表达。
- 图表提供可读标题、单位、图例和屏幕阅读器摘要；空数据绘制坐标骨架并显示“当前范围暂无数据”。
- 键盘焦点可见，切店弹层可用 Escape 关闭，减少动态效果遵守 `prefers-reduced-motion`。
- 宽屏展示五列或四列数字卡；窄屏按两列/单列重排，图表不得造成页面横向溢出。

## 10. 错误与空状态

- Dashboard 加载失败保留当前筛选，并提供重试。
- 无数据返回真实 0、空序列或明确的 `null`，不生成演示曲线。
- 401 显示登录失效；403 显示当前身份无权查看；5xx 显示服务暂不可用。
- 无会员数据源是成功状态，不触发整页错误。
- 钱包不存在时必须区分“未开通钱包”与余额 0。
- 切店失败不清空当前页或切换当前店铺。
- 自定义日期错误、范围过长和不允许的查询参数返回稳定 400 错误。
