# IM 消息菜单下层清晰度与常用表情稳定顺序设计

## 1. 目标

本微步骤只修复两个共享前端交互：

1. 聊天消息长按或右键打开消息操作菜单时，菜单下层聊天内容不再被模糊、饱和、对比度或折射类滤镜处理。
2. 聊天与动态回复共用的常用表情，在同一次面板打开期间保持原顺序；本次选择仍立即记录，但新顺序只在关闭后下一次打开时显示。

## 2. 明确边界

- 消息操作菜单本体、箭头、按钮、快捷回应、定位、玻璃材质和交互全部保持不变。
- 全屏菜单遮罩继续保留轻微纯黑透明压层及点击关闭能力，只移除遮罩的 `backdrop-filter`、`filter` 与模糊工具类。
- 不修改消息、Social、reaction REST/SSE、RBAC、数据库、migration 或最近使用记录格式。
- 不改变判断贴纸、普通 Unicode 表情的发送内容，也不改变记录最近使用表情的时机。

## 3. 实现设计

### 3.1 消息菜单下层

`ImMessageActionSheet` 的全屏 backdrop 使用专用 `im-message-action-backdrop` 类。该类只提供透明暗色背景，并明确将标准及 WebKit `backdrop-filter` 和普通 `filter` 设为 `none`。菜单 sheet 与 arrow 不增加该类，也不修改它们现有样式。

### 3.2 常用表情顺序

`ImChatComposer` 继续将每次有效选择传给 `recordRecentImReaction`，使共享最近使用记录立即持久化。组件另外保存“当前打开周期的可见快照”：

- 面板首次以 `emoji` 状态渲染时读取一次最新顺序。
- 面板保持打开时，共享最近使用记录的变更不替换该快照。
- 面板离开 `emoji` 后再次进入时，重新读取最新顺序。

动态快捷回复复用同一个 `ImChatComposer`，因此不增加 Social 专用排序状态或第二套表情目录。

## 4. 验证

- 组件测试证明 backdrop 不含任何 blur 工具类，专用 CSS 明确禁用三类滤镜，同时菜单与箭头原样保留现有玻璃类。
- 聊天输入框测试证明一次打开期间点击常用表情不会令按钮换位，关闭后再次打开才更新顺序。
- Social 快捷回复测试重复同一交互，证明动态入口继承共享行为。
- 运行聚焦测试、TypeScript 检查、正式生产构建及 `git diff --check`。
