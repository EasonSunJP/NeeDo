# 我的收藏统一时间线设计

## 目标

把当前按类型纵向堆叠的大卡片页面改为移动端收藏时间线。标题容器底部固定显示“全部、店铺、技师、服务、动态、聊天记录”六个分类；内容按收藏或最近操作时间倒序，并按“今天、昨天、YYYY年MM月DD日”分组。

所有交互继续使用正式 API、权限与审计。不得用 `localStorage`、前端假状态或新增 mock 代替置顶、删除、转发、多选和快捷表情的持久化。

## 页面结构

`MobileFullscreenHeader` 继续负责返回、标题、说明、搜索和关闭。分类标签放入它的 footer：

- 搜索关闭时，footer 只显示可横向滚动的六分类标签。
- 搜索开启时，footer 先显示搜索框，再显示分类标签。
- 当前分类使用现有客户端荧光绿色和圆角胶囊，不引入新的主题体系。
- 标签切换保留搜索词，并只在当前分类的数据中筛选。

正文采用参考图的紧凑时间线：日期标题、缩略图或头像、标题、摘要、类型标识、收藏时间。店铺、技师和服务保留进入正式详情页的能力；动态进入动态详情；聊天记录进入已收藏聊天记录详情。

“全部”把五种内容归一为同一种列表项，先显示置顶内容，再按 `activityAt` 倒序；非置顶内容严格按 `activityAt` 倒序。`activityAt` 默认等于收藏时间；用户修改快捷表情后使用该收藏元数据的更新时间。置顶顺序只由 `pinnedAt` 决定，取消置顶后回到普通内容的 `activityAt` 位置。分类页使用相同规则。日期分组使用条目的 `activityAt`，并按 Asia/Tokyo 计算：今天显示“今天”，前一天显示“昨天”，其他日期显示本地化的完整年月日。

页面新增或变更的标签、动作、日期和错误文案全部接入现有 i18n，并补齐项目当前支持的语言，不在组件内写死中文。

## 复用边界

不得新建收藏专用的滑动手势或快捷菜单系统。

- 左滑直接复用 `SwipeActionRow`，在条目右侧同时露出两个动作，顺序为“置顶/取消置顶”和“删除”。颜色、宽度、圆角、滑动距离、回弹和收起行为沿用聊天窗口；收藏页只提供动作配置和业务回调。
- 长按直接复用 `ImMessageActionSheet`，动作配置为“转发、信息置顶/取消信息置顶、删除、多选”，底部继续使用它现有的快捷表情区。面板布局、图标规格、遮罩、动效和关闭方式沿用聊天窗口。
- 如果共享组件缺少通用参数，只扩展共享组件的名称、类型或回调；聊天窗口现有行为和视觉不得改变。
- 长按识别复用聊天消息已有的指针阈值、移动取消和文本选择保护，不建立第二套定时器与手势状态机。
- 多选复用聊天的选择态视觉和底部操作条；收藏页只增加适配五种收藏条目的选择模型。

## 数据模型与 API

新增一份用户级收藏交互元数据，逻辑键为 `ownerUserId + itemType + itemKey`。它只保存：

- `pinnedAt`：为空表示未置顶；
- `reaction`：用户对该收藏内容的私有快捷表情标记；
- 标准的 `id / createdAt / updatedAt / deletedAt`。

`itemType` 只允许 `shop / technician / service / social_post / chat_record`。`itemKey` 使用各正式收藏记录已经公开的稳定标识。服务层必须先验证当前用户仍拥有对应收藏，随后才能写置顶或表情；删除原收藏时同步软删除该元数据。快捷表情不会给店铺、技师或动态作者发送消息。

新增统一分页读取接口 `GET /api/v1/me/favorites`，支持 `type`、`query`、`page`、`pageSize`。Repository 从现有实体收藏、动态收藏和聊天记录收藏读取正式数据；Service 归一为共同 DTO、合并置顶元数据、稳定排序并分页。响应包含：

- 唯一键、内容类型和详情路径所需的公开标识；
- 标题、摘要、图片和类型专用的轻量展示字段；
- `favoritedAt`、`activityAt`、`pinnedAt`、`reaction`；
- `canForward / canDelete` 权限结果。

写接口使用 Zod、JWT、RBAC、OpenAPI 与审计：

- `PUT /api/v1/me/favorites/:type/:itemKey/pin`；
- `DELETE /api/v1/me/favorites/:type/:itemKey/pin`；
- `PUT /api/v1/me/favorites/:type/:itemKey/reaction`；
- `DELETE /api/v1/me/favorites/:type/:itemKey/reaction`。

删除仍调用各来源已有的正式取消收藏接口，不复制删除逻辑。多选删除逐项调用相同来源命令，并汇总逐项结果，避免出现部分失败却显示全部成功。

## 转发与多选

单项转发进入现有 IM 联系人/会话选择器：实体发送正式实体卡片，动态发送动态卡片，聊天记录发送现有 chat-record bundle。多选转发只在所有所选项目都支持正式转发时启用；否则明确显示不支持项，不静默跳过。

多选模式显示选择框、已选数量、转发和删除。删除前使用现有确认层；成功项立即从列表移除，失败项保留并显示失败数量。离开页面、切换身份或完成操作后必须退出多选状态。

## 状态与错误处理

- 每个分类独立保留分页、加载和错误状态；“全部”由统一接口返回，不在前端拼接不同页。
- 置顶和表情采用服务端返回结果更新 UI；请求进行中禁用同一条目的重复操作。
- 删除失败时恢复列表项和原排序位置。
- 搜索、切换分类和翻页必须用 generation guard 忽略迟到响应。
- 空状态按当前分类显示，不再把五种空状态同时铺在一个页面。

## 测试与验收

后端覆盖统一排序、东京日期边界、分页稳定性、所有权隔离、RBAC、置顶/取消置顶、表情写入/清除、源收藏删除后的元数据清理、审计和部分失败。

前端覆盖六分类、全部合并排序、今天/昨天/完整日期、搜索、分页、左滑两动作、长按共享菜单、快捷表情、单选和多选、删除失败恢复，以及共享组件在聊天窗口中的既有回归。

5180 验收至少验证：六分类位置；五类内容的时间顺序；跨午夜日期标签；左滑置顶与删除；长按菜单和快捷表情；置顶刷新后仍保留；多选转发和删除；搜索；窄屏无横向页面溢出。完成后再合并 main、推送 GitHub、部署 Staging，并复验 Staging 的真实数据与 API readiness。
