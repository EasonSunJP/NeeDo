# NeeDo IM 浮动玻璃输入栏与上展面板设计

## 1. 状态与目标

本设计于 2026-08-30 经用户确认，适用于 NeeDo 用户端聊天窗口底部的消息输入区域。

目标是把当前贴满页面宽度、带顶部边线的输入区域，统一为与用户端底部导航相同的浮动玻璃视觉语言；表情与“更多”功能不再像输入栏的一部分向下堆叠，而是在输入栏下方以独立玻璃面板出现，并在底部锚定约束下向上展开。

本轮只调整输入区与展开面板的布局、视觉和响应式行为。语音、文字输入、发送、表情最近使用、完整表情目录、相册或媒体等“更多”动作继续使用现有正式逻辑，不改 API、数据库或消息数据结构。

## 2. 已批准的界面结构

聊天底部使用两个相互独立、视觉一致的玻璃胶囊：

1. **输入胶囊**位于上方，包含麦克风、文字或按住说话区域、表情按钮，以及“更多”或发送按钮。
2. **功能面板胶囊**位于输入胶囊下方，仅在表情或“更多”开启时出现。
3. 两个胶囊之间保留约 `8px` 的明确间距，不拼接、不共用边框，四角始终完整圆角。
4. 整组控件以聊天视口底部和安全区为锚点。面板位于输入胶囊下方，面板高度增加时，其顶部向上扩展，整组控件在可用视口内向上移动。

关闭面板时只保留输入胶囊。不得保留当前整条横贯屏幕的实色底板、顶部白线或直角容器。

## 3. 视觉语言

### 3.1 与底部导航保持同源

输入胶囊和功能面板复用现有 `.client-bottom-nav` 面板的设计语言，而不是复制一组固定颜色：

- 细的半透明主题边框；
- 由 `--client-elevated`、`--client-bg`、`--client-line` 等现有主题变量构成的透明渐变；
- 轻量内描边与上下高光；
- 玻璃模糊、饱和度与对比度处理；
- 克制的悬浮阴影；
- 日间、夜间、黑金、深绿、冷黑灰等现有主题保持可读。

实现应提取或复用一个聊天玻璃容器类，避免把底部导航选择器直接套在 IM 组件上，也避免在 TSX 中复制所有主题分支。

### 3.2 输入胶囊

- 宽度与用户端底部导航使用相同的页面内边距逻辑，窄屏至少保留 `12px` 左右安全间距。
- 胶囊整体为全圆角；建议最小高度 `56px`，内部垂直居中。
- 麦克风、表情和“更多”按钮的可点击区域不小于 `40px`，移动端优先达到 `44px`。
- 文本输入区仍可随多行文字增长，但不破坏胶囊圆角和按钮对齐；现有最大输入高度继续生效。
- 有可发送文字时，“发送”替换“更多”按钮，现有阻止发送和黑名单状态保持不变。
- 按住说话状态、取消提示和最长录音时间保持现有功能与反馈。

### 3.3 功能面板胶囊

- 四角全部圆角，不能因为靠近底部而变成直角，也不能与输入胶囊拼成一整块。
- 与输入胶囊使用相同玻璃材质，但内容区域可以略深，以确保 emoji、图标和标签具有足够对比度。
- 表情面板继续显示第一行最近使用的 8 个表情，下方显示完整目录；内容超出时只在面板内部滚动。
- “更多”面板继续显示现有正式动作，按钮必须保留真实点击行为，不因外层布局或动画拦截事件。
- 面板最大高度约为当前可视视口的 `42%`。超过后内部滚动，不能覆盖聊天标题，也不能把输入胶囊挤出视口。

## 4. 展开、收起与键盘行为

### 4.1 展开方向

面板的视觉起点位于输入胶囊下方。打开时面板高度由底部锚点向上增长，输入胶囊随整组控件向上移动；聊天消息区同步保留可见空间，不能被面板永久遮挡。

表情和“更多”互斥：

- 点击当前已打开的按钮，收起面板。
- 点击另一个按钮，直接切换面板，不先产生一次明显的收起跳动。
- 切换语音模式时关闭表情或“更多”面板，沿用现有行为。

### 4.2 软键盘与可视视口

- 移动端键盘出现时，整组控件跟随 `visualViewport` 或现有安全区布局移动到键盘上方。
- 不以固定设备高度或固定键盘高度计算位置。
- 键盘、面板和输入区不能发生相互覆盖；横竖屏切换后重新依据可视视口计算。
- `env(safe-area-inset-bottom)` 继续生效。

### 4.3 动效

- 使用短距离位移与透明度变化表现面板出现，建议 `160–220ms`。
- 动画不得改变最终点击区域，也不得在结束后留下透明遮罩拦截按钮。
- `prefers-reduced-motion: reduce` 下取消位移动画，仅保留即时或极短淡入。

## 5. 响应式与可访问性

- 以容器实际可用宽度为准，不依赖单一设备型号。
- 窄屏允许缩小胶囊内间距，但不得压缩到按钮重叠或输入框不可用。
- 表情网格列数可以按宽度下降；最近使用仍优先完整展示 8 个，确实不足时允许横向紧凑排列，但不得切断 emoji。
- “更多”动作网格按宽度自适应，标签不可与相邻按钮重叠。
- 所有按钮保留语义化 `button`、键盘焦点环和可理解的 `aria-label`。
- 主题前景色与玻璃背景需要保持可读对比；禁用、选中、录音和发送状态不能只靠颜色区分。
- 外层只能裁剪横向溢出，不能因 `overflow: hidden` 截断向上展开的面板、焦点环或阴影。

## 6. 组件与样式边界

主要修改范围：

- `src/features/im/components.tsx` 中的 `ImChatComposer` 布局与语义标记；
- `src/styles.css` 中新增可复用的 IM 玻璃输入栏、面板和主题样式；
- 与 `ImChatComposer` 相关的前端测试。

不在本轮修改：

- 消息发送、媒体上传、SSE、撤回、删除、快捷回复等消息业务；
- 后端路由、Service、Repository、Prisma schema 或 migration；
- 用户端底部导航本身；
- 首页或动态页轮播。

实现不得新增 mock、第二套聊天输入组件或页面级特例。现有 `ImChatComposer` 继续作为唯一正式输入组件。

## 7. 测试与浏览器验收

按测试先行实现，至少覆盖：

1. 输入区域不再使用横贯页面的顶部边框底板。
2. 输入胶囊与面板是两个独立容器，并保留可识别的测试标记。
3. 面板位于输入胶囊之后，拥有完整圆角、最大高度和内部滚动约束。
4. 表情与“更多”互斥切换，关闭和语音切换行为不回退。
5. 表情点击仍写入草稿并更新最近使用；“更多”动作仍调用原来的 `run`。
6. 发送按钮、禁用状态与录音指针事件没有回退。
7. 样式使用现有主题变量，并支持 reduced motion。

本地浏览器必须在 `5180` 的正式前后端组合上实际验收：

- 约 `440×956` 移动视口和至少一个更窄视口；
- 桌面宽度；
- 日间与夜间主题；
- 单行文字、多行文字、语音模式；
- 表情面板打开、滚动、选择、切换和关闭；
- “更多”面板打开并实际点击一个无破坏性的入口；
- 软件键盘或等价的可视视口缩小场景；
- 页面横向溢出为 0，console 新增 error 为 0。

完成前运行 IM focused tests、相关组件测试、lint、正式生产构建和 `git diff --check`。测试或构建通过不能替代上述浏览器可见验收。

## 8. 回滚边界

本轮没有数据库和 API 变更。若视觉或响应式验收失败，只回滚新的布局类、玻璃样式和对应测试，不回滚或修改消息业务、已发送数据、最近表情本地记录或用户端底部导航。
