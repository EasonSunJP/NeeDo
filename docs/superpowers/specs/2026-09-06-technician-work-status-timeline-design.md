## 方案选择

推荐新增独立工作状态记录与事件，由统一服务向三端提供投影。比只扩展通用审计日志更容易保证状态版本、幂等与考勤查询；比只从订单/排班推导多了真实出勤证据，也能表达移动与休息。

范围属于现有 Step 12 技师状态正式化闭环，复用现有 Step 10 订单状态机；按下列验收关卡顺序实施，不开展其他模块重构。

## 状态与动作

| 操作 | 正式行为 |
| --- | --- |
| 出勤 | 保存实际到岗时间，开启或恢复当前班段的工作状态 |
| 移动中 | 保存移动事件，可关联当前有权操作的预约；不要求新增 GPS 定位能力 |
| 服务中 | 打开已有预约选择/开始服务流程，使用现有开始服务 API；必须有真实预约执行成功才显示服务中 |
| 休息 | 保存休息开始，恢复出勤时关闭该休息区间；服务进行中必须先完成既有服务处理流程 |
| 退勤 | 保存退勤时间，检查当前班段与未完成确认预约，异常时使用应用内确认框并记录原因；进行中的服务不能被退勤按钮隐式完单 |

首次没有出勤记录时显示“未同步”，不能把已发布、已有排班或当天没有订单当成实际出勤/退勤记录。状态展示保留五态；出勤可显示“出勤 · 空闲”，移动、休息与退勤不能折叠成同一个值。技师档案审核状态继续独立存在。

订单开始、完成、取消通过已有执行状态影响工作状态投影；完成服务回到实际出勤/休息事实。重复提交、重试与并发状态变更不得产生重复事件或覆盖较新状态。

## 迟到、早退

- 时间以服务端 UTC 为准；班段按实际服务时区解释，日本现有业务按 Asia/Tokyo 展示。支持跨午夜，不用浏览器本地“今天”拆断夜班。
- 排班迟到：应出勤班段开始后尚无有效出勤记录，记待到岗异常；实际出勤后补充实际到岗及迟到时长，保留原异常事实。
- 预约迟到：已确认预约开始后尚未正式开始服务，即记录异常，关联订单、顾客及预约时间；稍后开始服务补充实际开始时间与偏差。
- 退勤早退：实际退勤早于当前应工作班段结束；如果同班段有未完成的确认预约，一并列出受影响预约。班段正常结束与两段班之间的间隔不判为早退，之后的新班段独立判断到岗。
- 短暂休息不自动判为早退；如果休息期间错过预约开始，仍产生预约迟到。提前结束一单不自动等价于提前退勤。
- 仅可预约 Availability 不是已承诺出勤班次。实施时沿正式排班来源判定实际班段；已确认预约独立构成服务义务，不把个人发布的所有空闲窗口当成强制考勤。
- 判断保存关联排班/预约 ID、当时计划起止时间、实际时间、规则版本、偏差与原因。后改排班不得悄悄抹去已有记录；更正以新事件追加。
- 后台定期检查到期班段/预约，使用唯一事件键去重；页面关闭仍能产生异常。异常发生时间取计划边界，另保留系统检测时间。首次上线不批量把没有出勤记录的历史数据标成迟到。
- 本功能记录运营事实，不自动扣工资、罚款或修改账本。

## 数据与 API

- 独立 Prisma 工作状态快照与不可变事件表，包含基础时间字段、软删除、技师/店铺/关联预约索引；新增 migration，不改已应用 migration。
- 状态、业务事件与审计同事务写入；请求带幂等键及当前版本，服务端决定操作者和事件时间。
- 技师本人读写 API 及分页时间线只使用当前 technician identity scope；Zod、permission、统一错误和 OpenAPI 完整覆盖。
- 商户只读取当前店铺有权访问的工作事件与订单详情；合作技师其他店铺的服务只能显示忙碌，不暴露顾客/地址/订单详情。运营受现有权限控制读取。
- 商户员工列表、调度入口和运营技师列表使用统一工作状态投影，分页批量读取避免 N+1；删除 published→available 映射。
- 三端接收既有实时机制中的状态变更通知并重新读取正式状态；重连及重新进入页面补读，事件仅负责刷新，不作为浏览器内存里的唯一数据源。
- 技师、商户、运营补充记录均持久化并审计，服务端校验长度、身份与店铺范围；提交成功后再加入时间线。

## 本月指标与迟到早退明细

- 在“业务状态与正式指标”现有栅格补上“迟到 / 早退”可点击指标卡，分别显示“本月迟到 N 次 · 早退 M 次”，沿用现有卡片主题、尺寸与交互。有效查询的零记录显示 0；加载失败显示失败及重试，不能显示假零。
- 点击后打开现有详情抽屉体系中的异常列表，默认当前技师、本月、全部异常；返回保留技师详情及原 tab。
- 时间范围提供今日、近 7 天、近 30 天、本周、本月、今年、自定义日期；近 7/30 天含今天，本周按周一开始。自定义日期包含所选结束日，转换为服务时区的起日零点至结束日次日零点的半开 UTC 区间；查询日期以异常应发生时间为准。
- 类型筛选为全部、迟到、早退；迟到明细另标明排班迟到或预约迟到。筛选改变时回到第 1 页，查询参数由服务端校验并执行，不能只筛当前页。
- 列表展示发生时间、类型、关联排班/预约、计划时间、实际时间、偏差时长、未到岗/未开始等待处理状态、原因及有权限的详情入口。未发生实际到岗时保留实际时间为空，并明确正在等待，不能伪造打卡时间。
- 后端按同一异常事实计算本月迟到数和早退数，分页接口返回 list、total、page、page_size。指标聚合不能依赖前端当前页或时间线最近 30 条。
- 每个班段迟到、预约迟到或退勤早退使用稳定异常键；系统检测、实际补报、重试与时间线更新都不重复增加次数。同一班段迟到和某预约迟到是两种不同履约对象，分别标注并计为各一条，不能隐式合并后丢失预约证据。
- 商户与运营按各自授权范围计算和查询；同一授权范围的指标与相同筛选条件的列表总数一致。查询失败/无权限不应暴露其他店铺异常信息。
