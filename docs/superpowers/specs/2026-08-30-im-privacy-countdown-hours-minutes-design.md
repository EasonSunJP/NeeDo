# IM 群聊隐私倒计时小时分钟化设计

日期：2026-08-30

状态：已确认设计

范围：Step 13 正式 IM 中“发起群聊”和已有群聊信息页的隐私模式倒计时

## 目标

群聊隐私模式的消失倒计时只保留“小时”和“分钟”两个输入项。小时允许 `0–99`，分钟允许 `0–59`，因此正式可保存的最大倒计时为 `99 小时 59 分钟`，即 `359940` 秒。

超出任一字段上限时，页面保留用户输入以便修改，并即时显示：

> 时间上限最大为99小时59分钟

超限状态不得创建群聊或保存已有群聊的隐私设置。

## 当前问题

- 两处隐私倒计时编辑器目前都显示月、日、小时、分钟四个字段。
- 小时当前被限制为 `23`，无法表达 `24–99` 小时。
- 输入超限数字时，前端会静默截断为字段上限，用户看不到输入错误，也不会出现要求的提示。
- 正式后端当前允许最长 `400` 天，和新的产品上限不一致，可被绕过前端直接提交。

## 已确认方案

采用“保留原输入、即时校验、前后端共同限制”的方案：

1. 两处编辑器共用同一个小时/分钟输入定义和校验规则。
2. 输入只保留数字字符，但不静默截断超限值。
3. 小时大于 `99` 或分钟大于 `59` 时，在输入区下方显示明确的错误提示，并阻止创建或保存。
4. `00 小时 00 分钟` 继续视为未设置，沿用“请设置消失倒计时”的必填提示。
5. 正式 API 同步把 `disappearingTtlSeconds` 的最大值收紧为 `359940` 秒；最小值仍为 `60` 秒。

不采用以下方案：

- 静默把超限值改成最大值：会掩盖用户实际输入，且不符合需要提示的要求。
- 自动把 `60` 分钟换算成 `1` 小时：改变了用户输入，也会让字段上限规则变得不明确。

## 前端交互与数据流

### 输入布局

- “发起群聊”和已有群聊信息页都把四列布局改为两列。
- 字段顺序固定为“小时”“分钟”。
- 小时输入声明最大值 `99`，分钟输入声明最大值 `59`，移动端继续使用数字键盘。
- 月和日只从本次编辑器移除，不删除底层通用倒计时类型，避免扩大到无关的旧数据结构重构。

### 校验状态

- 输入阶段保留纯数字原值，例如 `100` 或 `60`，以便页面能判断并展示错误。
- 任一字段超限时，输入区展示具有错误语义的文案“时间上限最大为99小时59分钟”。
- 超限时，“创建群聊”或“保存隐私设置”不可提交；提交处理函数仍需做相同保护，不能只依赖按钮状态。
- 倒计时为零且未超限时，继续显示必填提示，不显示上限提示。
- `99 小时 59 分钟` 是合法边界值。

### 正式数据转换

- 新提交统一转换成 `{ months: 0, days: 0, hours, minutes }`，继续兼容现有前端模型和正式适配器。
- 从正式 API 读取已有倒计时后，以“总小时 + 剩余分钟”回填两字段，不重新显示月或日。
- 若历史群聊已保存超过新上限的值，仍允许读取和显示聊天；编辑器以超限状态显示该值，并要求群主改到合法范围后才能再次保存隐私设置。
- 消息实际过期时间继续由正式后端的秒数和服务器时间决定，前端只负责编辑与展示。

## 后端契约

- 创建群聊和更新群聊隐私设置共用的 Zod 字段将 `disappearingTtlSeconds` 限制为 `60–359940`。
- OpenAPI 的创建、更新和会话数据说明同步记录最大值，避免文档与运行时校验漂移。
- 超限请求返回现有统一参数校验错误，不进入 Service 或 Repository。
- 不新增数据库字段或 migration；已有秒数字段足以表达该范围。
- 单聊继续禁止使用隐私消失倒计时，本次不改变其产品边界。

## 文案与可访问性

- 中文界面的错误文案必须精确为“时间上限最大为99小时59分钟”。
- 新增文案通过现有 i18n 体系补齐项目支持的语言，不新增页面内孤立硬编码。
- 错误提示使用可被辅助技术识别的 alert 语义，并与对应输入区保持视觉邻近。

## 测试与验收

### 前端自动化

- 倒计时字段定义只包含小时和分钟。
- `99:59` 合法，`100:00` 和 `00:60` 都返回超限状态。
- 超限输入不会被静默改写。
- 合法输入转换成月份、日期为零的现有倒计时对象。
- 新建群聊和已有群聊信息页都显示相同错误，并在超限时阻止提交。
- `00:00` 仍触发必填校验。

### 后端自动化

- `359940` 秒通过创建和更新校验。
- `359941` 秒在 Controller 之前被拒绝。
- OpenAPI 声明与 Zod 最大值一致。
- 现有群聊隐私模式、按发送时间、全员看过后及消息过期测试继续通过。

### 移动端浏览器验收

在正式本地 API 与真实测试账号环境中分别检查“发起群聊”和已有群聊信息页：

1. 开启隐私模式后只出现小时和分钟。
2. 输入 `99` 小时、`59` 分钟，可以创建或保存。
3. 输入 `100` 小时，出现精确上限提示且不能提交。
4. 输入 `60` 分钟，出现相同提示且不能提交。
5. 改回合法值后错误消失，可正常提交。
6. 刷新或重新进入群聊后，正式保存值仍正确显示。
7. 检查移动端无横向溢出、遮挡和控制台错误。

## 非目标

- 不改变隐私模式的两种倒计时起点。
- 不改变已发送消息的服务器权威过期与清理流程。
- 不新增 mock、平行隐私页面或客户端假保存。
- 不重构通用日期时长模型或其他业务中的月、日输入。
- 不合并、推送、部署或修改无关的 IM 工作。
