# IM 语音录制浮层设计

## 目标

让用户端、技师端和商户端共用的正式聊天页面支持可用、可试听、可取消的语音消息录制与发送。用户点击输入栏左侧语音按钮后立即进入录音浮层；录音最长 59 秒，停止后自动试听，确认后才发送。

本微步骤同时修复当前正式发送链路：现有前端会把完整录音 data URL 放进消息正文，而正式消息正文最多 4000 个字符，实际录音很容易在 API 校验阶段失败。新的链路必须先安全保存音频文件，再创建只引用规范媒体 URL 的正式消息。

## 范围

- 重做聊天输入栏语音按钮的启动行为。
- 新增覆盖当前会话的录音与试听浮层。
- 将录音上限从 60 秒统一为 59 秒。
- 新增正式语音文件上传与消息创建链路。
- 保留当前 Conversation、Message、SSE、未读数、拉黑和好友消息门禁。
- 用户端、技师端和商户端复用同一套组件和行为。
- 所有新增用户可见文案补齐现有五语言 i18n。

## 非目标

- 不提供语音转文字。
- 不保留参考图中的底部半圆手势区。
- 不使用长按、松开发送或上滑取消。
- 不新增语音通话、视频通话、降噪、变声、倍速、波形编辑或裁剪。
- 不新增 mock、浏览器业务持久化、轮询、数据表或 migration。
- 不改聊天消息列表、聊天背景素材或其他消息类型的视觉结构。

## 已选方案

采用全屏模态录音浮层。底部抽屉和输入栏原地展开虽然改动较小，但不能同时满足“背景与消息模糊”“录制气泡成为视觉中心”和“停止后明确试听确认”三个要求。

浮层挂载在当前会话页面内，不发生路由跳转。聊天内容仍留在原位置，关闭浮层后用户继续停留在同一会话和滚动位置。

## 视觉设计

### 背景

- 浮层覆盖当前会话可视区域，包括消息、顶部栏和输入栏。
- 背景同时使用半透明深色遮罩与 `backdrop-filter: blur(...)`，让文字和头像不可清晰阅读，但仍能辨认当前处于聊天上下文。
- 日间和夜间主题沿用现有 `--client-*` token 调整遮罩强度；不新增一套独立品牌主题。
- 浮层位于消息操作菜单、返回最新消息按钮和输入栏之上。

### 录音气泡

- 气泡位于屏幕上半部居中位置，使用参考图的明亮绿色主色和大圆角矩形。
- 气泡底部保留一个短小居中尖角，形成“正在说话”的提示语义。
- 录音阶段显示动态倒计时，例如 `59″ 后将停止录音`、`6″ 后将停止录音`。
- 倒计时按真实剩余时间更新，不显示 `60`，也不超过 59 秒。
- 获取麦克风权限期间，气泡显示“正在连接麦克风”，避免页面看似无响应。

### 录音阶段按钮

- 左侧圆形 `×`：立即取消本次录音、停止媒体轨道并关闭浮层。
- 中央圆形停止按钮：使用清晰的实心方块图标；点击后停止录音并进入试听状态。
- 录音阶段不显示发送按钮，避免未试听即误发。

### 试听阶段按钮

- 停止录音或录满 59 秒后，立即自动播放本次录音一次。
- 气泡显示录音总时长和当前播放进度；不再显示倒计时。
- 底部固定显示三个圆形按钮：
  - `×`：删除本次录音并关闭浮层。
  - 重放：从头播放；播放中再次点击仍从头开始。
  - 纸飞机：上传并发送本次录音。
- 发送期间纸飞机进入忙碌状态，三个按钮禁止重复操作。
- 发送失败时保留录音与试听能力，显示明确错误，不强制用户重新录制。

## 交互状态机

```text
idle
  -> acquiring_permission
  -> recording
  -> preview_playing
  -> preview_paused
  -> sending
  -> sent -> idle

acquiring_permission | recording | preview_* -> cancelled -> idle
acquiring_permission | recording -> error -> idle
sending -> send_error -> preview_paused
```

### 启动

1. 用户点击语音按钮。
2. 关闭表情和更多功能面板。
3. 打开模态浮层并请求 `getUserMedia({ audio: true })`。
4. 权限成功后创建 `MediaRecorder` 并立即开始录音。
5. 权限请求期间若用户取消，权限返回后必须立即停止新获得的轨道，不得后台继续录音。

### 停止与 59 秒上限

- 用户点击停止按钮时调用一次 `MediaRecorder.stop()`。
- 录音达到 59 秒时执行相同的停止路径，不自动发送。
- 计时以开始时间计算实际经过时长，250ms UI 刷新不能成为录音上限的事实来源。
- `onstop` 收齐音频分片后生成本地 `Blob` 和临时 object URL，进入试听并自动播放一次。
- 无有效音频数据时进入错误状态并关闭录音轨道，不创建消息。

### 试听

- 浮层持有一个受控 `<audio>` 元素。
- 自动播放若被浏览器策略阻止，仍进入可试听状态，并提示用户点击重放；不得丢失录音。
- 重放会把 `currentTime` 设为 0 后播放。
- 关闭、发送成功、路由离开或组件卸载时暂停播放器并回收 object URL。

### 发送

1. 前端把录音 `Blob` 作为原始请求体提交给受保护的语音消息接口。
2. 服务端验证会话权限、好友/业务会话发送资格、MIME 与文件魔数、59 秒时长和文件大小。
3. 服务端以不可猜测文件名保存音频，并使用既有正式消息服务创建 `needoMessageType=voice` 消息。
4. 消息正文只保存可搜索、可访问的短回退文本“语音”，metadata 保存规范 URL、MIME、文件大小、文件名和 1–59 秒整数时长。
5. 消息创建失败时补偿删除刚写入的音频文件；不会留下已报告成功但没有消息引用的文件。
6. 消息落库后沿用既有 `message.created` SSE、会话摘要和未读数更新。
7. 前端只有收到持久化 Message 成功响应后才关闭浮层并插入权威气泡。

## 正式 API 与存储

新增一个原子语音消息端点：

```text
POST /api/v1/im/conversations/:conversationId/voice?fileName=<name>&durationSeconds=<1..59>
Content-Type: audio/webm | audio/mp4 | audio/ogg
Body: raw audio bytes
```

- Bearer 鉴权，权限使用既有 `message:create`。
- `conversationId`、`fileName`、`durationSeconds` 使用 Zod 校验。
- 原始请求体使用明确音频 Content-Type 白名单和有界大小，默认上限沿用 8 MiB。
- 存储层验证 WebM、MP4 或 Ogg 对应文件签名；扩展名由服务端根据验证后的 MIME 决定。
- 文件名使用 256-bit 随机值；客户端文件名仅作为经过 `basename` 与长度限制的下载名称。
- 正式环境媒体公开基址继续读取配置，不硬编码域名。
- 响应沿用统一成功信封，并返回创建完成的正式 Message。
- OpenAPI 必须记录请求 MIME、参数、权限、成功响应和错误响应。
- 不新增 MessageType 数据库枚举；继续使用当前 `TEXT + needoMessageType=voice` 兼容投影。

## 组件边界

### `ImVoiceRecordingOverlay`

只负责模态视觉、倒计时、按钮、播放器状态和无障碍语义。它通过 props 接收当前状态及取消、停止、重放、发送回调，不直接访问 Store 或 API。

### `useImVoiceRecording`

封装权限请求、`MediaRecorder` 生命周期、59 秒边界、Blob/object URL、自动播放、清理和状态转换。会话页面只负责把成功 Blob 交给正式 adapter。

### 正式 IM adapter

新增 `sendVoiceMessage(conversationId, blob, metadata)`，调用正式语音端点并把返回 Message 映射为统一 `ConversationMessage`。页面不得再把 data URL 作为消息正文发送。

### 后端分层

```text
Route -> Controller -> Voice Message Service -> Media Storage + Realtime Message Service -> Prisma
```

Controller 只读取已校验参数和原始字节；文件校验、会话授权、补偿删除、消息创建和审计归 Service/Repository 层。

## 错误处理

- 浏览器不支持录音：显示“当前设备不支持浏览器录音”，关闭浮层。
- 麦克风权限被拒绝：显示“请允许麦克风权限后重试”，停止所有轨道。
- 录音设备中断：取消本次录音并显示可重试提示。
- 空录音或无数据分片：不上传、不创建消息。
- 自动播放被阻止：保留试听页并引导点击重放。
- 文件格式、大小或时长无效：服务端拒绝，前端保留可重录入口。
- 会话不存在、已拉黑、非好友或无权限：沿用现有正式错误，不创建文件或消息。
- 上传或消息创建失败：试听页保留 Blob；用户可重放、重试发送或取消。
- 页面离开、身份切换或组件卸载：停止录制轨道、暂停播放、清理计时器和临时 URL。

## 无障碍与移动端要求

- 浮层使用 `role="dialog"`、`aria-modal="true"` 和明确名称。
- 打开后焦点进入录音浮层；关闭后焦点返回语音按钮。
- `×`、停止、重放和发送均有可本地化 `aria-label`，点击区域至少 44×44px。
- 键盘 `Escape` 等同取消；发送按钮可通过键盘激活。
- 倒计时使用克制的 live region，避免每 250ms 重复播报；仅整秒更新可见文本。
- 尊重 `prefers-reduced-motion`，模糊遮罩和气泡只做必要的淡入淡出。
- 适配安全区、窄屏和桌面最大宽度；按钮不会被 iPhone Home Indicator 遮挡。

## 测试策略

### 前端单元与组件测试

- 点击语音按钮直接进入权限请求与录音浮层，不再切换成“按住说话”。
- 浮层包含背景模糊、绿色录音气泡、取消和停止按钮，且没有转文字或半圆元素。
- 倒计时从 59 开始，达到 0 时只停止并进入试听，不自动发送。
- 手动停止收齐 Blob 后自动调用播放器一次。
- 试听态只显示 `× / 重放 / 发送`，重放从 0 开始。
- 发送失败保留 Blob 与试听态；成功后采用服务端 Message 并释放资源。
- 权限拒绝、组件卸载、路由离开和取消期间权限迟到均停止媒体轨道。
- `maxVoiceRecordingSeconds` 的默认值和页面值均固定为 59。

### 后端测试

- Route、Zod、RBAC 与 OpenAPI 合同。
- 三种允许的音频签名、错误 MIME、伪造扩展名、空文件和超过 8 MiB。
- `durationSeconds` 仅接受 1–59。
- 非成员、非好友、拉黑、无权限请求在文件写入前失败。
- 成功请求保存一个音频文件、创建一个正式 voice 消息并发布一次 SSE。
- 消息创建失败时删除刚写入的文件。
- 重复客户端点击由前端 pending gate 阻止；后端不把失败请求报告为成功。

### 浏览器验收

- 使用当前 5180 实际服务 worktree，确认页面加载的提交与测试代码一致。
- 在手机视口验证点击启动、权限提示、背景模糊、59 秒倒计时、手动停止、自动重放、重放、取消和发送。
- 双正式账号验证发送方气泡、接收方 SSE 即时到达、双方播放、刷新后仍可播放。
- 验证控制台无错误、页面无水平溢出、录音结束后麦克风指示消失、取消后不产生消息或媒体文件。
- 分别检查白天与夜间主题，以及用户、技师、商户三端共享入口。

## 验收标准

- 点击语音按钮后立即出现模糊录音浮层并开始录音。
- 录音气泡以整秒显示剩余时间，最大 59 秒。
- 用户可随时取消或停止；录满 59 秒只停止，不自动发送。
- 停止后自动重放一次，并显示 `× / 重放 / 纸飞机发送`。
- 没有转文字按钮、长按提示、上滑取消或底部半圆。
- 发送使用正式音频文件 URL，不再发送 data URL 正文。
- 发送成功后双方通过正式历史和 SSE 读取同一语音消息，刷新后仍可播放。
- 所有失败路径不伪造成功，不泄漏媒体轨道，不丢失可重试录音。
- 定向测试、类型检查、生产构建和真实浏览器验收通过。
