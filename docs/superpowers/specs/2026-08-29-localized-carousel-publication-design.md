# NeeDo 五语言内容发布与双场景轮播正式设计

## 1. 状态与目标

本设计于 2026-08-29 经用户逐段确认。目标是建立一套可复用、可审计、可版本化的五语言内容发布基础，并先落地两个互相隔离但共用同一前端轮播插件的正式场景：

1. 用户端首页轮播图，由运营后台维护，轮播项跳转到真实店铺、技师或服务。
2. 联盟营销首页带图公告轮播，由联盟营销运营入口单独维护，轮播项打开正式公告详情，并可选跳转到真实联盟营销任务。

本设计同时定义店铺、技师、服务、联盟人物、联盟组织、联盟任务、官方公告和规则后续接入五语言发布能力时必须遵守的共同边界。

本设计不是展示页方案。所有正式状态来自 `/api/v1`、MySQL、MediaAsset、RBAC 和 AuditLog；禁止使用浏览器 `localStorage`、静态数组、mock API 或前端写死内容作为正式数据源。

## 2. 当前问题与现有基础

### 2.1 当前问题

现有 `FeatureCarousel` 已是可复用轮播组件，但 `homeCarouselStore` 仍保存浏览器本地场景状态，正式默认场景为空，且空数组会让轮播组件直接不渲染。运营后台 `CarouselPage` 尚未形成正式数据库内容管理闭环，所以用户端首页轮播无法由运营后台真实维护。

联盟营销首页也缺少独立的正式带图公告场景。两个场景不能共用一份内容，否则用户首页广告/推荐与联盟营销公告会互相覆盖。

### 2.2 继续复用的基础

- React、TypeScript、Vite 和现有用户端、联盟营销端、运营后台入口。
- `FeatureCarousel` 的滑动、自动轮播、指示器和移动端布局能力。
- 正式 `MediaAsset`、Shop、TechnicianProfile、Service、AffiliateTask、AffiliateProfile、AffiliateAlliance、User、RBAC 和 AuditLog。
- 现有 Affiliate 身份、联盟组织、任务、钱包、账本和 `needoId` 规则。
- 前端语言代码 `zh / zh-Hant / en / ja / ko` 和现有 i18n Provider。

### 2.3 必须被替换的旧边界

- `homeCarouselStore` 的浏览器持久化不能继续作为正式轮播权威。
- 旧 `home` 场景不从浏览器缓存导入正式数据库。
- 正式页面不能在 API 失败时读取本地旧轮播作为降级数据。
- 现有真实 MediaAsset 如有明确数据库归属，可以在受控迁移中引用；无法证明来源和归属的演示图片不能作为生产轮播种子。

## 3. 范围

### 3.1 第一实施微步骤

第一实施微步骤只包含：

- 统一内容语言代码、五语言初始化规则、完整性校验和版本并发基础。
- 正式公告及其五语言版本，满足联盟营销公告轮播的详情目标。
- `USER_HOME` 用户端首页轮播场景。
- `AFFILIATE_HOME_NOTICE` 联盟营销带图公告轮播场景。
- 两个独立运营后台入口和一个共享轮播编辑器。
- 正式读取、草稿、预览、立即发布、定时发布、停用、回滚、RBAC、审计和浏览器验收。

第一微步骤不得同时迁移店铺、技师、服务、联盟人物、联盟组织、联盟任务和全部规则表。

### 3.2 后续逐域接入五语言的内容

以下内容必须在后续独立微步骤中接入同一发布规范：

- 官方公告、轮播文字、利用规约、规则、说明和其他官方重要内容。
- 店铺/商户/技师发布的预约相关内容。
- 店铺的首页、环境、菜单、情报、地图说明和服务相关内容。
- 技师公开介绍、预约说明和服务介绍。
- 联盟营销任务的名称、简介、注意事项、参加说明和其他展示文字。
- 联盟营销公开人物资料，包括公开别名、人物标题、简介、擅长领域、合作说明、案例说明和展示标签。
- 联盟组织的公开名称、介绍、合作方向和展示信息。

### 3.3 明确不进入五语言内容版本的内容

- NeeDo 动态及其回复、转发和引用。
- 聊天内容。
- Request 内容。
- 用户 ID、身份 ID、订单号、任务状态、金额、日期和其他结构化事实。
- eKYC、银行账户、实名资料、账户名义和其他敏感风控资料。
- 外部社交主页 URL、外部平台账号标识和未经 NeeDo 验证的外部指标。
- NeeDo 可验证指标，例如完成订单、收益、评分、转化、粉丝或触达数据的正式统计值。

## 4. 语言与内容规则

### 4.1 正式语言集合

API 和数据库内容层统一使用以下 BCP 47 代码：

| 内容语言 | API/数据库代码 | 前端现有代码 |
|---|---|---|
| 简体中文 | `zh-CN` | `zh` |
| 繁体中文 | `zh-TW` | `zh-Hant` |
| 英文 | `en` | `en` |
| 日文 | `ja` | `ja` |
| 韩语 | `ko` | `ko` |

前端通过一个集中映射完成 `zh -> zh-CN` 和 `zh-Hant -> zh-TW`，业务组件不得自行散落语言转换判断。

### 4.2 首次填写自动复制

新建可翻译内容时，客户端提交 `sourceLocale` 和该语言内容。后端在同一事务内创建五条语言记录并复制相同值，同时记录初始来源语言。

该规则只在当前内容版本尚无任何语言记录时执行。五条记录创建后：

- 修改某个语言只更新该语言。
- 不自动反向覆盖其他四个语言。
- 编辑器可提供“以当前语言覆盖其他语言”的显式操作，但必须二次确认并携带版本号。
- 自动复制是初始填充行为，不代表系统自动翻译，也不能标记为人工翻译完成。

### 4.3 五语言发布完整性

正式发布前必须存在五条语言记录。每个业务域定义自己的必填字段；轮播至少要求标题和图片替代文字，公告至少要求标题和正文。

发布接口在事务中重新校验五种语言、媒体资源、关联目标、可见时间和版本号。任何一种语言或关联目标不合格时，整个版本不发布。

### 4.4 读取规则

正式前台只读取当前选择语言的已发布内容，不在读取时临时回退到其他语言。首次复制和发布完整性保证五种语言均有可显示内容，避免语言切换后出现混杂文字。

API 响应可以返回 `locale` 和 `releaseVersion`，但不向普通前台返回其他语言草稿或未发布内容。

### 4.5 人物、联盟和结构化事实

联盟营销人物可维护五语言公开别名、标题、简介、优势、合作说明、案例说明和展示标签。用户真实账号昵称、不可变 `needoId` 和实名资料仍来自统一账号系统，不能创建五份互相冲突的真实身份。

联盟公开名称和介绍可以分语言设置；联盟 ID、负责人、成员关系、分成比例、钱包和权限不做语言副本。

任务名称和说明按语言版本管理；预算、佣金单价、剩余比例、起止时间、领取条件的结构化值保持单一业务事实，由前端按语言格式化。

## 5. 总体架构

### 5.1 共用能力与业务隔离

共用部分：

- `ContentLocale` 语言契约。
- 首次复制、五语言完整性、乐观并发和版本发布服务。
- `CarouselPlugin` 前台轮播组件。
- `CarouselEditor` 运营后台编辑器。
- MediaAsset 选择、移动端预览、排序、语言页签和状态组件。

隔离部分：

- 场景数据、草稿、发布版本、权限、后台入口和审计动作。
- 用户首页轮播不能读取联盟营销公告内容。
- 联盟营销公告轮播不能被用户首页入口修改。
- 一个场景发布、停用或回滚不得改变另一个场景的当前版本。

### 5.2 不采用通用多态翻译表

正式数据库不使用只有 `entityType + entityId`、无法建立外键的万能翻译表。各业务域使用自己的翻译表和版本表，以保留数据库外键、唯一约束、软删除和查询索引。

复用发生在 Service 规则、Zod schema 组合器、API 响应契约和前端编辑组件层，不以牺牲关系完整性换取表数量减少。

### 5.3 分层

后端继续遵守：

```text
Route
  -> Controller
  -> Service
  -> Repository
  -> Prisma / MySQL
```

Controller 只处理请求和统一响应；发布状态机、事务、目标验证和审计由 Service 完成；Repository 只负责数据访问。

## 6. 双场景轮播

### 6.1 场景定义

| 场景 | 正式代码 | 内容用途 | 必须目标 |
|---|---|---|---|
| 用户端首页 | `USER_HOME` | 用户首页推荐/入口轮播 | 店铺、技师或服务三选一 |
| 联盟营销首页 | `AFFILIATE_HOME_NOTICE` | 带图正式公告 | 公告必选，联盟任务可选 |

共享组件只接受已由 API 裁剪为当前语言的 slide DTO，不自行读取场景 Store 或浏览器存储。

### 6.2 前台位置

用户端首页保留现有移动端轮播位置：顶部用户/区域/搜索区域之后、快捷入口之前或当前正式首页已有轮播插槽。页面布局调整时仍保持它处于首页头部内容区，不移动到精选推荐卡片内部。

联盟营销首页将相同轮播插件放在头像、等级、NeeDo ID、身份、收入、可提现金额和搜索栏组成的头部之后，当前任务概要之前。该场景显示带图公告，不作为商业广告位。

两个场景可以使用同一尺寸和交互组件，但样式允许通过场景主题参数适配各自页面；不能复制两份轮播行为代码。

### 6.3 用户首页目标

每个 `USER_HOME` slide 必须且只能绑定以下一个真实目标：

- 已发布且未软删除的 Shop。
- 已公开且有效的 TechnicianProfile。
- 已发布且未软删除、当前可访问的 Service。

发布时验证目标；读取时再次过滤已失效目标。API 返回业务安全的公开标识和路由 DTO，不向前端暴露内部数字主键作为可编辑地址。

### 6.4 联盟营销公告目标

每个 `AFFILIATE_HOME_NOTICE` slide 必须绑定一个正式公告。点击 slide 先进入当前语言的公告详情。

公告可以再绑定一个 AffiliateTask：

- 公告详情显示“查看任务”入口。
- 任务必须处于当前用户有权查看的正式状态。
- 联盟专属任务继续执行原有联盟可见性规则。
- 未发布、暂停、结束或无权访问的任务不泄漏详情；公告仍可正常阅读，但任务入口按正式状态隐藏或显示不可用说明。

未发布、停用或已过可见期的公告旧链接返回稳定的不可用结果，不返回草稿正文。

### 6.5 空、加载和失败状态

- 加载时保留轮播区域骨架，避免首页跳动。
- API 失败时在轮播区域显示当前语言的重试状态，不能触发全页错误边界。
- 正式返回“没有当前有效 slide”时不生成假内容；页面按场景显示经过设计的空状态或收起该插槽。
- 空状态与 API 失败必须可区分，运营后台显示无已发布版本的原因。

## 7. 数据模型

### 7.1 语言枚举

新增正式 `ContentLocale`，数据库值与 API 映射固定为五种语言。后端集中完成枚举和 BCP 47 字符串转换。

### 7.2 CarouselRelease

`CarouselRelease` 表示一个场景的完整发布版本，而不是单个 slide 的可变容器。至少包含：

- `id`。
- `scene`：`USER_HOME / AFFILIATE_HOME_NOTICE`。
- `version`：同场景单调递增。
- `status`：`DRAFT / SCHEDULED / PUBLISHED / DISABLED / ARCHIVED`。
- `lockVersion`：乐观并发。
- `publishAt / activatedAt / disabledAt / archivedAt`。
- `createdById / publishedById / disabledById`。
- `sourceReleaseId`：克隆或回滚来源。
- `createdAt / updatedAt / deletedAt`。

约束：

- `(scene, version)` 唯一。
- 每个场景最多一个当前 `PUBLISHED` 版本。
- 每个场景只能有受控数量的未完成草稿，第一微步骤默认一个当前编辑草稿。
- 所有列表过滤软删除。

### 7.3 CarouselSlide

`CarouselSlide` 属于一个 Release，至少包含：

- `id / releaseId / mediaAssetId / sortOrder / isEnabled`。
- `visibleFrom / visibleUntil`，UTC，可空表示跟随 Release。
- `targetType`。
- 可空且有外键的 `shopId / technicianProfileId / serviceId / announcementId / affiliateTaskId`。
- `createdAt / updatedAt / deletedAt`。

Service 根据场景强制目标组合：

- `USER_HOME`：Shop、TechnicianProfile、Service 恰好一个，其余为空。
- `AFFILIATE_HOME_NOTICE`：Announcement 必填，AffiliateTask 可选，其余为空。

数据库为所有关联字段、`releaseId + sortOrder`、可见时间和软删除字段建索引。

### 7.4 CarouselSlideTranslation

至少包含：

- `id / slideId / locale`。
- `badge / title / caption / ctaLabel / imageAltText`。
- `sourceLocale / isInitialCopy`。
- `createdAt / updatedAt / deletedAt`。

`(slideId, locale)` 唯一。标题和图片替代文字是发布必填项；其余字段允许按场景为空。

### 7.5 OfficialAnnouncement

公告稳定主体与发布内容版本分离：

- `OfficialAnnouncement`：稳定 ID、公告类型、联盟营销可见范围、可选任务关联和软删除。
- `OfficialAnnouncementRelease`：单调版本、草稿/定时/已发布/停用/归档状态、可见时间、操作者和并发版本。
- `OfficialAnnouncementTranslation`：release + locale 唯一，保存标题、摘要、正文和必要的无障碍文字。

公告发布和回滚规则与轮播一致，但公告版本独立于轮播版本。轮播引用稳定 Announcement；前台只解析该公告当前有效的已发布 Release。

### 7.6 后续业务翻译表

后续微步骤分别增加：

- `AffiliateProfileTranslation`。
- `AffiliateAllianceTranslation`。
- `AffiliateTaskTranslation` 或任务版本对应翻译表。
- Shop、TechnicianProfile、Service 及店铺首页各模块对应的版本/翻译表。
- 官方规则、规约和说明对应的正式版本/翻译表。

第一微步骤不预建这些尚未接线的空表。每个业务域接入时通过独立 migration、API、兼容读取和浏览器验收完成。

## 8. 发布状态机

### 8.1 草稿

- 新建草稿可从空版本开始，也可克隆当前已发布版本。
- 空版本首次保存一个语言时，后端自动生成五语言记录。
- 草稿允许暂时缺字段，但后台必须明确显示每种语言的完整度。
- 草稿保存使用 `expectedLockVersion`，冲突返回 409，不静默覆盖。

### 8.2 预览

- 预览通过运营后台受保护接口读取指定草稿。
- 预览可切换五种语言和移动端尺寸。
- 预览不产生公开 URL，不改变发布状态，不让普通用户访问草稿。

### 8.3 立即发布

发布事务必须：

1. 锁定场景和目标 Release。
2. 验证 RBAC、`expectedLockVersion` 和幂等键。
3. 验证五语言、MediaAsset、排序、可见时间和所有目标。
4. 把旧 Published 版本归档。
5. 把目标版本设为 Published，记录操作者和时间。
6. 写 AuditLog。
7. 提交后使读取缓存失效。

任何一步失败全部回滚，不能出现部分语言或部分 slide 生效。

### 8.4 定时发布

- 定时使用 UTC `publishAt`，后台按操作者当前时区显示。
- 幂等 Worker 在生效时间执行与立即发布相同的完整校验和原子切换。
- Worker 失败记录稳定原因并告警，旧已发布版本继续有效，不能先归档旧版本再失败。
- 同一场景的多个定时版本按明确规则拒绝时间冲突；第一微步骤只允许一个待生效版本。

### 8.5 停用

停用当前场景版本是受保护写操作。停用后普通读取不返回该版本；历史版本、审计和关联记录保留。单独移除或停用某个 slide 时，应从已发布版本克隆新草稿并发布，不能直接修改已发布行。

### 8.6 回滚

回滚不把旧行原地改回 Published。系统从选定历史版本克隆一个新的、版本号更高的 Release，再执行当前完整性和目标校验并原子发布。这样可以保留时间线和当时已失效目标的验证结果。

### 8.7 Slide 可见期

同一 Published Release 内，读取端按服务器 UTC 过滤 `isEnabled` 和 slide 可见期。发布校验要求 Release 在生效时至少有一个可能有效的 slide；全部 slide 后续自然到期时返回正式空状态，不回退到历史版本。

## 9. 运营后台体验

### 9.1 独立入口

运营后台提供两个独立入口：

1. `内容运营 -> 用户端首页轮播图`。
2. `联盟营销 -> 联盟营销公告轮播`。

两个入口使用同一编辑器代码，但传入固定场景，不能通过可篡改查询参数跨场景保存。

### 9.2 列表和编辑器

编辑器至少提供：

- 当前已发布版本、当前草稿和待定时版本状态。
- slide 新增、排序、启用状态和删除草稿项。
- 正式 MediaAsset 选择/上传结果及移动端预览。
- 五语言页签、逐语言完整度和未人工校对提示。
- 首次复制说明。
- 显式“复制当前语言到其他语言”操作和二次确认。
- 目标搜索与选择；只允许选择当前操作者权限范围内且正式有效的实体。
- 保存草稿、五语言预览、立即发布、定时发布、停用和历史回滚。
- 409 冲突后的重新读取与差异提示。

### 9.3 公告编辑

联盟营销公告入口可先创建或选择正式公告，再把公告加入轮播。公告正文编辑器与轮播短文案分别保存，但使用同一五语言页签和发布完整性组件。

公告发布与轮播发布是两个明确动作。轮播发布时公告必须已有覆盖轮播生效时段的正式版本；禁止让轮播先公开一个只能访问草稿的公告。

### 9.4 权限不足和失败

- 只读运营人员可以查看版本和预览，但看不到写按钮。
- 编辑权限不等于发布权限。
- 保存失败保留当前页面内尚未提交的输入，显示稳定错误；浏览器内存不是业务权威，刷新后仍以服务器草稿为准。
- 上传失败、目标失效、语言不完整、时间冲突和版本冲突分别显示可操作原因。

## 10. API 设计

### 10.1 前台读取

建议正式读取接口：

- `GET /api/v1/content/carousels/user-home?locale=zh-CN`。
- `GET /api/v1/affiliate/content/carousel?locale=zh-CN`。
- `GET /api/v1/affiliate/announcements/:announcementId?locale=zh-CN`。

所有接口使用正式会话和场景所需页面权限。用户首页接口只返回 `USER_HOME`；联盟接口只返回 `AFFILIATE_HOME_NOTICE`，后端不接受普通客户端任意指定内部 scene。

轮播响应至少包含：

- `scene / locale / releaseVersion / generatedAt`。
- 当前有效 slides。
- 每个 slide 的当前语言文案、MediaAsset 派生 URL、无障碍文字和经过权限裁剪的目标 DTO。

不返回其他语言、草稿、内部操作者、审计信息或可枚举的内部业务主键。

### 10.2 运营管理

建议正式管理接口：

- `GET /api/v1/backoffice/content/carousels/:scene`。
- `POST /api/v1/backoffice/content/carousels/:scene/releases`。
- `GET/PATCH /api/v1/backoffice/content/carousel-releases/:releaseId`。
- `GET /api/v1/backoffice/content/carousel-releases/:releaseId/preview`。
- `POST /api/v1/backoffice/content/carousel-releases/:releaseId/publish`。
- `POST /api/v1/backoffice/content/carousel-releases/:releaseId/schedule`。
- `POST /api/v1/backoffice/content/carousel-releases/:releaseId/disable`。
- `POST /api/v1/backoffice/content/carousel-releases/:releaseId/rollback`。
- `GET /api/v1/backoffice/content/carousels/:scene/history`，必须分页。

公告管理使用独立 `/api/v1/backoffice/affiliate/announcements` 域，包括分页列表、草稿版本、预览、发布、定时、停用和回滚。

所有写接口使用 Zod、OpenAPI、JWT、明确 permission、`expectedLockVersion` 和稳定幂等键。Controller 不直接访问 Prisma。

### 10.3 目标搜索

后台目标选择复用或新增受保护分页搜索接口，按场景返回允许的 Shop、TechnicianProfile、Service、Announcement 和 AffiliateTask。搜索结果必须经过当前状态、软删除、商户/平台范围和任务可见性校验。

发布 Service 仍需再次查询并验证目标，不能信任前端选择时的旧状态。

## 11. RBAC 与审计

### 11.1 权限拆分

至少拆分：

- 用户首页轮播读取、编辑和发布权限。
- 联盟营销公告读取、编辑和发布权限。
- 联盟营销公告轮播读取、编辑和发布权限。
- MediaAsset 使用/上传权限。

发布权限覆盖立即发布、定时发布、停用和回滚。只有编辑权限的用户不能改变公开状态。

### 11.2 服务端场景约束

Permission 只是第一层。Service 根据 route 固定场景并再次校验：

- 用户首页运营权限不能写联盟营销场景。
- 联盟营销运营权限不能写用户首页场景。
- 全局管理员也必须通过明确权限，不能依赖前端显示菜单。

### 11.3 审计动作

至少记录：

- 创建/克隆草稿。
- 编辑 slide、语言内容、排序、时间和目标。
- 显式跨语言复制。
- 创建/编辑公告版本。
- 立即发布、定时发布、定时失败、停用和回滚。
- MediaAsset 绑定变化。

审计包含操作者、场景、Release/Announcement ID、版本、前后状态、目标引用、原因、请求幂等键和时间；不记录 access token、银行资料或其他敏感字段。

## 12. 缓存、调度与一致性

- 前台可按 `scene + locale + releaseVersion` 做短 TTL 缓存。
- 发布、停用和回滚事务提交后使对应场景五语言缓存全部失效。
- 公告发布或停用使公告详情缓存和引用该公告的联盟营销轮播缓存失效。
- 缓存不是权威；缓存不可用时读取数据库，不回退浏览器本地数据。
- 定时发布 Worker 使用数据库锁、稳定任务键和有限重试；多实例只能有一个成功切换版本。
- 公共读取只返回事务提交完成的版本，不能观察到一半语言或一半 slides。

## 13. 错误处理

使用统一错误响应，不返回 Prisma 或数据库原始异常。至少覆盖：

- 场景不存在或 route/scene 不匹配。
- Release、公告或目标不存在、已软删除或状态无效。
- 五语言不完整或字段超限。
- MediaAsset 不存在、非图片、已失效或无使用权限。
- slide 时间、Release 发布时间或定时版本冲突。
- 无有效 slide。
- 乐观并发冲突。
- 重复发布或幂等键冲突。
- 权限不足。
- 公告未发布或无法覆盖轮播生效期。
- 联盟任务不可见、已暂停、结束或已失效。

API 失败由各轮播区域自行处理，不得使用户首页或联盟营销首页进入全局恢复页。

## 14. 旧数据与迁移策略

### 14.1 第一微步骤

- 新增 Carousel、Announcement、Translation、Release 和 RBAC migration。
- 已应用 migration 不修改。
- 不读取或迁移 `needo.carousel-scenes.*` 等浏览器 key。
- 前台接正式 API 后，移除对应正式路由对 `homeCarouselStore` 的读取；如动态页仍依赖旧 `timeline` 场景，保留其未扩大兼容边界，另开微步骤迁移。
- 没有真实已发布轮播时保持正式空状态，运营通过新后台发布真实内容。

### 14.2 后续领域迁移

每个业务域按以下顺序独立迁移：

1. 新增版本/翻译表和约束。
2. 把当前正式内容复制到五语言作为首个版本。
3. 增加正式 API 和编辑器。
4. 前台切换为按当前语言读取。
5. 验证刷新、重登和后端重启持久性。
6. 停止写旧单语言列；旧列先保留只读兼容。
7. 在后续独立清理步骤确认无读取后再移除旧列。

不能在同一个 migration 中把所有 Shop、Technician、Service、Affiliate 和官方内容一次性改完。

## 15. 后续内容域的特殊规则

### 15.1 店铺、技师和服务

- 店铺首页、环境、菜单、情报、地图文字和预约说明分别按模块版本化。
- 经纬度、营业时间、价格、库存、服务时长和结构化地址字段保持单一事实。
- 地图的交通说明、地标说明和到店指引可按语言设置。
- 技师真实账号、资质状态、评分和排班不是翻译内容。

### 15.2 联盟人物资料

- `AffiliateProfile` 当前结构化合作状态继续保留。
- `bio`、优势、服务区域展示文字等逐步迁移到 `AffiliateProfileTranslation`。
- 可增加五语言公开别名和人物标题，但不能覆盖 User.needoId、实名或统一账号昵称。
- 外部主页 URL 保持一份；自定义平台显示标签如需翻译，进入渠道翻译子表，而 URL 不复制。

### 15.3 联盟组织

- 联盟公开名称、简介和合作方向进入 `AffiliateAllianceTranslation`。
- 负责人、成员树、权限、比例、钱包和邀请保持当前正式结构，不被翻译迁移覆盖。

### 15.4 联盟任务

- 任务展示名称、描述、注意事项、参加说明和标签进入任务版本对应的五语言翻译。
- 预算、平台费率、奖励单价、日期、目标店铺/服务和 Claim 快照仍由正式任务版本统一管理。
- 任务提交审核和发布时，五语言作为同一任务版本原子生效；不能让不同语言指向不同预算或条件。

### 15.5 官方规则与规约

- 使用稳定文档主体、不可变发布版本和五语言正文。
- 草稿允许分语言逐步修改。
- 发布时五语言一次生效，并固化 Hash、发布人和时间。
- 合同接受继续固化用户实际接受的语言、版本和正文 Hash；不得只记录当前最新版本。

## 16. 测试要求

### 16.1 数据库与 Repository

- migration 可在全新库和现有本地正式库应用。
- 场景版本唯一、翻译唯一、目标外键和软删除过滤。
- 一个场景最多一个 Published、一个 Scheduled 的约束/事务行为。
- 目标组合和索引结构验证。

### 16.2 Service 和状态机

- 首次一种语言保存后原子生成五种语言。
- 后续修改单语言不覆盖其他语言。
- 显式复制到其他语言需要正确版本号。
- 缺任一语言、图片或有效目标时发布失败且旧版本不变。
- 立即发布、定时发布、停用、克隆回滚和重复幂等请求。
- 两个发布者并发发布同一场景只能一个成功。
- 定时 Worker 多实例并发只激活一次。
- rollback 生成新版本，不篡改历史行。
- 公告和可选任务的状态、时间和可见性验证。

### 16.3 API、RBAC 和审计

- Zod、OpenAPI、统一错误、场景固定、分页和 locale 校验。
- 只读、编辑、发布权限矩阵。
- 用户首页权限不能写联盟场景，反向亦然。
- 普通用户不能读取草稿或其他语言内容。
- 所有写操作生成完整 AuditLog。

### 16.4 前端

- 共享 CarouselPlugin 在两个场景正确渲染。
- 当前语言映射和切换后重新读取。
- 不同场景内容不会串场。
- 加载、正式空状态、API 错误重试和失效目标处理。
- 用户 slide 正确跳转店铺、技师和服务。
- 联盟 slide 打开公告详情，任务入口受可见性控制。
- 后台五语言页签、首次复制提示、完整度、预览、冲突和权限状态。
- 现有动态、聊天和 Request 不被五语言编辑器接管。

### 16.5 浏览器正式验收

使用正式账号、MySQL、Redis 和 `/api/v1` 完成：

1. 分别从两个运营后台入口创建真实草稿。
2. 上传/选择正式 MediaAsset，设置真实目标。
3. 验证首次填写复制五语言，再单独修改每一种语言。
4. 预览五语言和移动端尺寸。
5. 立即发布并在用户首页和联盟营销首页验证。
6. 验证用户轮播三种目标和联盟公告/任务跳转。
7. 验证定时发布、停用和历史回滚。
8. 验证无权限角色只能读取或完全不可访问。
9. 刷新、退出重登和重启后端后，内容、版本和审计仍存在。
10. 两端最终 console error/warning 为 0；轮播失败不触发全页恢复页。

测试通过不替代浏览器验收，浏览器页面可见也不替代数据库、RBAC、审计和重启持久性证明。

## 17. 完成定义

第一实施微步骤只有在以下全部满足时才算完成：

- 两个正式场景分别可由对应运营入口维护。
- 两个场景共用轮播插件但数据、权限和发布状态完全隔离。
- 五种语言首次复制、独立编辑和原子发布真实可用。
- 公告详情和用户首页目标均使用真实业务实体。
- 草稿、预览、立即/定时发布、停用和回滚可用且有审计。
- 不使用 mock、localStorage、静态演示数据或前端权限替代后端校验。
- migration、Service、Repository、API、OpenAPI、RBAC、前端测试、lint、正式 build 和浏览器验收全部通过。

后续店铺、技师、服务、联盟人物、联盟组织、联盟任务和规则内容只有在各自独立微步骤通过相同正式验收后，才能宣称已完成五语言接入。

## 18. 推荐后续微步骤顺序

1. 五语言发布底座、OfficialAnnouncement 与双场景轮播。
2. 官方公告中心、规则/规约的版本化编辑和合同 Hash 对齐。
3. 联盟营销人物资料与外部渠道显示标签多语言化。
4. 联盟组织公开名称和介绍多语言化。
5. 联盟任务展示内容多语言化并接任务审核/发布。
6. 店铺首页、环境、菜单、情报和地图文字多语言化。
7. 技师公开资料和预约说明多语言化。
8. Service 和预约相关发布内容多语言化。
9. 全域语言切换、权限、审计、迁移兼容和浏览器回归。

每次只执行一个微步骤。任何步骤未通过验收时不得提前进入下一步骤，也不得把仅有页面或静态文案的结果描述为前后端已打通。
