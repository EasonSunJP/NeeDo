# NeeDo 联系人 NeeDoID 与好友动态入口正式化设计

日期：2026-08-27  
阶段：Step 13 — IM / Social / Notification 后端化  
状态：用户已确认，待进入实施计划

## 1. 目标

本微步骤只修复联系人“信息设置”页的两个正式数据问题：

1. 页面必须显示账号不可变的 `needoId`，不得把数据库自增主键 `users.id` 当成好友 ID。
2. “标签”卡片正下方必须固定显示好友动态入口。入口只读取正式 Social API 和 MySQL 数据，不读取 IM mock、浏览器本地业务数据或展示占位数据。

当前本地数据库中的具体复现记录为：

- `users.id = 237`
- `users.needoId = n0000000237`
- `users.email = sim.customer.071@needo.local`
- `users.username = 柴田 陽菜`

因此截图中的 `ID 237` 是内部主键泄漏，正确显示值应为 `ID n0000000237`。

## 2. 已确认的产品规则

### 2.1 好友 ID

- `ImUser.id` 继续使用数据库用户主键的字符串形式，作为现有会话、联系人和消息关联键；不改变内部关系。
- `ImUser.userIdLabel` 必须使用正式 `User.needoId`。
- 搜索好友时允许按昵称或 NeeDoID 搜索，不再把内部自增主键作为用户可见账号标识。

### 2.2 动态时间与可见性范围

只有满足 `createdAt >= now - 30 × 24 小时` 的正式动态才计入“近期有动态”。置顶状态不扩大本入口的 30 天范围。

后端必须继续执行当前查看者可见性判断。`followers` 动态只有在当前查看者具备有效关注关系时才能计入，不能因为联系人页的入口而绕过 Social 隐私边界。

### 2.3 展示和跳转

动态入口卡固定放在“标签”卡片正下方，单聊好友信息页始终渲染，不再因好友未出现在 Social 全局首分页而整体消失。

状态规则：

- 最近 30 天内至少存在一条当前用户可见动态：显示“前往好友的动态页”。
- 最近 30 天内不存在当前用户可见动态：显示“好友近期无动态”。
- API 读取失败：显示“动态暂时无法加载”，不得伪装为无动态。

点击“前往好友的动态页”或“好友近期无动态”，统一跳转到该好友的完整动态页。

## 3. 正式数据设计

### 3.1 IM 身份契约

正式 IM API 的参与者与联系人对象补齐：

```text
userId       数据库内部用户主键，只用于关系和路由
needoId      不可变 NeeDoID，供展示与搜索
username     当前可编辑显示名称
avatarUrl    正式头像 URL
```

`GET /api/v1/im/contacts` 同时返回联系人账号的上述正式资料，前端不得再在缺少会话参与者时构造“用户 237”之类的占位账号。

### 3.2 好友近期动态状态接口

新增一个受认证的固定规则状态接口：

```text
GET /api/v1/social/users/:userId/activity-status
```

接口职责：

1. 验证目标用户存在且未软删除。
2. 使用当前认证用户执行动态可见性过滤。
3. 使用 `findFirst`/`EXISTS` 只判断最近 30 天是否至少存在一条可见动态，不读取媒体 JSON 或完整动态列表。
4. 返回目标好友的 Social profile ref，保证三端能跳转到正确的好友动态页。
5. 明确区分 `recent_posts` 与 `no_recent_posts` 状态。

查询使用 `authorUserId + deletedAt + createdAt` 组合索引，只在打开单个好友信息页时调用一次；不在通讯录列表中批量预取。该接口不替代已有分页动态列表接口，好友完整动态页继续使用正式分页 Social API。

## 4. 前端设计

保留现有 NeeDo 深色主题、圆角、间距和 `ImContactMomentsEntry` 视觉语言，不复制微信页面，也不新增第二套联系人页面。

前端调整：

- `ContactSummaryCard` 仍显示好友头像、显示名称和 `ID {needoId}`。
- 标签卡保持现有编辑能力。
- 动态入口卡移动到标签卡之后。
- 入口卡在进入单聊信息设置页时按目标 `userId` 单独请求，不能依赖 Social Provider 已加载的全局第一页。
- 加载期间保留稳定卡片高度，避免标签和消息设置区域跳动。
- 三端路由使用现有 `socialPaths.profile` 生成用户端、商户端和技师端各自的好友动态页地址。

## 5. 错误与边界

- 联系人数据缺少 `needoId` 时视为正式 API 契约错误；不得回退显示数据库主键。
- 目标好友被软删除或当前用户无权查看时，后端返回稳定错误，前端显示不可用状态。
- 状态接口不返回密码、邮箱、内部标签或其他非公开账号资料。
- 群聊信息页不显示单一好友动态入口，避免错误归属。
