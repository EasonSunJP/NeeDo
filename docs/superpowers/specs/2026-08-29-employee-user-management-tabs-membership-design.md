# 员工与用户管理插页、时间线、月历及会员授权设计

## 1. 背景与已确认方向

本轮继续完善 NeeDo 商户后台与运营后台的正式人员管理能力。用户已经确认采用插页式员工详细信息卡，并补充以下要求：

- 商户后台将“人员与顾客”拆分为独立的“员工管理”和“用户管理”。
- 所有面向运营人员和商户人员的“顾客”文案统一改为“用户”；数据库资源名和既有 API 中的 `customer` 可以保留，避免无业务价值的破坏性重命名。
- 员工详细信息卡不再把全部内容堆在一页，而是使用六个插页。
- 员工动态使用统一纵向时间线，并提供服务端分页及 10、30、50、100 条每页选项。
- 员工日程月视图与用户端正式日历保持一致：七列、每周一行、五至六行展示一个月。
- 用户详细信息卡使用统一插页和时间线；“身份与基础资料”改为“基础资料”。
- 会员等级独立成为一个插页。运营后台可以授予会员等级，并选择永久免费、免费若干天或免费若干个月。
- 用户资料与账号必须遵守 NeeDo 全局身份规则：一个全局账号、一个公开 NeeDoID、多个身份与业务资料扩展；界面不再暴露 CustomerProfile ID、User ID 等内部数据库编号。

参考截图只作为信息架构、插页导航、时间线与记录列表的设计参考，不复制其中的品牌、字段、数据或业务规则。

## 2. 总体架构

### 2.1 身份模型

界面主语统一为全局 NeeDo 账号：

```text
User / Account（全局账号，公开 NeeDoID）
  ├─ UserIdentity（用户、员工、商户、运营等身份）
  └─ CustomerProfile / TechnicianProfile（业务资料扩展）
```

详细信息卡顶部只展示公开 NeeDoID、账号状态、身份标签、会员等级、资料可见性等正式字段。内部 `userId`、`customerProfileId`、`technicianProfileId` 继续用于数据库关联、RBAC、审计和 API 路径，但不显示给业务操作人员。

### 2.2 插页组件

员工卡和用户卡共用同一套可访问插页组件：

- `role="tablist"`、`role="tab"`、`role="tabpanel"`。
- 支持左右方向键、Home、End。
- 当前插页使用 NeeDo 管理后台蓝色强调色、清晰边线与轻量阴影。
- 桌面端横向排列；窄屏横向滚动，不压缩文字。
- 所有插页面板保持挂载，仅隐藏非当前面板，确保编辑草稿在切换插页后仍保留。
- 身份摘要位于插页上方，不随插页重复。

## 3. 员工详细信息卡

### 3.1 六个插页

1. `基础资料`
   - 姓名、城市、服务区域、从业年限、个人简介。
   - 保留真实编辑模式及既有 PATCH 正式接口。
2. `从属与账号`
   - 专属技师／合作技师、在职状态、所属店铺、开始和结束日期。
   - 账号启停、验证状态、邮箱、手机号、NeeDoID。
3. `员工日程`
   - 复用正式日程投影 API 和现有共享日历。
   - 日、周、月视图继续可切换。
4. `薪酬与分成`
   - 计薪模式、基础工资、时薪、日薪、单次报酬、分成、最低保障和 NDP 分摊。
   - 保留正式编辑和单笔收入预估。
5. `结算记录`
   - 工资结算周期及法定节假日顺延规则。
   - 最近工资单正式统计、已付、未付及前往财务结算入口。
   - 商户后台不发起自动转账，财务人员仍在财务结算页手动登记支付。
6. `员工动态`
   - 共享纵向时间线、评论入口和正式审计事件。
   - 分页由 `/merchant-admin/employees/:needoId/timeline` 服务端完成。

### 3.2 员工动态分页

- 默认每页 10 条。
- 每页选项固定为 10、30、50、100。
- 显示总数、当前页、总页数、上一页和下一页。
- 改变每页数量时回到第 1 页。
- 新增评论后回到第 1 页并刷新，确保最新评论可见。
- 人工合成的“验证”和“加入店铺”历史事件只在不会破坏分页总数时显示；正式审计列表本身不允许通过客户端切片伪装成服务端分页。

### 3.3 月视图

`ScheduleCycleCalendarBoard` 的月视图改为复用 `UnifiedCalendarMonthGrid`：

- 固定七列星期头。
- `getMonthGridDates()` 产生 35 或 42 个日期格，按周自然换行。
- 非当前月日期降低透明度。
- 每格显示最多三条正式事件及溢出数量。
- 点击日期进入当天视图。
- 跨店铺预约继续只显示灰色锁定和“其他店铺已有确认安排”，不暴露店铺、用户、服务、订单或金额。
- 日视图和周视图保持现有行为。

## 4. 商户后台导航与用户管理

### 4.1 导航拆分

商户后台主导航拆成两个独立分区：

- `员工管理`
  - 员工列表
- `用户管理`
  - 用户列表
  - 评价中心

正式路由使用 `module=staff`、`module=users`、`module=reviews`。页面和空状态中的“客户”统一改为“用户”。后端 `/customers` 资源路径保留，因为它表达 CustomerProfile 领域模型，不作为用户可见文案。

### 4.2 用户详细信息卡插页

用户卡使用五个插页：

1. `基础资料`
   - 昵称／显示名称、邮箱、手机、城市、简介、资料可见性、创建和更新时间。
   - 标题不再出现“身份与基础资料”。
2. `会员等级`
   - 当前等级、授权方式、开始时间、到期时间和授权操作员。
   - 商户后台只读；运营后台在有 `backoffice:customers:write` 权限时可编辑。
3. `预约与消费`
   - 正式预约数量、状态汇总、完成消费、下次预约、近期预约和正式评价摘要。
4. `权限与账号`
   - NeeDoID、用户名、账号状态、最近登录、正式角色和身份。
5. `用户动态`
   - 与员工动态共用时间线卡片和分页控件；商户范围只返回本店可见审计事件，运营范围返回平台可见事件。

## 5. 会员等级授权

### 5.1 正式数据模型

在 `CustomerProfile` 增加以下正式字段：

```text
membershipGrantMode: SELF_SERVICE | OPERATOR_COMPLIMENTARY
membershipDurationUnit: FOREVER | DAY | MONTH | null
membershipDurationValue: Int | null
membershipStartsAt: DateTime | null
membershipExpiresAt: DateTime | null
membershipGrantedById: Int | null
```

现有记录默认 `SELF_SERVICE`，不推断付费状态，也不自动扣款。运营授予会员时使用 `OPERATOR_COMPLIMENTARY`：

- 永久免费：`FOREVER`，数量和到期时间为 `null`。
- 免费 N 天：`DAY`，到期时间按 UTC 开始时间加 N 个自然日计算。
- 免费 N 个月：`MONTH`，按日历月份计算；例如 1 月 31 日加 1 个月时取目标月最后有效日期。

### 5.2 正式接口

新增：

```text
PUT /api/v1/backoffice/customers/:id/membership
```

请求体：

```json
{
  "membershipLevel": "gold",
  "grantMode": "operator_complimentary",
  "durationUnit": "month",
  "durationValue": 3,
  "startsAt": "2026-08-29T00:00:00.000Z"
}
```

规则：

- `forever` 时 `durationValue` 必须为 `null`。
- `day`、`month` 时数量必须是 1–1200 的整数。
- 仅 `backoffice:customers:write` 可以调用。
- Service 计算到期时间，Repository 只执行 Prisma 写入。
- 每次授权写入 `backoffice.customer.membership.assign` 审计日志，记录等级、期限类型、期限数量、开始和到期时间，但不记录 token、密码或其他敏感数据。
- 普通资料 PATCH 不再承担会员授权逻辑，避免会员等级与基础资料混写。

## 6. 用户动态分页接口

新增：

```text
GET /api/v1/backoffice/customers/:id/timeline?page=1&pageSize=10
GET /api/v1/merchant-admin/customers/:id/timeline?page=1&pageSize=10
```

两者返回统一分页结构。`pageSize` 最大 100，列表按 `createdAt desc, id desc` 排序。商户接口必须先验证该用户与当前店铺存在正式预约关系，并继续应用店铺范围审计过滤；平台接口使用平台权限。读取时间线不产生新的审计记录，防止“查看行为”污染被查看的时间线。

## 7. 错误处理与状态

- 切换插页不触发重复保存。
- 分页请求使用既有详情请求协调器，忽略过期响应。
- 会员授权失败保留编辑草稿；成功后同时刷新用户详情、会员插页、时间线和列表。
- 401、403、404、409、5xx 使用正式错误翻译，不显示原生 Prisma 或 Node 异常。
- 会员到期时间由后端计算，前端只提交规则，不自行决定最终时间。

## 8. i18n 与视觉

- 所有新增用户可见文案补齐简体中文、繁体中文、日语、英语、韩语。
- 继续使用现有管理后台主题 token，不硬编码参考图的白色主题。
- 深色模式下保持蓝黑表面、蓝色当前插页、可读边线和 WCAG 可识别焦点。
- 不增加 mock、demo、placeholder 或本地存储业务数据。

## 9. 验收标准

- 员工卡默认只显示“基础资料”面板，六个插页可键盘和鼠标切换，编辑草稿不丢失。
- 员工动态能在 10、30、50、100 间切换并请求正式分页 API。
- 员工月历在桌面和窄屏均是一周一行，不再是一行 35／42 天。
- 商户顶栏分别出现“员工管理”和“用户管理”，用户页面不再出现“顾客”或“客户正式档案”。
- 用户卡不显示任何内部数字 ID，只显示公开 NeeDoID。
- 用户卡包含独立“会员等级”和“用户动态”插页。
- 运营可以授予永久免费、免费 N 天或免费 N 个月的会员等级；刷新后数据仍在。
- 商户只能查看会员授权状态，不能编辑。
- 会员修改出现在统一用户动态中。
- Prisma migration、Zod、OpenAPI、RBAC、审计、前后端测试、lint、build 和本地浏览器验收全部通过。
