# 运营数据大盘交互补全设计

日期：2026-09-06

## 目标

在不新增 mock、数据库、migration 或 API 的前提下，补全运营数据大盘的三类交互：顶部三日迷你折线节点详情、主趋势图说明入口、排行榜正式详情跳转。

## 范围

本微步骤仅修改运营后台 Dashboard 及其复用的正式详情页面参数接线：

1. 删除顶部指标卡迷你折线下方的水平基线。
2. 三日迷你折线的每个节点可通过鼠标或键盘打开卡内数据浮层。
3. 三张主趋势图的常驻说明文字移入标题右侧的圆形信息按钮。
4. 排行榜整行可通过鼠标或键盘进入相应正式详情页面，并自动打开既有详情抽屉。

不修改排行榜统计口径、Dashboard API、RBAC、数据库或订单数据。

## 交互设计

### 三日迷你折线

- 删除 SVG 中仅作装饰的水平基线。
- 保留三日折线路径和三个可见节点。
- 每个节点增加透明命中区域及按钮语义，支持点击、Enter 和 Space。
- 选中后在当前指标卡内显示浮层，内容为日期、格式化数值和指标单位。
- 点击其他节点直接切换浮层内容；关闭按钮或 Escape 清除选中状态。
- 指标数据变化时清除旧选中状态，避免显示失效日期或数值。
- 浮层不得遮挡卡片标题和详情入口，也不得造成横向溢出。

### 主趋势图说明

- 移除标题下方常驻的说明段落。
- 标题和圆形 `i` 信息按钮保持在同一标题行。
- 信息按钮复用现有 `TitleWithInfo` 组件及其悬停、点击、焦点与无障碍行为。
- 提示内容继续使用现有说明字符串，不改变翻译来源。
- 图例、双轴坐标、精确数据表和节点点击详情保持不变。

### 排行榜详情

- 每个排行榜条目整体变为可交互行，支持鼠标点击、Enter 和 Space，并提供清晰焦点样式。
- 保留行内排行、头像、名称、TEST 标签、公开 ID、GMV 和完成次数的现有视觉结构。
- 点击服务项目时进入正式服务数据页面并自动打开既有服务详情抽屉。
- 点击技师时进入正式技师管理页面并自动打开既有技师详情抽屉。
- 点击用户时进入正式用户管理页面并自动打开既有用户详情抽屉。
- 目标页面使用 URL 查询参数保存目标类型和正式实体 ID，因此刷新后仍可恢复详情。
- 目标不存在、被删除、无权限或请求失败时，继续使用目标页面现有的空态或错误状态；大盘不复制详情请求和权限判断。
- `service` 与 `technician_service` 必须按响应中的实体类型路由到能够读取该正式实体的既有详情数据链路，不把两类 ID 混用。

## 数据流

1. Dashboard 继续从现有运营 Analytics API 读取指标、三日序列和排行榜。
2. 迷你折线详情只使用当前卡片已取得的三点数据，不发起额外请求。
3. 主图说明只移动展示位置，不改变数据流。
4. 排行榜点击将响应中的 `entityType`、`entityNumericId` 和必要的公开 ID 编码进目标 URL。
5. 目标正式页面解析 URL，调用自身既有 API，并打开自身既有详情抽屉。

## 错误与权限

- 不为排行榜详情新增免鉴权或公共管理接口。
- 深链接仍受目标路由现有 RBAC 守卫保护。
- 无效、缺失或非正整数实体 ID 不自动打开抽屉，页面保持正常列表状态。
- 详情请求失败时保留目标页面现有重试或错误反馈，不回退到静态数据。

## 测试与验收

自动化测试先失败后实现，覆盖：

1. 迷你折线没有水平基线，存在三个可操作节点，节点选择、切换、关闭和键盘操作可用。
2. 指标卡向迷你折线传入格式化所需的标题和单位。
3. 主趋势图说明仅出现在标题旁的信息提示中，原常驻说明段落不存在。
4. 排行榜三类条目产生正确的详情动作，并保持 TEST 标签与排序切换行为。
5. 三个目标页面能解析有效深链接并自动打开既有详情抽屉；非法参数不触发读取。

实现完成后运行相关组件测试、完整前端测试、TypeScript lint 和 production build。浏览器验收使用当前登录的运营账号，逐项验证迷你折线节点、大图说明、三类排行榜详情、键盘操作、横向溢出与运行时错误。

## 非目标

- 不修改 Dashboard 或排行榜后端统计。
- 不增加新的详情弹窗或第二套详情组件。
- 不增加新 API、schema、migration 或测试数据。
- 不推送 GitHub，不部署 staging。
