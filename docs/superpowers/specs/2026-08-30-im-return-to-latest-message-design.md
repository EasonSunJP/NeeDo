# IM 回到最新消息按钮设计

日期：2026-08-30  
范围：用户端、技师端、商户端共用的正式 IM 会话页

## 目标

当用户向上浏览历史消息、最新一条消息离开聊天可视区域后，提供一个明确且紧凑的入口返回最新消息。该入口不能强制打断历史阅读，也不能与现有的“新消息数量”胶囊形成两套重复操作。

## 交互规则

1. 在消息列表末尾放置一个不可见的最新位置标记。
2. 最新位置标记处于聊天可视区域时，不显示返回按钮。
3. 最新位置标记离开聊天可视区域时，显示“回到最新消息”按钮。
4. 用户点击按钮后，消息列表平滑滚动到最底部；最新位置重新可见后按钮自动消失。
5. 用户停留在历史消息区域时收到新消息，不自动抢走当前位置；按钮继续显示。
6. 用户手动滚回底部时，按钮自动消失。
7. 消息操作菜单或媒体全屏预览开启时，暂时隐藏按钮，避免遮挡当前操作。
8. 会话切换或消息列表重置后重新计算可见状态，不能沿用上一会话的按钮状态。

## 视觉规则

- 使用与动态页“发布动态 +”按钮相同的圆形尺寸、玻璃质感、阴影、主题色和右侧悬浮位置。
- 图标使用单一向下箭头，方向与用户提供的参考图相反，表示返回更下面的最新内容。
- 不显示“新消息数量”文字胶囊，不增加第二个并存入口。
- 按钮有可访问名称“回到最新消息”，支持键盘焦点和点击操作。
- 按钮本身不支持拖动，避免与消息列表的滚动手势冲突；这里只复用动态页按钮的视觉和固定位置。

## 实现边界

- 只修改前端会话页的滚动状态、按钮渲染和相关样式/测试。
- 继续使用现有正式消息 Store、分页、SSE 和数据库数据，不新增 mock、接口、轮询或本地业务数据。
- 保留现有“用户发送消息时自动贴底”和“用户在底部时收到消息自动贴底”逻辑。
- 将当前仅在收到新消息后出现的“`N 条新消息`”胶囊替换为本设计的统一按钮。

## 状态与数据流

1. 会话页渲染消息列表以及列表末尾标记。
2. 浏览器以消息滚动容器为观察根节点，监听末尾标记是否可见。
3. 可见性变化只更新会话页本地 UI 状态，不写服务器或浏览器持久化。
4. 点击按钮调用现有消息滚动容器的平滑 `scrollTo`，并清理旧的新消息计数状态。
5. 新消息、媒体加载、输入栏高度变化后重新确认末尾标记状态，避免动态高度导致按钮状态错误。

## 降级与错误处理

- 浏览器不支持 `IntersectionObserver` 时，退回到现有的滚动距离计算；距离底部小于现有近底阈值时视为最新位置可见。
- 找不到消息滚动容器时不渲染按钮，不抛出页面运行错误。
- `prefers-reduced-motion: reduce` 时使用即时滚动，其他情况下使用平滑滚动。

## 验收标准

- 初次进入并停留在最新消息位置时没有按钮。
- 向上滚动到最新位置离开可视区域后出现圆形向下箭头。
- 按钮与动态页“发布动态 +”按钮位于同一右侧悬浮位置，且不会被输入栏遮挡。
- 点击后回到最底部并自动隐藏。
- 手动滚到底部同样自动隐藏。
- 查看历史时收到新消息不会被强制拉回底部，按钮保持可用。
- 消息菜单和媒体全屏预览期间不显示按钮。
- 窄屏、桌面和输入栏展开状态下无横向溢出或点击遮挡。
- 正式 IM 数据、分页、SSE、撤回、删除和快捷表情行为不受影响。
