# 店铺申请页重构设计

**日期：** 2026-09-06  
**范围：** 店铺身份申请第一步“服务展示”页面  
**目标：** 在不改变正式 API、数据库和审核流程的前提下，重构申请表单的信息层级、费用输入、eKYC 入口、上传控件和固定头尾布局。

## 1. 实施边界

- 仅重构店铺申请第一步及支撑它的共享 UI 小组件。
- 保留现有 `/api/v1/identity-applications/*` 草稿、媒体上传、银行校验、合同确认和提交链路。
- 保留正式服务种类及关键词库，不新增 mock、静态标签或假 eKYC 状态。
- 不修改数据库 schema，不新增 migration。
- 第二步“银行与身份”和第三步“收费规则与合同”的业务逻辑保持不变。
- 主页效果预览继续复用 `StoreDetailExperience`，不创建独立的简化预览。

## 2. 页面结构

第一步按以下顺序拆为七个独立容器，不再把全部字段放入一个大容器：

1. **名义**
   - 个人名义
   - 法人名义
2. **基础信息**
   - 申请人
   - 法人或代表者姓名
   - 法人或代表者姓名注音
   - 店铺名称
   - 店铺地址
   - 联系电话
3. **服务种类与关键词**
4. **费用区间**
5. **店铺简介**
6. **上传店铺第一张展示图**
7. **主页效果预览**

每个容器标题使用统一标题组件。解释性小字不直接显示在标题下方，而是放入标题右侧的圆形 `i` 说明入口。字段级校验错误仍可在相应控件附近显示，避免把错误信息隐藏在说明入口中。

## 3. 名义与基础信息

“申请人”复用现有 `responsiblePersonName` 正式字段，只改变页面文案和位置，不删除后端审核所需字段。它位于“法人或代表者姓名”之前。

申请人输入框与“本人确认（eKYC）”按钮同一行：

- 未验证时，按钮显示“本人确认（eKYC）”，进入正式 `/me/settings/verification` 页面。
- 已验证时，状态来自正式账户数据，按钮显示“已本人确认”。
- 不以点击、页面返回或本地状态伪造已验证结果。
- eKYC 不自动覆盖申请人输入内容；申请人仍需确认并提交自己的申请资料。

法人名义继续保留正式法人名称校验要求。页面上的“法人或代表者姓名/注音”同时作为本次申请展示的法人主体信息；提交适配层继续向现有正式字段发送完整数据，避免改变 API 契约。个人名义仍按现有规则在银行步骤校验 eKYC 姓名。

## 4. 服务种类与关键词

- 分类与关键词继续从正式 shop taxonomy API 加载。
- 未选择服务种类时，不加载或显示对应关键词库。
- 选择服务种类后，显示该种类的关键词组。
- 保留现有种类与关键词数量限制、取消种类时移除依赖关键词的行为。
- 分类按钮不再追加“需审核”“審査必要”“Review required”等审核提示；所有服务种类统一进入店铺申请审核。
- 说明文字迁入标题右侧圆形 `i`。

## 5. 费用区间

将单个“收费展示”文本框改成最低价与最高价两个日元金额输入。页面与主页预览统一格式化为：

```text
￥xxx,xxx ~ ￥xxx,xxx
```

行为规则：

- 只接受非负整数日元金额。
- 两端均为空时保持选填状态。
- 只填写一端时阻止进入下一步并提示补全区间。
- 最低价不得高于最高价。
- 使用千位分隔格式展示。
- 继续序列化到现有 `showcaseDraft.priceLabel`，并能从已有相同格式的草稿恢复，不改动 API 或数据库。

## 6. 店铺简介与展示图

- “店铺简介”继续写入现有 `showcaseDraft.description`，保持必填规则。
- 原生文件输入视觉入口替换为与当前 NeeDo UI 一致的圆角上传按钮。
- 上传按钮触发隐藏的原生文件选择器，仍仅接受现有正式链路支持的 JPEG、PNG。
- 选择后显示文件名；预览继续使用 object URL，并在变更或卸载时释放。
- 上传说明放在标题的圆形 `i` 中。

## 7. 主页效果预览

- 保持现有 `StoreDetailExperience` 预览及实时草稿映射。
- 费用区间、关键词、店铺名称、地址、简介和第一张展示图继续实时映射。
- 预览作为独立容器，标题为“主页效果预览”。
- 预览内部的固定页签或导航不得覆盖申请页头部。

## 8. 固定头部与底部操作

申请页头部沿用正式共享头部形态，并仅对本页提升层级，使其高于：

- 主页效果预览中的固定头部和页签；
- 页面内容；
- 悬浮的下一步按钮。

“下一步：银行与身份”使用固定底部操作容器：

- 水平宽度、左右间距和安全区与主页底部导航一致；
- 页面隐藏主页导航时，占用其原本的底部位置，而不是悬浮到导航上方；
- 正文增加足够的底部留白和滚动安全距离，最后一个预览容器不会被按钮遮挡；
- 加载、禁用和错误处理继续复用现有正式保存逻辑。

## 9. 多语言

新增或变更的用户可见文案覆盖简体中文、繁体中文、日文、英文和韩文。审核标记仅从注册选择器中移除，不改变后台审核规则和审核页面资料。

## 10. 测试与验收

按测试驱动方式实施：

1. 先新增失败测试，锁定七个独立容器、申请人顺序、正式 eKYC 入口、审核标记移除、费用区间格式与校验、自定义上传按钮、固定底部按钮和头部层级。
2. 实现最小改动使测试通过。
3. 运行 identity application、shop taxonomy、i18n 相关测试和前端 build。
4. 启动正式本地前后端前，确认监听端口、PID、cwd、分支和代理目标。
5. 在接近 iPhone 14 Pro Max 的移动视口验收：
   - 七个容器及标题顺序；
   - 圆形 `i` 说明；
   - 选择种类后出现关键词；
   - 费用区间格式；
   - 上传按钮和文件名；
   - 主页效果预览；
   - 固定头部与底部按钮无覆盖冲突；
   - 页面无水平溢出和控制台错误。

## 11. Git 交付

- 实现放在独立 `codex/` 功能分支或工作树中，避免夹带当前工作区的其他改动。
- 测试和浏览器验收通过后提交实现。
- 合并前确认 `main` 工作树无未提交改动，并将功能提交合并到本地 `main`。
- 本地合并、远端推送、部署和线上验收分别报告，不把其中一项当作其他项已经完成。
