# 正式预约确认页线上确定版 UI 恢复设计

日期：2026-09-02

## 目标

在不回退正式 API、真实预约提交和订单状态机的前提下，把用户端预约确认页恢复为历史线上确定版的视觉结构与滚动交互。视觉权威来源为提交 `a06b28bf` 中的 `src/pages/user/CheckoutPage.tsx`，正式数据权威来源为当前 `FormalCheckoutPage` 使用的服务详情、可预约时段和预约创建 API。

## 问题定义

当前正式页在去除旧 mock 流程时把确认页重写成了通用卡片：顶部六个确认项目变成圆角矩形，只有“套餐”常亮；正文的套餐、服务方式、时间、地址、技师、备注和注意事项也被明显简化。这与已确定并在线使用的页面不一致。

本次恢复必须同时解决：

- 顶部六个确认项目恢复为圆角向右箭头分段。
- 页面滚动时，位于页面中部的确认项目成为当前项目，当前项目及之前项目累计点亮。
- 点击任一箭头可平滑滚动到对应区块。
- 正文结构、层级、间距、卡片形态和固定底栏恢复为线上确定版。
- 所有内容继续使用正式 API 数据，不重新引入旧 mock、legacy store 或假数据。

## 采用方案

采用“保留正式数据层，移植确定版表现层”的方式：

1. 当前 `FormalCheckoutPage` 继续负责读取正式服务详情、正式可预约时段并创建正式预约。
2. 从历史确定版提取确认进度箭头、区块结构、视觉类名和滚动联动逻辑。
3. 在正式页面内部建立只读展示适配层，把正式返回值转换为确定版组件需要的展示字段。
4. 正式 API 未提供的业务字段不编造；对应元素隐藏、使用接口已有的通用描述，或呈现明确的不可用状态。

不采用以下方案：

- 只修顶部导航：正文仍会与线上确定版不一致。
- 整页回退历史代码：会恢复旧 mock 和 legacy 状态，破坏正式数据边界。

## 页面结构

页面保持一个固定顶部栏、六个正文区块和一个固定底部操作栏：

1. 套餐：大图、服务标签、服务名称、描述、含税价格、时长、区域和服务内容标签。
2. 服务方式：到店／上门选择；到店时显示门店和坐席信息，上门时显示上门说明。
3. 时间：日期、时间、人数、预约提示和汇总行。
4. 地址：地图预览、正式地址、门店／区域说明、Google 地图和复制地址操作。
5. 技师：头像、名称、区域、可约状态、综合评价、评价数、技能标签和系统接单率。
6. 备注：特殊需求输入框与常用提示标签。
7. 注意事项：业务注意事项、取消政策、NDP 说明。
8. 固定底栏：应付金额、正式支付方式、联系和确定预约。

## 顶部箭头与滚动状态

六个分段复用历史确定版的 SVG 路径，不使用普通圆角矩形或近似 CSS 多边形：

- 第一个分段有圆角左边和圆角右箭头尖端。
- 后续分段左侧为承接前一箭头的内凹口，右侧为圆角箭头尖端。
- 每个分段保留图标和文字，横向等分，不产生 390px 或 440px 宽度下的横向滚动。
- 未点亮状态使用深色表面；点亮状态使用品牌荧光绿，图标和文字切换为深色。

页面为六个正文区块保存引用。滚动或窗口尺寸变化时：

1. 读取固定进度条底部位置。
2. 在该位置与视口底部之间取中点作为确认阈值。
3. 按区块顺序查找顶部已经越过阈值的最后一个区块。
4. 将它设为当前步骤，并把索引小于等于当前步骤的箭头累计点亮。

该计算通过 `requestAnimationFrame` 初始化，并使用被动 scroll 监听；卸载时移除 scroll、resize 监听。点击箭头时调用对应区块的 `scrollIntoView`，备注箭头额外聚焦输入框。

## 正式数据映射

- 服务名称、封面、简介、标签、价格、时长和服务区域来自正式服务详情。
- 日期和时间来自正式 availability 接口；不可预约时段不得作为可选项显示。
- 门店名称、地址、服务区域和地图查询只使用正式服务／店铺信息。
- 技师头像、名称、评分、评价数、技能和接单率只在正式响应包含时展示；不以收藏数替代评价数，也不生成假年龄或假接单率。
- 支付方式来自正式服务或预约上下文；含税展示口径沿用当前正式价格字段。
- 确定预约继续调用当前正式创建预约接口，并保留现有登录、错误和余额不足处理。

如果当前接口缺少确定版某个字段，本次优先采用结构兼容的缺省展示或隐藏该行，不扩大数据库 schema，也不新增 mock 数据。

## 状态与错误处理

- 加载状态保持正式页现有骨架／等待反馈，避免先渲染假服务。
- 服务不存在、无权限或请求失败时沿用正式错误处理，不进入可提交状态。
- 没有可预约时段时禁用确定预约，并给出正式接口对应的不可预约提示。
- 创建预约期间按钮防重复提交；失败时保留用户已选内容。
- 外部地图和复制地址操作不得阻断预约主流程。

## 可访问性与适配

- 顶部导航使用 `nav` 和可识别的按钮名称，当前步骤暴露 `aria-current="step"`。
- 点击目标和底部按钮保留移动端可操作尺寸。
- 支持 390px、440px 以及桌面最大内容宽度；顶部六段不换行、不横向溢出。
- 尊重减少动态效果偏好；平滑滚动在该偏好下改为即时滚动。
- 固定顶部和底部栏继续处理安全区域，正文预留足够上下空间。

## 验证范围

实现按测试驱动顺序进行：

1. 为当前步骤计算建立单元测试，覆盖首屏、每个区块越过页面中部和页面底部的边界。
2. 为六个箭头测试 SVG 形状、累计点亮、点击跳转和 `aria-current`。
3. 为正式数据映射测试缺字段场景，确保不回退 mock。
4. 保留并更新预约读取、时段选择和提交测试。
5. 运行相关测试、类型检查、lint 和生产构建。
6. 在标准正式运行端口确认前后端监听进程、工作目录、分支和代理来源。
7. 登录后以 390px、440px 浏览器尺寸检查首屏、时间区、地址区、技师区、备注／页面底部；保存截图并检查控制台、请求失败和横向溢出。

## 非目标

- 不修改预约数据库模型、migration、订单状态机或结算逻辑。
- 不修改商家端、技师端预约详情页。
- 不重新设计线上确定版，也不为了代码复用简化其视觉层级。
- 不进行远端推送、部署或生产数据库操作。
