# NeeDo Web / iOS / Android 共存开发执行文档

> 执行方式：遵守仓库 AGENTS.md，逐个微步骤实施。每步完成测试与回归后再进入下一步；本文不代表相关能力已实现。

**目标：** 保留现有网页、业务和设计，交付共享业务核心的 Android 与 iOS App。

**确定架构：** React / TypeScript / Vite 共享页面、主题和业务；Capacitor 内置移动端 Web 资源，按需接入原生能力；三端共用现有正式 API、数据库、订单、钱包、排班和通知系统。

**交付顺序：** 先打通 Android 调试 APK，同时完成 iOS 初始构建。玻璃、登录、键盘从第一轮就做双端真机验收；最终交付 Web 产物、Android AAB 与安装测试包、iOS 签名构建及发布资料。

## 1. 执行边界

仓库级执行、安全、验证和授权边界以 `AGENTS.md` 为准；本文只定义 M01–M11 的移动端增量范围、顺序、验收与回退。

## 2. 开发执行顺序

每个 M 为一个工作包。包内涉及多个独立能力时，逐项实现、测试、提交；不得打包成一次大改。

### M01 — 移动构建入口

**范围：** vite.config.ts、package.json、必要的 src/App.tsx 路由导入边界；拟新增 src/main.mobile.tsx 与移动 HTML 入口；复用现有产物审计。

- [ ] 核实 main、工具链、锁文件和现有测试，在隔离目录按锁文件安装；固定首页、登录、IM、排班、订单页的视觉与加载基线。
- [ ] 复用 App，增加移动构建目标和独立输出目录，生成可被原生壳加载的 index.html。
- [ ] 增加 build:mobile 与 verify:mobile-build 命令；后者覆盖类型检查、formal 移动构建和递归产物审计，保留现有 Web 验证命令。
- [ ] 增加测试：Web 入口不缺失、移动入口资源可解析、目标业务路由可达、非运行资源与敏感文件被拦截。
- [ ] 按路由逐批延迟加载，测量首屏请求、解析耗时与体积；不在本步重构翻译系统或删除引用不明的资产。

**通过：** Web 全入口可用；移动产物可独立预览，核心路由与资源无错误；两种产物均通过审计。
**回退：** 撤销移动入口与必要导入调整，原 Web 构建保持可用。

### M02 — 双平台壳与正式 API

**范围：** 拟新增 capacitor.config.ts、android/、ios/；src/api/portalApiBaseUrl.ts 及现有媒体地址、环境校验模块与测试。

- [ ] 锁定兼容的 Capacitor、平台与插件版本；记录 Node、Xcode、Android SDK 和构建工具版本。
- [ ] 使用负责人批准且校验通过的 `appId`，设置 `appName: NeeDo`、`webDir: dist-mobile`；正式配置不得包含 `server.url`、明文请求或宽泛导航，API 必须是经校验的绝对 HTTPS 地址，正式签名包关闭 WebView 调试与敏感日志。
- [ ] 补测试：缺少必要配置失败、正式 API 非 HTTPS 被拒绝、来源精确匹配、本地 origin 下媒体 URL 正确。
- [ ] 打通正式测试环境的登录入口、首页、媒体及各门户 API；不通过放开全部 CORS/导航解决请求错误。
- [ ] Android 安装调试 APK；iOS 完成构建，取得授权签名后安装真机。断网冷启动显示离线/重试状态，不持续白屏。

**通过：** 双端可启动并访问真实业务；壳与数据加载分别计时；Web 链路不变。只有模拟器结果时，真机项保持未通过。
**回退：** 撤销壳与平台地址边界变更，服务端业务契约不变。

### M03 — 玻璃效果与性能

**范围：** src/styles.css、src/lib/clientPerformance.ts 及测试；现有 MobileShell.tsx、FloatingHomeHeader.tsx 对应组件。首次原生增强只验证底部导航一个部件。

- [ ] 固定深浅主题、动态背景、滚动及弹窗叠加的双端真机基线；补齐跨平台无障碍与降级策略测试。
- [ ] 在现有 token 上完成标准玻璃与无滤镜基础样式，按第 3 节检查清晰度、裁切、对比度和性能。
- [ ] 增强默认关闭。iOS 验证受支持的局部原生材质；Android 先保证共享 CSS 效果，原生增强通过背景采样与性能验证后才能启用。
- [ ] 验证坐标同步、遮挡、触摸、返回动画和读屏；一次只替换一个可独立关闭的部件。

**通过：** 双端标准档可接受；增强无内容模糊、错位、重复交互或明显性能倒退。不通过则保留标准档，不扩大范围。
**回退：** 关闭该部件增强，恢复共享玻璃；基础档始终可用。

### M04 — 安全会话与登录恢复

**范围：** src/auth/authEnvelope.ts、现有认证、存储与 Google 登录模块及测试；后端认证仅做必要兼容调整。

- [ ] 先补并发刷新、退出后晚到响应、换身份、进程重启、凭据迁移与存储失败测试。
- [ ] 在现有会话入口接入经过安全评估的 Keychain / Keystore 实现；访问凭据沿用短期策略，刷新凭据不得落入普通 Preferences 或明文存储。
- [ ] 保留刷新锁、版本比较、退出失效和门户隔离；缺少浏览器锁 API 时，在同一会话模块补等价保护。
- [ ] 使用提供方支持的原生登录链路，验证 state、nonce、适用的 PKCE、回跳与后端 audience；覆盖取消、失败和绑定。
- [ ] 回归 Web 多标签页、旧凭据格式、退出与换账号；核查 CSP、导航和原生桥权限，日志不得含凭据。

**通过：** 不串号、不重复刷新失控、不复活已退出会话、不在存储失败后降低安全性。
**回退：** 兼容上一安全格式或要求重新登录，不恢复明文持久化。

### M05 — 键盘、返回、滚动与恢复

**范围：** 现有 MobileShell、src/lib/useVisualViewportFrame.ts、useIosScrollContainer.ts、persistentResourceCache.ts 及相关测试。

按以下顺序分别实现、验证和提交：

- [ ] 键盘/安全区：原生与 Web 各有明确责任方，同一 inset 只应用一次；中日文输入及旋转后输入栏不遮挡、不跳动。
- [ ] 返回：先处理适用的键盘/弹层，再处理页面，根页面遵循平台行为；一次手势不得触发两次导航。
- [ ] 滚动：系统与自定义回弹只有一个责任方；验证 IM、日历横向滑动、地图与嵌套滚动。
- [ ] 生命周期：前台恢复、网络切换、进程回收及换账号后，缓存、请求和实时订阅正确恢复；晚到请求不能覆盖新账号状态。
- [ ] 无障碍：按第 4 节验证字体、读屏、焦点、横屏与触摸目标，不靠禁止缩放或机型偏移修补。

**通过：** 双端真机输入、返回与恢复正常；无重复订阅、缓存串号；Web/PWA 无对应回归。
**回退：** 每项平台适配独立撤销，保留浏览器路径；不恢复已确认的安全缺陷。

### M06 — 媒体、权限、定位与深链

**范围：** 现有上传、图片、录音、定位、分享模块；必要原生插件与权限声明，不另建上传服务。

- [ ] 每种能力单独接入；按需申请权限，覆盖拒绝、取消、部分照片授权、设置中撤销及返回 App。
- [ ] 沿用正式上传校验与持久化；验证大小/类型、HEIC 处理、方向、超时、后台中断及预览资源释放。
- [ ] 深链先校验域名、路径和参数，再恢复身份与路由；对象仍由服务端鉴权。覆盖冷启动、过期登录及对象删除。
- [ ] 不受信外部页面不得进入可调用受信原生桥的容器。

**通过：** 拒绝权限有可操作反馈且不影响无关业务；无越权、重复上传或无限等待。
**回退：** 关闭单一原生能力，保留可用的共享业务流程与明确提示。

### M07 — 推送与实时恢复

**范围：** 现有通知、SSE、设备绑定；backend/src/services/realtime-event.gateway.ts、redis-realtime-event.bus.ts 及必要推送集成。

- [ ] 保留前台 SSE，接入后台 APNs / FCM 提醒和正式设备注册、轮换、解绑；不另造实时业务协议。
- [ ] 先测漏事件补拉、重复通知、前后台切换、退出解绑、多设备及通知打开无权限对象。
- [ ] 重连有限退避并带抖动；每个身份只保留必要连接。断线从持久化状态补拉，不依赖 Redis Pub/Sub 保存历史。
- [ ] 复用可靠投递机制；持久性缺口独立补齐，不以内存数组充当可靠队列。
- [ ] 真机验证锁屏、系统回收、通知点击及开发/生产渠道；未取得权限的渠道不得宣称通过。

**通过：** 推送只触发提醒和查询，最终状态来自 API；重复通知不重复执行业务，恢复后状态一致。
**回退：** 停用推送渠道，前台查询与正式业务继续可用。

### M08 — 商店必需功能与资料

**范围：** 现有设置、账号生命周期、UGC、隐私与支付相关模块；每个缺口独立实施。

- [ ] 按目标地区与提交时官方要求核对登录、支付分类、隐私、SDK 权限及数据使用；产品/法律决策由负责人确认。
- [ ] 账号删除、举报、屏蔽与审核处置走真实端到端流程；确认未完成订单、依法保留记录和删除/匿名化规则，不自行删除账本。
- [ ] 权限用途与行为一致；设备标识遵循批准的数据策略，不用指纹绕过隐私限制。
- [ ] 准备审核账户、访问说明、隐私入口和准确截图；不临时加入假数据或隐藏故障。

**通过：** 阻断功能有测试证据，资料与行为一致；政策未核实或必要决策未批准则不得提交。
**回退：** 暂停提交；已有数据按批准的生命周期规则处理，不做破坏性撤销。

### M09 — 服务端稳定性与多实例正确性

**范围：** backend/src/middlewares/security.middleware.ts、现有 worker/实时模块、deploy/prod/、deploy/staging/、环境校验与部署契约测试。

各项先建立失败测试或故障复现，再实施：

- [ ] API/媒体：对齐路由、受信来源、HTTPS 和媒体持久化；公开静态资源版本化缓存，身份与私有媒体不得进入共享公开缓存。
- [ ] 限流：共享原子计数；验证代理信任边界、客户端识别及 Redis 故障行为，不得故障时绕过认证保护。
- [ ] Worker：验证任务归属、租约、重试与幂等；扩容不得重复结算、扣款或重复执行不可重复动作。
- [ ] Redis：认证关键状态与可淘汰缓存隔离；逻辑 DB 不视为内存隔离。不淘汰策略仍须处理容量耗尽与写失败。
- [ ] 数据库：连接预算覆盖全部 API、worker 与运维余量；核查分页、索引、热点查询与锁等待，禁止无限增大连接池。
- [ ] 运维：落实存活/就绪检查、优雅停止、指标、告警、备份与恢复演练；重启不丢媒体，任务可恢复，部署保持业务一致性。

**通过：** 隔离环境双实例、依赖故障与恢复验证通过；账本、订单及安全约束不被削弱。
**回退：** 保留上一镜像和兼容配置，按验证结果调整实例规模，不破坏性降级数据库。

- [ ] 明确目标活跃用户、请求速率、长连接数、交易速率与环境资源；隔离账户和数据，从小负载开始核对业务结果。

- [ ] 阶梯升压、稳定负载、峰值、持续运行与恢复测试；观测 P95/P99、错误率、连接池等待、锁、事件循环、队列与资源余量。
- [ ] 演练实例重启、Redis/数据库异常、断网和集中重连；核对重复扣款、结算、超卖、漏事件等不变量。

**通过：** 第 5 节指标与业务不变量通过；容量结论只覆盖实测场景和资源，未测场景不外推。
**回退：** 停止测试并恢复隔离环境；未经授权不得压测生产或触发真实支付。

**范围：** 现有 CI、原生构建流程与发布记录；证书和密钥由受控签名环境提供，不进入仓库。

- [ ] 验证首次安装、覆盖升级、旧 App + 新后端、旧缓存、过期会话及进程恢复；保存上一可用包与 Web 资源版本。

## 3. 玻璃效果实施标准

| 档位 | 实现与启用条件 |
|---|---|
| 基础 | 无滤镜，以主题底色、描边、高光和层级保持可读；减少透明度或能力不足时使用 |
| 标准 | 复用 CSS backdrop-filter、透明底色与高光，作为双端默认；限制滤镜面积、图层与动画 |
| 增强 | 仅对通过相关真机验收的局部部件启用；依据系统能力、无障碍设置与实测性能选择，始终可关闭 |

**原生与渲染约束：**

- iOS：支持系统上验证 UIGlassEffect；旧系统采用受支持的模糊材质或基础档。必须证明目标背景正确合成，不能假设可直接作用于任意 WKWebView DOM。
- Android：CSS 标准档先通过；原生增强须验证目标背景采样。禁止对整个 WebView 加 RenderEffect 模糊，窗口模糊不能直接当成 DOM 容器模糊。
- 文字、图标和命中区域清晰独立；覆盖层不制造双份导航、读屏重复、触摸拦截。
- SVG 折射和自定义 shader 未通过目标真机验证前不得成为默认依赖；禁止每帧截屏、DOM 转图或服务器计算玻璃。
- 减少动态与减少透明度分别处理；后台、卸载后停止不必要动画与监听。

**验收动作：**

- 对比深浅主题、明暗图片/视频背景、滚动与弹窗叠加；检查裁切、闪烁、重影、错位、清晰度及对比度。
- 同机同场景比较标准/增强档，连续滚动至少 10 分钟，记录慢帧、内存、发热与输入响应。
- 横竖屏、安全区、键盘及返回动画中坐标一致；关闭增强无布局跳变。
- 截图不能证明动态折射或流畅性；保留必要录屏与性能轨迹。

## 4. 手机体验与适配标准

| 项目 | 必测行为 |
|---|---|
| 启动 | 离线、弱网、API 故障有明确状态与重试，不持续白屏 |
| 键盘 | 中日文输入法、候选栏、发送、旋转与前后台恢复；输入不遮挡，无双重位移 |
| 安全区 | 系统 inset 与 env(safe-area-inset-*) 责任清晰；覆盖刘海、手势条、三键导航 |
| 返回/滚动 | Android 系统返回及适用预测返回、iOS 边缘返回；弹窗、地图、日历和聊天不抢事件或双退 |
| 无障碍 | 大字体、读屏顺序、焦点、缩放；主要触摸目标按 iOS 44pt / Android 48dp 对应尺度检查 |
| 网络 | 取消、超时、429/503、断网重连；有限重试加抖动，不能只依赖在线状态标记 |
| 交易 | 超时先查结果，重试沿用同一逻辑请求的幂等键；不显示假成功，不离线自动重放扣款 |
| 恢复 | 进程回收、过期登录、换账号、权限撤销与升级后恢复；无串缓存与重复连接 |

**最低验收矩阵：**

- iOS：拟支持最低系统的小屏旧机、支持原生增强的系统与设备、高刷新率机；深浅主题及减少动态/透明度设置。
- Android：低内存、中端、旗舰；覆盖 Pixel 或 Samsung，以及 OPPO / ColorOS，记录系统与 WebView 版本。
- 布局：窄屏、横屏、大字体、全面屏手势、三键导航；宣称支持平板/折叠屏前追加对应验收。
- Web：现有支持浏览器和 PWA；用户、技师、商户、运营入口回归。
- 网络/安装：Wi-Fi、受限网络、离线、网络切换；首次、重复、覆盖升级及清数据启动。

最低支持版本根据项目依赖与实机结果确定，不能直接采用框架可启动的最低版本。

## 5. 统一验收门槛

以下为执行目标，不是已达标声明。M01 固定参考设备、网络、样本与测量方式；调整目标须说明依据并获得确认，不能为掩盖失败临时放宽。

| 维度 | 门槛 |
|---|---|
| 业务 | 登录、首页、预约/订单、IM、通知和换账号等核心流程全部通过；无阻断错误、越权、重复扣款/结算 |
| 构建 | Web/Mobile 可复现，入口资源完整；产物无非运行源文件、备份和敏感凭据 |
| 反馈 | 参考设备主要点击反馈 ≤100ms；业务完成时间另计，不用提前成功反馈达标 |
| 启动 | 至少 20 次冷启动，参考设备壳可交互 P95 ≤2.5s；业务数据就绪单独计时 |
| 滚动 | 60Hz 参考机按 16.7ms 帧预算记录慢帧与连续卡顿；增强相对标准无明显倒退 |
| 稳定性 | 连续使用 30 分钟，反复开关聊天/媒体/弹窗 50 次；无崩溃、ANR、持续内存增长或输入延迟恶化 |
| API | 读接口初始目标 P95 <800ms、P99 <1500ms、错误率 <1%；写入、上传、实时分别定指标，业务不变量零违规 |
| 恢复 | 断网、后台、进程回收和升级后恢复；旧 App 兼容新后端，不重复提交未知结果交易 |
