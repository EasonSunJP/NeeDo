# 运营服务类型与搜索分析实施计划

> 依据已批准设计 `2026-09-01-operations-comprehensive-data-overview-order-settlement-and-growth-design.md` 第 11 节执行。每个任务单独提交，保持可运行、可测试、可回滚。

## 目标

将现有正式服务分类与搜索标签接入运营后台，并记录真实搜索行为，提供按城市、时间和服务类型筛选的关键词 TOP10，以及最多 5 个关键词的原始次数与 0–100 归一化趋势对比。所有修改使用正式 API、MySQL、RBAC 和审计，不增加 mock。

## Task 1：数据模型、权限与迁移

- 为服务分类和业务关键词增加乐观锁版本号。
- 新增搜索关键词别名与真实搜索事件模型，保留软删除、索引和关联。
- 新增服务类型读写、搜索分析读取权限，并按现有后台角色最小授权。
- 先写 schema/permission 契约测试，再生成单一可回滚 migration。

## Task 2：真实搜索事件采集

- 搜索成功后记录实际提交的关键词、标准化关键词、城市、服务类型、结果数与匿名会话哈希。
- 不记录 IP、User-Agent、access token 或原始会话标识。
- 补 repository/service 测试，验证无关键词不记录、失败搜索不记录、别名可解析。

## Task 3：运营服务类型正式 API

- 提供分页分类、关键词和别名查询，以及带 `reason`、`expectedVersion` 的新增/修改接口。
- Controller 只处理请求响应；Service 负责事务、版本冲突与审计；Repository 负责 Prisma。
- 补 Zod、OpenAPI、permission 和集成测试。

## Task 4：关键词 TOP10 与趋势 API

- 提供城市、时间、服务类型筛选的 TOP10。
- 提供最多 5 个关键词对比，返回原始搜索次数与明确标记的 0–100 归一化指数。
- 使用东京自然日切片；排序同值时以首次出现时间、关键词 ID 稳定排序。
- 补跨日、零数据、筛选和归一化测试。

## Task 5：运营后台页面

- 新增“运营服务类型设置”入口与权限守卫。
- 页面包含服务分类/搜索标签/同义词管理、统一城市时间筛选、关键词 TOP10 和趋势对比。
- 趋势图图例可点击显示/隐藏系列；不可用能力显示 TEST，不伪造数据。
- 补 API adapter 运行时校验、路由、i18n 与组件测试。

## Task 6：正式验收与本地主干合并

- 运行 migration status、定向后端测试、后端 lint/build、定向前端测试与前端 build。
- 在隔离端口启动正式 backend/frontend，验证 health/ready/proxy、后台路由、网络请求、控制台与页面交互。
- 将功能分支合并到本地 `main`，复跑合并后关键验证；不 push、不部署。
