## 版本时间线

- 导航位于运营栏最底部、官方通知下方，复用 User LOG 时间线组件。
- 左侧按东京时区显示发布时间，中间时间线，右侧版本与变更内容；正文超过十行
  沿用共享展开/收起规则。页面只读，没有创建、删除、评论入口。
- 正式 GET `/api/v1/backoffice/releases`，分页、Zod、平台身份、
  `backoffice:dashboard:read` 权限及服务端部署环境隔离；没有公开写接口。
- 发布快照来自不可变构建中的 Git 提交清单。部署三个 API ready 并切换当前版本后，
  以当时 UTC 生成发布时间，由容器内部 CLI 事务写入版本表与 `release.published` 审计。
- 上次版本清单缺失时，如果上次部署 revision 存在于当前 Git 祖先图中，仍按该边界
  计算增量；完全没有历史部署证据才记为首次基线，不伪造历史发布时间。
- deploymentId + payload hash 保障重试幂等；不同内容复用 ID 拒绝。保留服务器发布
  receipt，写入失败时可原样重放，不能生成新时间来冒充原发布时间。
- 本地 migration `20260907010000_release_publications` 已单独应用并登记，未应用
  其他任务的 pending migration。Prisma Client 已生成。
- MySQL 验证：四次并发同一发布仅一条记录、一条审计；冲突拒绝、按发布时间排序、
  分页和环境隔离通过，测试记录已清理。真实 UI 当前无发布记录，因为本轮未部署。

## 首页轮播编辑

- 五种内容语言快捷切换置于页面顶部；已发布内容和编辑列表均用缩略图。
- 已发布缩略图提供编辑及当前语言图片替换，编辑明确点击后才建立服务器草稿，
  页面访问本身不创建草稿。图片上传和语言更新均走原正式 API、媒体权限与乐观锁。
- 编辑区显示选中缩略图，可直接替换当前语言图片，保留默认图片/语言独立图片能力。
- 首页轮播不请求历史列表，不提供历史回滚控件。旧已发布版本在替换发布（含定时
  激活）事务内软删除；历史读取只返回当前有效槽位，旧首页快照不能回滚。
  按项目软删除规则保留数据库痕迹及操作审计，不进行物理清库。
- 服务端提供 latestVersion 并在版本计数时包含退休记录，避免编号重用与编辑冲突。
  联盟公告模块原有历史流程不在此改动范围。
- 本地 MySQL 在单个最终强制回滚的事务内验证：克隆当前内容、五语言保留、发布替换、
  旧版本退出历史/预览、审计写入。没有更改当前正式轮播内容。

## 用户详情抽屉

打开/关闭抽屉改变 `detailUserId` URL 参数，旧列表以整个 searchParams 对象为依赖，
因此误触发列表重读，并在 loading 时卸载表格。现在按规范化的真实列表查询建立稳定
依赖，抽屉参数变化不触发列表请求，保留表格节点及尚未提交的搜索输入。回归测试同时证明正常翻页仍会请求。
已登录浏览器在打开与关闭 LifeDance 管理员 D 的详情前后，表格均为 21 行（含表头，20 条数据）。
全局滚动复位也排除这三类后台页面的抽屉参数；真正翻页和换页面仍会复位。独立 Router 回归已验证。
最终浏览器验证打开与关闭 Kenta Mori 详情后 scrollTop 均为 916px，未提交的搜索文字保持；随后清空测试输入。
