# 新建排班周期的历史草稿隔离

## 问题与最小修复

新建技师自主排班周期输入 2026-09-20 至 2026-12-20 后，旧草稿可能重新进入向导或覆盖输入。

- 新建默认值不再隐式复制历史周期的日期、模板、规则和技师名单。默认日期使用东京当天至一个自然月后；显式传入空技师名单仍为空，发起时继续拒绝空对象。
- 向导仅把未过期的执行/已确认周期视为当前周期；有效草稿仍可继续编辑。过期记录保留在存储中，但不参与当前向导候选与限额计算。
- 已打开的向导按周期 ID 定位，不在该周期消失后自动切换到其他历史草稿。
- 规则编辑器按周期 ID 初始化。其他共享状态刷新不再替换本次未保存的标题、日期、规则和技师选择。
- 草稿重新加载时保留持久化的技师 ID 与顺序，不再使用尚未加载的实体缓存将其替换为默认技师。

没有新增接口、表、migration 或可见文案，没有删除或迁移历史排班数据。

## 已确认的既有边界

`AutomationWizard → dispatch-center/store` 的周期创建、草稿保存和最终确认仍是浏览器 localStorage 生命周期，没有向后端发送周期创建/保存请求。正式 `/schedule/slots` API 是独立契约；本次未改变它，也未增加假 API。

后端周期持久化/发布验收：**NOT IMPLEMENTED**。本次验证不声称跨设备同步、真实后端发布或 staging 修复已上线。没有执行 push、PR、部署或 staging/production 数据操作。

## 回滚

本变更仅为前端状态读取/初始化修复，可用 `git revert` 回滚对应修复提交；无需数据库回滚，不应清除用户 localStorage 或历史排班记录。
